# Handoff Writer

## 목적

다음 세션이 **이 문서만 읽고 바로 작업을 이어가게** 만든다. 대화 로그를 요약하는 게
아니라, 이어받는 사람이 실제로 필요한 것만 남긴다.

성공 기준은 하나다. **컨텍스트가 완전히 날아간 상태에서 이 문서만 보고 다음 명령을
칠 수 있는가.** 못 치면 실패다.

## 진행 보고서와의 차이

혼동하기 쉬우므로 먼저 구분한다.

| | 진행 보고서 | 핸드오프 (이 스킬) |
|---|---|---|
| 질문 | 무슨 일을 했나 | 다음에 무엇을 어떻게 하나 |
| 시점 | 과거 | 미래 |
| 독자 | 이해관계자·본인 | 이어받는 작업자 |
| 핵심 | 결과·성과 | 재개 지점·다음 명령·함정 |

이미 진행 보고서가 있으면 링크만 걸고 내용을 복사하지 않는다.

## 작성 전 반드시 확인

1. **작업 위치와 상태** — 리포 경로, 마지막 커밋 해시, push 여부, 브랜치. 확인 없이
   쓰지 않는다(`git log --oneline -1`, `git status -sb`).
2. **진행 중이던 작업의 정확한 지점** — 깨끗하게 멈췄나, 아니면 절반 고친 파일이 있나.
   후자면 그 파일과 미완 상태를 반드시 적는다.
3. **기존 문서와의 역할 분리** — 규칙 문서(CLAUDE.md)·상태 문서(status.md)가 이미
   있으면 중복하지 않고 링크한다. 핸드오프는 세션 인계에만 집중한다.

## 문서 구조

프로젝트 성격에 따라 가감하되, 아래 6개는 뺄 수 없다.

### 1. 지금 어디까지 왔나
- 완료된 것을 한눈에. 나열이 아니라 "무엇이 돌아가는 상태인가"로 쓴다.
- **작업 중이던 것**을 반드시 명시한다. 없으면 "없다. 깨끗하게 멈췄다"라고 적는다.
  절반 고친 게 있으면 파일·함수·미완 이유를 적는다.

### 2. 다음에 할 일 (바로 시작 가능)
- 추상적 방향("개선한다")이 아니라 **구체적 변경**을 적는다. 어느 파일의 무엇을
  왜 어떻게 바꾸는지.
- 우선순위와 그 근거를 적는다. "왜 이것부터인가"가 없으면 다음 사람이 순서를 뒤집는다.
- 예상 결과를 적는다. 특히 **지표가 나빠지는 게 정상인 경우** 반드시 명시한다
  (안 그러면 다음 사람이 버그로 오해하고 되돌린다).

### 3. 반드시 지킬 것 (어기면 결과가 무효)
- 이 작업의 신뢰도를 떠받치는 규율. 어겼을 때 무엇이 무효가 되는지까지 적는다.
- 예: 봉인 홀드아웃 개봉 규칙, 정답-정책 분리, 회사 자산 경계.

### 4. 함정 (이미 시도했다 실패한 것)
- **가장 가치 있는 섹션이다.** 다음 사람이 같은 실패를 반복하는 것을 막는다.
- 시도한 접근, 실패한 결과(수치), 왜 실패했는지를 적는다.
- "그냥 하지 마라"가 아니라 근거를 적는다. 근거 없이 금지하면 다시 시도한다.

### 5. 알려진 미해결
- 해결 못 한 것을 숨기지 않는다. 상태(누가·언제 볼 것인지)와 함께.
- 해결 불가능할 수 있는 것은 "한계로 기록하는 것도 정당한 결론"이라고 명시한다.

### 6. 환경 복구
- 복붙해서 바로 돌아가는 명령. 버전 제약(예: Python 3.9라 특정 패키지 고정)을 적는다.
- 외부 의존성(경로·환경변수·인증)을 적는다. 없으면 무엇이 실패하는지도.

## 담지 않는 것

- **대화 흐름**: "처음엔 A를 했다가 사용자가 B를 요청해서…" 같은 서술. 결과만 남긴다.
- **정정 과정**: 틀렸다가 고친 이야기는 결과만. 단 그 실패가 다음 사람도 빠질 함정이면
  §4에 근거와 함께 남긴다.
- **성과 자랑**: 수치는 재개에 필요한 만큼만. 상세는 결과 리포트로 링크.
- **이미 다른 문서에 있는 것**: 규칙·설계·상태 문서가 있으면 링크. 복사 금지.

## 작성 원칙

- **명령형으로 구체적으로.** "고려한다"가 아니라 "`measure.py`의 `crit_hit` 판정을
  독립 상황 기준으로 바꾼다".
- **파일·함수·해시를 적는다.** "채점 로직"이 아니라 "`sitpipe/measure.py`의
  `score_episode`".
- **수치는 분자/분모를 병기한다.** "82.5%"가 아니라 "33/40 (82.5%)".
- **화살표로 인과·순서를 압축하지 않는다.** 서술로 푼다.
- **내부 코드·조항 번호를 단독 표기하지 않는다.** 의미를 병기한다.

## 저장 위치

- 기본: 작업 리포의 `docs/HANDOFF.md`. 프로젝트 관례가 있으면 따른다.
- 개인 작업물이 회사 리포에 들어가면 안 되는 경우 등 **경계 규칙이 있으면 위치를 먼저
  확인**한다.
- 파일을 쓴 뒤 커밋 여부를 사용자에게 확인한다(자동 커밋 규칙이 있으면 따른다).

## 마지막 자기검증

문서를 쓴 뒤 반드시 스스로 확인한다.

1. 이 문서만 읽고 **다음 명령을 칠 수 있는가?** 못 치면 §2·§6이 부실하다.
2. 다음 사람이 **이미 실패한 접근을 다시 시도할 여지**가 있는가? 있으면 §4를 보강한다.
3. **규율을 어길 여지**가 있는가? 어기면 무엇이 무효가 되는지 적었는가?
4. 다른 문서와 **중복**되는가? 중복이면 링크로 바꾼다.

검증에서 걸리면 고친 뒤 확정한다.
