# 작성자 목소리 보정 가이드

## 0. 목적

자연스러운 문장을 만든다는 이유로 모든 사람의 글을 같은 기업 문체로 바꾸지 않는다. 이 문서는 사용자가 직접 쓴 글에서 반복되는 표현 습관을 추출해, 이력서·포트폴리오·IR 문서에도 본인의 목소리가 남게 하는 기준이다.

특정 유명인이나 레퍼런스 작성자의 목소리를 모사하지 않는다.

---

# 1. 사용할 샘플

우선순위는 다음과 같다.

1. 사용자가 직접 작성한 최근 업무 메모
2. 링크드인·블로그·회고글
3. 이메일이나 메신저 중 업무 설명이 잘 된 문장
4. 수정 전 이력서에서 자연스럽게 읽히는 부분
5. 발표 원고 또는 면접 답변

다음 자료는 목소리 샘플로 쓰지 않는다.

- AI가 대부분 작성한 문서
- 여러 사람이 공동 편집한 문서
- 법률·공공 양식처럼 표현이 제한된 문서
- 특정 회사의 문구를 옮긴 자료
- 감정이 격해 평소 문체와 다른 메시지

샘플은 3개 이상, 전체 500~2,000자를 권장한다.

---

# 2. 목소리 프로필 추출

## 2.1 격식 수준

| 수준 | 특징 | 적용 예 |
|---|---|---|
| 공식적 | 완결문, 직무 용어, 감정 표현 적음 | 이력서·IR |
| 담백한 실무형 | 쉬운 말, 구체적 사례, 짧은 단정 | 경력기술서·포트폴리오 |
| 설명형 | 배경과 이유를 충분히 풂 | 회고·케이스 스터디 |
| 대화형 | 질문·짧은 반응·해요체 | 블로그·발표 원고 |

한 문서 안에서 기본 격식은 유지한다. 포트폴리오 제목이 담백한 실무형이라면 본문만 갑자기 광고 문체가 되지 않게 한다.

## 2.2 문장 길이

샘플에서 다음을 확인한다.

- 짧은 단문을 자주 쓰는가
- 한 문장에 배경을 충분히 넣는가
- 괄호를 자주 쓰는가
- 설명 뒤에 짧은 결론을 붙이는가

기존 리듬을 살리되, 한 문장이 지나치게 길어지는 습관은 문서 목적에 맞게 줄인다.

## 2.3 종결 방식

- `~했습니다`: 공식적이고 책임이 분명함
- `~했어요`: 발표·블로그에 적합
- `~한다`: 보고서·정책 문서에 적합
- 명사형: 제목·표·성과 카드에 적합

사용자가 특정 어미를 자주 쓴다고 모든 문장을 같은 어미로 맞추지 않는다. 문서 유형이 우선이다.

## 2.4 단정의 강도

사용자의 원문에서 다음을 구분한다.

- 강한 단정: `문제는 A였습니다.`
- 제한적 단정: `A가 주요 원인이라고 판단했습니다.`
- 관찰: `A가 반복해서 나타났습니다.`
- 제안: `A를 우선 검토할 수 있습니다.`

근거 수준보다 단정을 세게 만들지 않는다.

## 2.5 어휘 성향

확인할 항목:

- 한자어와 쉬운 말의 비율
- 영어 직무 용어 사용량
- `문제`, `병목`, `기준`, `흐름`, `범위` 등 자주 쓰는 핵심어
- 감정 형용사 사용량
- 숫자와 사례 제시 방식

사용자가 자연스럽게 쓰는 직무어는 남긴다. 단순 동의어 치환으로 낯선 단어를 넣지 않는다.

## 2.6 자기표현 수준

- 성과를 직접 말하는가
- 팀과 본인 역할을 조심스럽게 나누는가
- `저는`을 자주 쓰는가
- 실수·한계를 공개하는가

이력서에서는 `저는`을 줄이되, 책임 수준의 신중함은 유지한다.

## 2.7 감정 온도

| 온도 | 특징 | 적합 문서 |
|---|---|---|
| 낮음 | 객관적, 짧은 평가 | 이력서, IR |
| 중간 | 문제 의식과 학습을 표현 | 포트폴리오, 경력기술서 |
| 높음 | 개인 동기와 감정이 중심 | 회고, 브랜드 스토리 |

지원 문서에서는 감정 온도를 원문보다 한 단계 이상 높이지 않는다.

# 3. 6줄 목소리 프로필

편집 전에 내부적으로 아래를 채운다.

```text
격식: 공식적 / 담백한 실무형 / 설명형 / 대화형
문장 리듬: 짧은 단문 중심 / 혼합 / 긴 설명 중심
단정 강도: 강함 / 중간 / 신중함
전문용어: 적음 / 보통 / 많음
영어 혼용: 적음 / 업계 용어만 / 많음
보존할 특징: {사용자다운 표현 2~3개}
```

예시:

```text
격식: 담백한 실무형
문장 리듬: 핵심 단문 뒤에 설명문을 붙임
단정 강도: 근거가 있을 때만 강하게 단정
전문용어: 보통
영어 혼용: PRD·LLM·QA처럼 관행 용어만
보존할 특징: 실제 사용자 장면부터 설명, 한계를 숨기지 않음
```

# 4. 목소리를 살리는 편집

## 4.1 사용자가 자주 쓰는 쉬운 말을 남긴다

```text
사용자 원문
실무자는 여러 시스템을 오가며 숫자를 다시 확인해야 했습니다.

과잉 편집
분산 데이터 소스 간 탐색 비용이 발생했습니다.

권장 편집
실무자는 여러 시스템을 오가며 같은 숫자를 다시 확인해야 했습니다.
```

원문의 구체적인 업무 장면을 전문 용어로 덮지 않는다.

## 4.2 자연스러운 불완전성을 보존한다

사람 글은 모든 문단이 같은 길이와 구조를 갖지 않는다. 핵심 프로젝트는 길게 설명하고, 보조 경험은 짧게 써도 된다.

모든 프로젝트를 `문제–해결–성과` 세 문장으로 강제로 맞추지 않는다.

## 4.3 습관적 약점을 개성으로 착각하지 않는다

다음은 그대로 보존하지 않는다.

- 한 문장이 지나치게 김
- 조사와 접속사 반복
- 모호한 대명사
- 지나친 겸손으로 책임이 사라짐
- 같은 단어의 의미 없는 반복
- 업계 외부 독자가 모르는 내부 용어

## 4.4 강조 방식은 유지하되 정리한다

사용자가 대비를 자주 쓰면 문서에서도 활용할 수 있다.

```text
기존에는 이벤트를 보여줬습니다. 바꾼 뒤에는 담당자가 대응할 상황을 보여줬습니다.
```

다만 모든 페이지에서 같은 대비 문형을 반복하지 않는다.

# 5. 브랜드 목소리 보정

브랜드 문서는 개인 목소리보다 기존 브랜드 자산을 우선한다.

## 확인 자료

- 공식 홈페이지 첫 화면
- 제품 내 문구
- 보도자료와 채용 페이지
- 대표 인터뷰
- 브랜드 가이드
- 고객에게 자주 쓰는 이메일

## 브랜드 프로필

```text
핵심 약속:
주요 독자:
격식:
자주 쓰는 단어:
피하는 단어:
문장 길이:
감정 온도:
근거 제시 방식:
```

브랜드마다 다른 말을 같은 `혁신적이고 직관적인 솔루션` 문체로 바꾸지 않는다.

---

# 6. 문서별 목소리 조정

## 이력서

- 개인 목소리 30%, 채용 문서 관습 70%
- 쉬운 어휘와 판단 방식을 남김
- 감정·유머는 거의 사용하지 않음

## 경력기술서

- 개인 목소리 50%, 문서 관습 50%
- 문제를 본 관점과 의사결정 이유를 드러냄
- 지나치게 공문처럼 만들지 않음

## 포트폴리오

- 개인 목소리 60%, 정보 구조 40%
- 제목과 회고에서 관점이 보이게 함
- 기능 설명은 정확성을 우선

## IR·회사소개서

- 개인 목소리 10~20%, 회사 목소리 80~90%
- 창업자의 동기는 일부 남기되 주장과 수치는 회사 기준으로 통일

## 제품·브랜드 소개

- 기존 브랜드 목소리를 최우선
- 작성자의 개인 말투가 브랜드를 덮지 않게 함

# 7. 목소리 일관성 검사

- [ ] 첫 문단과 프로젝트 본문의 격식 수준이 같은가?
- [ ] 갑자기 광고 문구처럼 과장된 문장이 없는가?
- [ ] 일부 섹션만 지나치게 공문처럼 딱딱하지 않은가?
- [ ] 영어 혼용 원칙이 문서 전체에서 같은가?
- [ ] 같은 개념을 사용자가 평소 쓰지 않는 낯선 단어로 바꾸지 않았는가?
- [ ] 자연스러운 부분까지 불필요하게 다시 쓰지 않았는가?
- [ ] 작성자의 판단과 한계 인식이 남아 있는가?
- [ ] 레퍼런스 작성자의 문장 습관을 복제하지 않았는가?

# 8. 샘플이 없을 때의 기본 목소리

```text
구체적인 업무 장면을 먼저 쓴다.
핵심 판단은 짧게 단정한다.
근거와 한계는 다음 문장에서 설명한다.
전문용어는 정확하게 쓰되, 기술명으로 문장을 시작하지 않는다.
자기평가 대신 역할과 결과를 쓴다.
감탄사와 과장 수식어를 쓰지 않는다.
```

기본 목소리는 안전한 출발점일 뿐이다. 사용자의 자연스러운 문장 샘플이 생기면 다음 편집부터 프로필을 갱신한다.
