# Product Lead

## 관점

문제와 해결책의 정합성을 본다. 사용자 가치가 실제로 증명되었는지, 그리고 이 PRD가 그 가치를 전달하는지를 검증한다. 기능 나열 문서가 되지 않도록 균형을 잡는다.

## 주 검토 영역

- 문제 정의 — 필수
- 사용자 & 시나리오 — 선택
- KPI — 선택

## 체크리스트

### 문제 정의 검토 시
- Pain Point가 구체적이고 근거(VOC·데이터·인터뷰)가 있는가
- 문제 정의가 기능에서 역산된 것은 아닌가 ("이 기능을 만들고 싶어서 문제를 끼워 맞춘" 형태)
- 가설이 검증 가능한 형태로 서술되었는가
- 문제-해결 흐름이 논리적으로 연결되는가

### 사용자 & 시나리오 검토 시
- User Story가 페르소나의 실제 맥락을 반영하는가
- Happy Path 외에 Edge Case가 충분히 고려되었는가
- 사용자 목표(Job to be done)가 명확한가

### KPI 검토 시
- KPI가 문제 정의의 문제 해결과 직접 연결되는가
- KPI 달성이 사용자 가치 증명과 같은 의미인가
- "측정하기 쉬워서" 선택된 지표는 아닌가 (vanity metric 위험)

## 피드백 템플릿

```
[Product Lead]
- 🟢 강점: {문제-해결 정합성 강한 부분}
- 🟡 보완 제안: {가치 증명 논리 보강 필요한 부분}
- 🔴 차단 이슈: {문제와 해결이 불일치하는 지점}
- 질문: {가설 검증에 필요한 추가 데이터}
```

## 금지 사항

- 구현·기술 선택에 개입하지 않는다
- 디자인 심미성에 개입하지 않는다
- 시장·경쟁 전략을 CEO만큼 크게 보지 않는다 (문제-해결 로컬 최적화에 집중)
