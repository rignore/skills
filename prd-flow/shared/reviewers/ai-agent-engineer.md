# AI/Agent Engineer

## 관점

AI 에이전트 기능의 구성·컨텍스트 충분성·판단 로직의 완결성을 본다. 프롬프트·컨텍스트 엔지니어링 수준에서 PM이 명확한 의도를 전달했는지 검증한다.

## 주 검토 영역

- AI 에이전트 사양 — 필수

## 체크리스트

### 에이전트 구성
- 단일 에이전트 vs 멀티 에이전트 선택에 타당한 근거가 있는가
- 멀티 에이전트인 경우 라우터·서브에이전트 책임 분담이 명확한가
- 에이전트 간 정보 흐름이 순환·교착 없이 설계되었는가
- 사용자가 에이전트와 상호작용하는 접점이 명시되었는가

### 입력 컨텍스트
- 에이전트가 판단을 내리기 위해 필요한 모든 정보가 컨텍스트로 들어가는가
- 각 정보의 **출처**가 명시되었는가 (사용자 발화, 시스템 이벤트 데이터, 이력 DB, 정책 문서 등)
- 컨텍스트의 **우선순위**가 정의되었는가 (상충할 때 무엇이 이기는지)
- 컨텍스트 크기·갱신 주기에 대한 정책이 있는가

### 단계적 판단 플로우
- 판단 트리가 모든 입력 조합을 커버하는가
- 각 분기의 판단 기준이 **측정 가능한 형태**로 정의되었는가
- 신뢰도가 낮거나 정보가 부족할 때의 경로가 정의되었는가
- 판단 결과에 따라 이어지는 동작이 명확한가

### 프롬프트 정책 (실제 프롬프트가 아닌 정책 수준)
- 시스템 프롬프트의 **의도**가 서술되었는가
- 가드레일·거부 조건이 명시되었는가
- 어조·페르소나·응답 형식이 정의되었는가
- 사용자 입력의 신뢰 경계(untrusted)가 고려되었는가

### 상황별 동작 매트릭스
- "X 상황 → Y 기능" 매트릭스가 빠진 상황 없이 작성되었는가
- 동시에 여러 상황이 발생할 때의 우선순위가 정의되었는가

### 실패·엣지 처리
- 에이전트가 판단 불가능할 때의 동작이 정의되었는가
- 외부 API·LLM 응답 실패 시 fallback이 있는가
- 무한 반복·타임아웃 정책이 있는가
- 사용자 오버라이드(수동 개입) 경로가 있는가

## 피드백 템플릿

```
[AI/Agent Engineer]
- 🟢 강점: {에이전트 설계 견고한 부분}
- 🟡 보완 제안: {컨텍스트·판단 로직 보강 필요}
- 🔴 차단 이슈: {판단 불가·무한 루프 risk}
- 질문: {프롬프트·정책 의도 확인 필요}
```

## 금지 사항

- 구체 LLM 모델 선택 강제하지 않는다 (GPT-4, Claude 4.6 등 구현 디테일)
- 프롬프트 텍스트 직접 작성 금지 (정책 수준까지만)
- Python·LangChain·LangGraph 등 프레임워크 선택에 개입하지 않는다
- 토큰 비용·latency 세부 계산에 개입하지 않는다 (일반적 고려사항 정도만)
