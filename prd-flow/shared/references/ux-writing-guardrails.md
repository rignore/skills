# UI 텍스트 작성 가드레일

PRD 안에 포함되는 모든 UI 텍스트(알림, 버튼 레이블, 에러 메시지, 툴팁, 상태 표시 등)에 적용되는 작성 규칙. PRD 본문 작성과는 별개로 적용된다.

이 스킬 세트의 공통 UX 라이팅 표준.

## 코어 밸류

UI 텍스트는 항상 다음 4가지 가치를 충족해야 한다.

- **명확한**: 사용자가 한 번에 이해할 수 있는가
- **전문적인**: 신뢰를 주는 어조인가
- **책임감 있는**: 시스템이 책임지는 자세를 보이는가
- **일관적인**: 서비스 전반에서 같은 단어·어조를 쓰는가

## 1. 기본 3요소 (A·B·C)

알림이나 중요한 메시지는 다음 세 정보를 포함하되, 긴급도에 따라 조정한다.

| 요소 | 정의 | 예시 |
|---|---|---|
| **A. 현재 상황 / 객관적 진단** | 시스템이 확인한 사실 (데이터, 이벤트) | "OOO님의 계정에 미승인 기기가 새롭게 접속을 시도했습니다." |
| **B. 잠재적 영향 / 책임** | 방치 시 예상되는 위험 | "본인이 아닐 경우, 개인 정보 유출 위험이 발생할 수 있습니다." |
| **C. 즉시 취해야 할 행동** | 사용자에게 요구되는 조치 | "타인 접속이 확인될 시, 지금 즉시 비밀번호를 변경하세요." |

### 조합 패턴

- **[A] + [C]**: 빠른 조치가 필요한 상황. "주문 #1024 결제 승인 실패. 즉시 결제 수단 확인과 조치 담당자 지정이 필요합니다."
- **[B] + 객관적 근거(수치/데이터)**: 위험 고지. "현재 저장 공간 사용률 98%, 초과 임박 상태가 15분간 지속되고 있습니다."
- **[A] + [B] + [C]**: 가장 완전한 형태. 전체 알림이나 토스트에 사용

## 2. 어조 분리

메시지 성격에 따라 어조를 다르게 적용한다.

| 구분 | 권장 어조 | 예시 |
|---|---|---|
| **시스템 기능 (버튼, 메뉴)** | 명사형 | 저장, 홈으로 이동, 프로젝트 이동 중 |
| **상태 / 조치 안내** | "~이 필요합니다." (책임감 부여) | 즉시 확인 및 조치가 필요합니다. |
| **사용자 조작 / 입력 안내** | "~해주세요." | 올바른 이메일 형식으로 작성해주세요. |

## 3. 사용자 중심 행동 유도

정보 제공보다 행동 유도에 초점.

### 체크리스트

- [ ] 버튼 레이블이 단순 "보기"가 아닌 구체적 행동(조치, 재접수, 시작 등)을 담고 있는가?
- [ ] 사용자의 목적이 문장의 시작에 위치하는가? (예: "OOO 하려면, [버튼]을 누르세요.")
- [ ] 시스템 상태 설명이 아닌, 사용자가 즉시 취해야 할 행동이 명확한가?
- [ ] 할 수 없는 것 대신 할 수 있는 것을 강조했는가?

### Do / Don't 예시

❌ **Don't**: "모바일 앱 설치 후 실시간 알림을 받아보세요."
✅ **Do**: "실시간 알림을 받으려면, 모바일 앱을 설치하세요."

❌ **Don't**: "로그아웃을 진행 하시겠습니까?"
✅ **Do**: "로그아웃을 진행 하시겠습니까?" (그대로 두되, 컨펌 버튼은 "로그아웃"으로 명확히)

## 4. 직관성 및 간결성

### 체크리스트

- [ ] 불필요한 설명이나 의미 없는 단어를 모두 제거했는가?
- [ ] 전문 용어/약어 대신 실무자가 이해하는 대중적 용어로 대체했는가?
- [ ] 불가피하게 전문 용어를 사용했다면 툴팁/인포팁으로 의미를 즉시 제공했는가?
- [ ] 해당 용어가 서비스 전반에서 통일된 단어인가?

### Do / Don't 예시

❌ **Don't** (반품 검수 결과 화면)
- 문제 발생 여부: ◉ 문제 발생 확인
- 문제 유형: ◉ 상품 파손
- "해당 티켓은 확인이 종료되었습니다 변경 사항이 있으시다면 수정해주세요"

✅ **Do**
- 문제 발생 여부: ◉ 문제 발생 확인
- 문제 유형: ◉ 상품 파손
- "반품 검수 확인이 완료되었습니다. 잘못 입력된 사항은 재검수 버튼을 눌러 수정해주세요."

## 5. 진단 및 위험 고지

### 5-a. 단정적 사실 제시 (현재 상태 진단)

진단의 신뢰성과 행동의 긴급성을 부여한다.

- [ ] 추측이나 가정 없이, 시스템이 확인한 현재 사실을 **현재 시제로 단정적으로** 제시하는가?
- [ ] "꽤", "심하게" 같은 주관적 형용사 대신, **측정 가능한 수치**(%, 시간, 임계치)나 **구체적 식별 정보**(항목명, 위치)를 명시했는가?

### 5-b. 잠재적 영향 명시 (미래)

현재 상태가 미래에 미치는 결과를 책임감 있게 경고한다.

- [ ] 경고 상황: "~할 수 있습니다", "~됩니다" 시제로 잠재적 위험을 명확히 경고했는가?
- [ ] 설정/미작동 상황: 사용자가 잃게 되는 핵심 가치(실시간 모니터링, 알림 수신 등)를 명시하여 설정을 유도하는가?

## 6. 불확실성 제어

사용자의 불안을 유발하는 요소를 제거하고, 시스템 사용 과정을 예측 가능하게 만든다.

### 체크리스트

- [ ] 버튼을 누르거나 다음 단계로 넘어갈 때, 다음 화면에서 발생할 결과(시스템 재시작, 메일 수신 등)를 미리 알려 불안감을 제거했는가?
- [ ] 유머, 은어, 이모티콘, "놀라운", "대박" 같은 감정적이거나 과장된 표현을 사용하지 않았는가?

### Do / Don't 예시

❌ **Don't**: "전체 알림 설정시 모든 유저에게 알림이 발송됩니다"
✅ **Do**: "전체 알림 설정 확인 — 설정을 저장하면, 이후 이벤트 발생 시 등록된 모든 사용자에게 알림이 발송됩니다. 특정 담당자에게만 알림을 발송하려면, 담당자 지정 알림을 설정해야 합니다."

❌ **Don't**: "결제 수단 상태가 원활하지 않습니다."
✅ **Do**: "등록된 결제 수단이 만료되었습니다. 다음 결제일에 구독 결제가 실패할 수 있습니다. 조치가 없을 경우 구독이 일시정지됩니다. 서비스를 유지하려면 결제 수단을 다시 등록해 주세요."

## 7. PRD 안에서 UI 텍스트 작성하는 위치

기능 정의 산출물의 화면별 기능 정의 안에 다음 서브섹션을 둔다.

```
[화면명]
1. 화면 목적
2. 기능 정의
3. 비즈니스 로직 (필요 시 Mermaid)
4. UI 텍스트 초안
   4-a. 알림/메시지 (A·B·C 적용)
   4-b. 버튼 레이블 (어조 규칙 적용)
   4-c. 에러 메시지 (코드 노출 금지, 행동 명시)
   4-d. 빈 상태 / 로딩 상태 안내
5. 계산 수식 (해당 시)
```

## 8. 최종 체크리스트

PRD 작성 완료 시 모든 UI 텍스트에 대해 다음을 확인:

- [ ] 코어 밸류 4가지(명확/전문/책임감/일관)를 충족하는가
- [ ] 기본 3요소(A·B·C)가 적절히 적용되었는가
- [ ] 어조 규칙(명사형/필요합니다/해주세요)이 일관되는가
- [ ] 전문 용어에 대한 보조 설명이 있는가
- [ ] 동일 의미에 동일 단어를 사용하는가
- [ ] 다음 동작의 결과를 미리 알려주는가
- [ ] 감정적·과장된 표현을 배제했는가
