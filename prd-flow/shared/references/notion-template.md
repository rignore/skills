# Notion 페이지 템플릿 (선택 — notion_upload 활성 시에만)

prd-flow 스킬 세트가 Notion에 업로드할 때 사용하는 표준 페이지 구조. **모든 산출물의 SoT(진실의 원천)는 로컬 파일(`prd-flow/{slug}/`)이며, Notion 페이지는 그 미러다.** context.json의 `notion_upload`가 true인 경우에만 이 템플릿을 사용한다. Notion 없이도 전체 파이프라인이 동작해야 한다.

상위 페이지(허브) + 하위 페이지(작성/산출물) 분리 구조를 사용한다. 표준 Notion MCP 도구(`notion-create-pages`, `notion-update-page`, `notion-fetch`, `notion-search`)만 사용한다.

## 페이지 구조 개요

```
📄 PRD - {제품/기능명}  (상위 페이지 - 허브)
├── [메타 정보 블록 / 페이지 프로퍼티]
├── [📊 산출물 진행 상태 보드]
├── [👀 외부 공유용 산출물 콜아웃 - 하위 페이지 링크]
├── 📝 변경 이력 (테이블)
│
└── [하위 페이지들]
    ├── 📋 Working Doc           (최초 업로드 시 함께 생성)
    ├── 📌 1-Pager PRD            (통합 산출 시 자동 생성)
    └── 📐 Full PRD               (통합 산출 시 자동 생성, Full 모드만)
```

## 상위 페이지 (허브)

작성 진행 추적과 산출물 진입점만 담는다. 작성 내용이 누적되지 않으므로 항상 짧고 깔끔하게 유지된다.

### 페이지 프로퍼티

| 프로퍼티명 | 타입 | 값 |
|---|---|---|
| 작성자 | Person | 작성자 |
| 모드 | Select | One-Page / Full |
| 전체 상태 | Select | 작성 중 / 검토 중 / 확정 / 보류 |
| 마지막 수정일 | Date | 자동 |
| AI 기능 포함 | Checkbox | 여부 |
| 이해관계자 | Multi-person | 검토자 목록 |
| 관련 프로젝트 | Relation | 상위 프로젝트 (사용자 워크스페이스에 있는 경우만) |

> 프로퍼티는 사용자의 Notion 워크스페이스 구조에 맞춰 조정 가능. 특정 DB 스키마를 전제하지 않는다.

### 상위 페이지 본문 구조

```markdown
# PRD - {제품/기능명}

> 작성일: {YYYY-MM-DD}
> 모드: {One-Page | Full}
> AI 기능 포함: {예 | 아니오 | 미확정}
> 작성자: {작성자}
> 이해관계자: {목록}

---

## 📊 산출물 진행 상태

| 산출물 (검토 영역) | 상태 |
|---|---|
| 문제 정의 | 대기 |
| 사용자 & 시나리오 | 대기 |
| 기능 정의 | {대기 | Skip} |
| AI 에이전트 사양 (조건부) | {대기 | Skip} |
| 우선순위 | 대기 |
| KPI & 성공 기준 | 대기 |
| 통합 리뷰 | {대기 | Skip} |
| QA 테스트 리스트 | {대기 | Skip} |
| 통합 산출 (1-Pager / Full PRD) | 대기 |

상태 값: `대기`, `작성 중`, `검토 중`, `확정`, `Skip`

---

## 👀 외부 공유용 산출물

> 통합 산출 완료 후 다음 하위 페이지를 단독 공유할 수 있습니다.

- 📋 **Working Doc** ({링크}) — 작성 과정·페르소나 리뷰 (PM·내부 팀)
- 📌 **1-Pager PRD** ({링크 또는 "통합 산출 완료 후 생성됨"}) — 임원진·세일즈·마케팅
- 📐 **Full PRD** ({링크 또는 "Full 모드 통합 산출 완료 후 생성됨"}) — 엔지니어·QA·디자이너

---

## 📝 변경 이력

| 일시 | 영역 | 변경 내용 | 변경자 | 반영된 페르소나 피드백 |
|---|---|---|---|---|
| {생성 일시} | 초기 설정 | PRD 페이지 생성 (상위 + Working Doc) | {작성자} | - |
```

## 하위 페이지: 📋 Working Doc

작성 과정 전체를 담는 작업 페이지. PM과 내부 팀의 작업 영역. 외부 이해관계자에게 공유되지 않는다.

### Working Doc 본문 구조

```markdown
# 📋 Working Doc — {제품/기능명}

> 상위 페이지: {링크}
> 이 페이지는 PRD 작성 과정·페르소나 리뷰를 누적합니다. 외부 공유는 1-Pager PRD / Full PRD 페이지를 사용하세요.

---

## 📋 문제 정의 (토글)

🟡 아직 작성되지 않았습니다.

- 해결 시 기대 효과

---

## 👤 사용자 & 시나리오 (토글)

🟡 아직 작성되지 않았습니다.

작성 예정 항목: 페르소나, User Story, Happy Path, Edge Case

---

## ⚙️ 기능 정의 (토글)

🟡 아직 작성되지 않았습니다.

작성 예정 항목: 에이전트 구성도, 입력 컨텍스트, 상황별 동작 매트릭스, 단계적 판단 플로우, 프롬프트 정책, 실패/엣지 처리
```

## 하위 페이지: 📌 1-Pager PRD

통합 산출 단계에서 생성. 양식·시스템 프롬프트는 `shared/references/1pager-prd-template.md` 참조.

- One-Page 모드 / Full 모드 모두 생성
- 임원진·세일즈·마케팅 단독 공유 가능 (URL·권한 분리)
- A4 1장 분량 강제

## 하위 페이지: 📐 Full PRD

통합 산출 단계의 Full 모드에서 생성. 양식·시스템 프롬프트는 `shared/references/full-prd-template.md` 참조.

- Full 모드만 생성 (One-Page 모드에서는 만들지 않음)
- 엔지니어·QA·디자이너 단독 공유 가능
- 티켓 위계(Epic 하위에 Story·Task 같은 레벨, 각각 Sub-task) 적용

## 최초 업로드 절차 (notion_upload 활성 시)

1. `tool_search`로 Notion MCP 도구 로드 (`notion-create-pages`)
2. 부모 페이지 식별 (사용자가 제공한 URL 또는 페이지명 → `notion-search`)
3. **상위 페이지 생성** — `notion-create-pages`로 빈 허브 페이지 생성, 메타·산출물 진행 상태·콜아웃·변경 이력 표 배치
4. **Working Doc 하위 페이지 생성** — 상위 페이지 자식으로 `notion-create-pages` 호출, 검토 영역별 토글·페르소나 리뷰 로그 빈 구조 배치
5. 상위 페이지 콜아웃에 Working Doc 링크 삽입, 1-Pager / Full PRD는 "통합 산출 완료 후 생성됨" 플레이스홀더로 표시
6. 변경 이력에 "PRD 페이지 생성 (상위 + Working Doc)" 행 추가
7. 두 페이지 URL 모두 사용자에게 안내

## 통합 산출물 업로드 절차

1. **1-Pager PRD 페이지 생성** — 상위 페이지 자식으로 `notion-create-pages` 호출, `shared/references/1pager-prd-template.md`의 출력 양식 적용
2. (Full 모드만) **Full PRD 페이지 생성** — 상위 페이지 자식으로 `notion-create-pages` 호출, `shared/references/full-prd-template.md`의 출력 양식 적용
3. 상위 페이지 콜아웃의 1-Pager / Full PRD 링크 갱신
4. 변경 이력에 "1-Pager PRD 생성", (Full 모드만) "Full PRD 생성" 행 추가

## 통합 산출물 재업로드 (갱신) 시

선행 산출물 수정 후 사용자가 "1-Pager·Full PRD 갱신"을 요청하면:

1. 로컬 산출물을 먼저 갱신한 뒤, 기존 1-Pager / Full PRD 하위 페이지를 **덮어쓰기** (`notion-update-page` 또는 본문 블록 교체)
2. 변경 이력에 "1-Pager·Full PRD 갱신: {시점}" 행 추가
3. 상위 페이지의 마지막 수정일 갱신

## 부분 업데이트 시 주의사항

- **부분 업데이트**: 해당 검토 영역 토글만 수정. 다른 영역 건드리지 않음. **Working Doc 안에서만** 작업
- **상태 보드 동기화**: 산출물 완료 시 상위 페이지의 산출물 진행 상태 표 업데이트
- **변경 이력 추가**: 모든 업데이트는 상위 페이지 변경 이력 테이블에 행 추가
- **상위 페이지에는 작성 내용을 누적하지 않는다** — 메타·진행 상태·콜아웃·변경 이력만 두고, 길이가 짧게 유지되도록 한다
- **로컬 우선**: 항상 로컬 파일을 먼저 수정하고 Notion에 반영한다. Notion에서만 수정된 내용이 발견되면 사용자에게 로컬 반영 여부를 확인한다

## 페이지 권한·공유

스킬은 페이지 공유 권한을 직접 변경하지 않는다. 사용자에게 안내만 제공:

- **상위 페이지**: PM·이해관계자 전체 (작성 진행 추적용)
- **Working Doc**: PM·내부 팀만 (작성 과정·페르소나 리뷰 노출 방지)
- **1-Pager PRD**: 임원진·세일즈·마케팅 (외부 공유 가능)
- **Full PRD**: 엔지니어·QA·디자이너 (내부 또는 협력사)

## 기존 PRD 페이지 업데이트 시

사용자가 "기존 PRD에 KPI 섹션만 추가" 같은 요청을 할 경우:

1. 기존 상위 페이지 URL 받기
2. `notion-fetch`로 상위 + Working Doc 구조 확인
3. Working Doc의 해당 영역 토글에서만 작업
4. 다른 영역은 건드리지 않음
5. 상위 페이지 변경 이력에 기록

기존 페이지가 구버전(상위/하위 분리 전 단일 페이지) 구조라면 사용자에게 마이그레이션 여부 확인:

```
이 PRD 페이지는 구버전(단일 페이지) 구조입니다.
새 구조(상위 + Working Doc + 1-Pager/Full PRD 하위 페이지)로 마이그레이션할까요?
- 예 → 기존 영역별 토글을 Working Doc 하위 페이지로 이동, 상위 페이지 정리
- 아니오 → 구버전 구조 유지하며 요청된 영역만 추가
```
