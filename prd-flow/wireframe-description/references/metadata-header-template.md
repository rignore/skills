# 메타데이터 헤더 템플릿

디스크립션 문서의 최상단에 반드시 포함하는 헤더 블록이다.
Owner, 작성일, PRD 링크가 없으면 문서의 출처와 책임이 불명확해진다.

---

## 표준 헤더 형식

```markdown
# {화면명}

Revision history
| 버전 | 변경 내용 | Author | Date |
|------|---------|--------|------|
| 0.0  | 최초 작성  | {이름}  | YYYY.MM.DD |

Owner: 기획 {이름} / 디자인 {이름} / 개발 {이름}, {이름}
Date: 최초 {YYYY.MM.DD} / 최종 수정 {YYYY.MM.DD}
Doc. Link: PRD {로컬 경로 또는 URL} / DEV {URL}
```

---

## 작성 규칙

| 필드 | 작성 기준 |
|------|---------|
| **화면명** | 프로토타입 화면 명칭 기준으로 사용 |
| **버전** | 최초 작성은 `0.0`. 이후 내용 변경마다 `0.1`, `0.2`... 증가. 화면 구조 변경(넘버링 재수립)은 `1.0`으로 메이저 증가 |
| **변경 내용** | 구체적으로 기술 (예: "3-2 화면 상태 분기 추가", "에러 처리 정책 반영") |
| **Author** | 디스크립션 작성자 이름 |
| **Owner 기획** | 해당 화면 기획 담당자 |
| **Owner 디자인** | 시각 디자인 담당자 (미정이면 `TBD`) |
| **Owner 개발** | 프론트엔드 개발 담당자 (미정이면 `TBD`) |
| **Date 최초** | 최초 작성일 `YYYY.MM.DD` |
| **Date 최종 수정** | 가장 최근 수정일 `YYYY.MM.DD` |
| **Doc. Link PRD** | 로컬 PRD 경로(`prd-flow/{slug}/notion-pages/full-prd.md`). notion_upload가 true면 Notion PRD URL 병기. 없으면 `미제출` |
| **Doc. Link DEV** | 개발 스펙 문서 또는 이슈 트래커 링크. 없으면 생략 |

---

## 수정 이력 추가 예시

```markdown
Revision history
| 버전 | 변경 내용 | Author | Date |
|------|---------|--------|------|
| 0.0  | 최초 작성  | 김기획  | 2026.05.14 |
| 0.1  | 에러 처리 정책 반영 (오류 안내 스낵바 정책 참조로 변경) | 김기획 | 2026.05.20 |
| 0.2  | [3-2a] 펼쳐진 상태 분기 추가 | 김기획 | 2026.06.03 |
| 1.0  | 화면 구조 변경에 따른 넘버링 전면 재수립 | 김기획 | 2026.07.01 |
```

---

## PRD 없을 때

로컬 PRD 파일도 Notion URL도 없는 경우:

```markdown
Doc. Link: PRD 미제출 / DEV -
```

디스크립션 본문에서 비즈니스 로직·정책 항목은 `*` 인라인 노트로 표기한다.
