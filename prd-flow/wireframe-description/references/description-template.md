# 디스크립션 작성 템플릿 및 가이드

## Description 블록 기본 구조

각 화면 단위(Scene)에 대해 아래 구조로 작성한다.

```markdown
Description

{화면/섹션 명칭}

{이 화면이 언제 표시되는지 진입 조건 기술. 한두 문장이면 충분.}

[번호] 컴포넌트명

{무엇을 표시하는지, 어떤 데이터가 바인딩되는지 직접적으로 기술.}

{조건이 있으면 이어서 기술.}

[번호-서브] 하위 요소명 : 한 줄로 설명이 가능하면 콜론(:) 뒤에 바로 기술

{한 줄로 부족하면 줄바꿈 후 상세 기술}
```

---

## 핵심: 쓰는 것 vs 쓰지 않는 것

### 쓰지 않는 것 (와이어프레임에서 보이는 것)

```
❌ **표시 형식**: "신규 태스크 등록" 고정 텍스트
❌ **라벨 표시 형식**: "태스크 유형 *"
❌ **표시 형식**: "취소" 고정 텍스트 버튼
❌ **플레이스홀더**: "예: 3분기 마케팅 캠페인 기획"
❌ 모달 최상단 영역. 제목과 닫기 버튼을 포함한다.
❌ 2열 그리드로 배치한다.
```

위 내용은 와이어프레임을 보면 바로 알 수 있다. 디스크립션에 쓰면 중복이다.

### 쓰는 것 (와이어프레임만 봐서는 알 수 없는 것)

```
✅ AI가 생성한 전체 미처리 주문 이슈의 핵심 요약 텍스트 표시.
✅ "이슈 상세 ({N}건 · {M}그룹)" 형식으로 표시
✅ 판매 채널이 지정되어 있지 않을 경우 미표시
✅ 동일 지표의 이슈가 2건 이상일 때만 표시
✅ 클릭 시 해당 주문 상세 팝업 화면에 표시
✅ *현재 DB에 없는 정보, 해당 항목 어떻게 저장할지 논의 필요
```

와이어프레임에서 "이슈 상세(10건 · 2그룹)"이라고 보이더라도, 그 숫자가 어떤 데이터를 어떤 규칙으로 계산한 것인지는 보이지 않는다. 그것을 기술하는 것이 디스크립션의 역할이다.

## 작성 스타일 규칙

### 1. 간단한 요소는 한 줄로

하위 요소가 단순하면 `[번호] 이름 : 설명` 한 줄로 끝낸다.

```markdown
[2-1a] 이슈 유형명 : 그룹핑된 이슈 유형명 표시

[2-1c] 판매 채널명 : 그룹핑된 판매 채널명 표시

판매 채널이 지정되어 있지 않을 경우 미표시
```

불필요한 볼드 헤더("**표시 형식**:", "**데이터 소스**:") 없이, 설명이 곧 내용이다.

### 2. 동적 데이터 형식은 템플릿 문자열로

화면에 표시되는 데이터의 형식을 기술할 때, 템플릿 문자열을 사용한다.

```markdown
헤더 텍스트 : "이슈 상세 ({N}건 · {M}그룹)" 형식으로 표시

{N} = 전체 미처리 이슈 수
{M} = 그룹핑 후 생성된 그룹 수
```

```markdown
표시 형식 : "{방향 화살표} ({부호}{차이값}{단위})" 형식으로 표시
```

**주의**: 고정 텍스트(버튼 라벨, 섹션 제목 등)에는 템플릿 문자열을 쓰지 않는다. 템플릿은 **동적으로 바뀌는 데이터**에만 사용한다.

### 3. 조건은 직접적으로

조건부 표시는 간결하게 기술한다.

```markdown
동일 지표의 이슈가 2건 이상일 때만 표시.

판매 채널이 지정되어 있지 않을 경우 미표시
```

복수 조건이 있으면:

```markdown
결제 유형이면서 카드 또는 간편결제인 그룹에 표시
```

### 4. 인터랙션은 트리거 → 동작

```markdown
기본 상태는 접힘, 클릭 시 펼쳐짐.
```

```markdown
마우스 오버 시 해당 플랜에 대한 "플랜 설명" 툴팁 표시
```

```markdown
*클릭 시 해당 주문 상세 팝업 화면에 표시
```

무거운 구조("**인터랙션**: - 클릭 시: ...") 없이 자연스러운 문장으로.

### 5. 계산/수식이 있는 복합 항목만 상세하게

단순한 항목은 한두 줄이면 충분하지만, 계산 로직이나 분기가 복잡한 항목은 상세하게 풀어쓴다.

```markdown
[2-2d-1] 방향 화살표 및 변화량 : "{방향 화살표} {변화량}" 형식으로 표시

방향 화살표 표시 정책 : 최초 이슈 값과 최신 이슈 값을 비교하여 표시
- 최신값 > 최초값 → "▲" 표시
- 최신값 < 최초값 → "▼" 표시
- 최신값 = 최초값 → "—" 표시

변화량 표시 정책 : "({부호}{차이값}{단위})" 형식으로 표시
- 수식: 차이값 = 최신값 − 최초값
- 부호: 차이값 > 0이면 "+", 차이값 < 0이면 "−", 0이면 미표시
- 소수점 1자리까지 표시

색상: 화살표 색상과 동일
```

### 6. 논의/확인 필요 사항은 `*` 인라인 노트

```markdown
[2-1b] 이슈 유형 태그 : 이슈 유형에 대한 부가 정보를 태그 형식으로 표시

이슈 발생 영역 정보 표시 - "결제" 또는 "배송" 중 한 개 표시
*현재 DB에 없는 정보, 보고서에 기재되는 정보로 해당 항목 어떻게 저장할지 논의 필요
```

`> ⚠️ **논의 필요**:` 같은 무거운 블록쿼트 대신, `*` 한 줄로 해당 항목 바로 아래에 표기한다.

### 7. 그룹핑/정렬 정책

데이터가 어떤 기준으로 묶이고 정렬되는지 기술한다.

```markdown
그룹핑 기준 : 이슈를 이슈 유형 + 판매 채널 조합으로 그룹핑하여 표시.

동일 이슈 유형이라도 판매 채널이 다르면 별도 그룹으로 분리.
판매 채널 정보가 없는 이슈끼리는 같은 그룹으로 묶음.
```

```markdown
해당 지표의 전체 이슈를 최신순(내림차순)으로 나열
```

### 8. 색상 의도 (예외적 기술)

구체적 색상값은 쓰지 않되, 의미적 강조가 있으면 간단히 언급한다.

```markdown
색상: 화살표 색상과 동일
```

```markdown
확인 상태에 따라 시각적 구분 필요 (미확인/확인중)
```

### 9. 공통 정책 참조

시스템 공통 정책이 존재하면, 해당 정책을 디스크립션에서 다시 풀어 쓰지 않고 **정책명으로 참조**한다. 이렇게 하면 정책이 변경되어도 개별 디스크립션을 수정할 필요가 없다.

**좋은 예:**
```markdown
검색: 데이터 테이블 키워드 검색 정책 A 적용

정렬: 데이터 정렬 기준 정책 B (사용자 등록 데이터) 적용

유효성 검증: 텍스트 입력폼 유효성 검증 정책 A 적용 (입력 항목 3개 이상이므로 포커스 아웃 시점 검증)
```

**나쁜 예:**
```markdown
검색 시 키워드와 데이터에서 공백을 제거하고 연속된 2개 이상의 숫자/문자가 일치할 경우 표시합니다...
(= 공통 정책을 그대로 복사한 것. 정책이 바뀌면 모든 디스크립션을 수정해야 함)
```

**공통 정책과 차이가 있는 경우:**
```markdown
정렬: 데이터 정렬 기준 정책 A 적용. 단, 이 화면에서는 최근 접속일 기준 내림차순을 우선 적용.
```

### 10. 종속 관계/비활성화

다른 컴포넌트의 선택/값에 따라 활성·비활성이 결정되는 관계를 기술한다.
인과 관계를 "[원인 컴포넌트] 조건 → [결과 컴포넌트] 상태" 형식으로 간결하게 쓴다.

```markdown
[1-2] 태스크 유형 셀렉박스

[1-1] 프로젝트 미선택 시 비활성화.

선택 후 [1-1] 값이 변경되면 선택값 초기화.
```

```markdown
[2-3] 저장 버튼

필수 입력 항목([2-1], [2-2]) 중 하나라도 미입력 시 비활성화.
```

### 11. 에러/예외 처리

데이터 호출 실패, 타임아웃, 권한 오류 등 예외 상황에서의 UI 처리를 기술한다.
공통 정책으로 처리 가능하면 정책명으로 참조한다.

```markdown
[3-1] 주문 목록

데이터 호출 실패 시: 오류 안내 스낵바 정책 적용.
```

```markdown
[2-2] 라인 차트

데이터 로딩 실패 시 "데이터를 불러올 수 없습니다.\n잠시 후 다시 시도해 주세요." 표시 + [새로고침] 버튼 노출.
```

```markdown
[1-5] 첨부 이미지 뷰어

이미지 로딩 실패 시: 대체 아이콘 + [다시 시도] 버튼 표시.
```

### 12. 외부 화면 참조

다른 화면 설계서에 상세가 정의된 경우, 해당 문서를 참조하도록 기술한다.
중복 작성을 방지하고 단일 출처를 유지한다.

```markdown
[2-1] 이슈 그룹 카드

카드 내 컴포넌트 상세 구성 → (AI 이슈 요약 배너 설계서 [2] 참고)
```

```markdown
그룹핑 기준 참고 → [2]
```

```markdown
주문 상세 팝업 동작 상세 → (주문 상세 팝업 설계서 참고)
```

### 13. 데이터 정의/카테고리 목록

셀렉박스, 탭, 필터 등의 선택 항목 목록이 고정값이거나 시스템 정의값인 경우 기술한다.
동적으로 불러오는 경우는 출처(API·DB)를 기술한다.

```markdown
[1-3] 워크스페이스 타입 셀렉박스

카테고리: 개인 / 팀 / 조직 (고정값)
```

```markdown
[3-2] 문제 유형 셀렉박스

카테고리: DB에서 동적 로드. 관리자가 등록한 문제 유형 목록 표시.

*현재 어드민 화면 미개발, 초기값 하드코딩 여부 논의 필요
```

## 출력 파일 형식

최종 문서는 아래 구조의 Markdown 파일로 출력한다. **메타데이터 헤더는 반드시 포함한다.**

```markdown
# {화면명}

Revision history
| 버전 | 변경 내용 | Author | Date |
|------|---------|--------|------|
| 0.0  | 최초 작성  | {이름}  | YYYY.MM.DD |

Owner: 기획 {이름} / 디자인 {이름} / 개발 {이름}, {이름}
Date: 최초 {YYYY.MM.DD} / 최종 수정 {YYYY.MM.DD}
Doc. Link: PRD {로컬 경로 또는 URL} / DEV {URL}

---

Description

{화면 단위 1 명칭}

{진입 조건}

[1-1] 컴포넌트명

{설명...}

[1-2] 컴포넌트명 : 간단한 설명

---

Description

{화면 단위 2 명칭}

{...}

---

부록: PRD 대비 차이점

| 항목 | PRD | 와이어프레임 | 비고 |
|------|-----|----------|------|
| (차이점 없으면 이 섹션 생략) | | | |
```

## 완성 예시

아래는 예시 도메인(커머스 어드민)의 "AI 주문 이슈 요약 배너" 화면에서 발췌한 작성 예시다.

```markdown
Description

비정상 상태 배너 기본 상태

해당 스토어에 미확인 또는 확인 중 이슈가 1건 이상 존재할 때 표시.

[1-1] 이슈 요약

AI가 생성한 전체 미처리 이슈의 핵심 요약 텍스트 표시.

[1-2] 패턴 분석

AI가 생성한 전체 추세 판단 텍스트를 표시합니다.

[1-3] 이슈 상세 아코디언

기본 상태는 접혀있고 클릭 시 펼쳐짐.

헤더 텍스트 : "이슈 상세 ({N}건 · {M}그룹)" 형식으로 표시

{N} = 전체 미처리 이슈 수
{M} = 그룹핑 후 생성된 그룹 수

그룹핑 기준 참고 - [2]

---

Description

이슈 그룹 카드 - 결제 유형

그룹핑 기준 : 이슈를 이슈 유형 + 판매 채널 조합으로 그룹핑하여 표시.

동일 이슈 유형이라도 판매 채널이 다르면 별도 그룹으로 분리.
판매 채널 정보가 없는 이슈끼리는 같은 그룹으로 묶음.

[2-1] 그룹 카드 헤더

[2-1a] 이슈 유형명 : 그룹핑된 이슈 유형명 표시

[2-1b] 이슈 유형 태그 : 이슈 유형에 대한 부가 정보 아래 순서대로 태그 형식으로 표시

이슈 발생 영역 정보 표시 - "결제" 또는 "배송" 두 개 중 한 개 표시
*현재 DB에 없는 정보, 보고서에 기재되는 정보로 해당 항목 어떻게 저장할지 논의 필요

세부 카테고리
- 결제 유형일 경우 : 카드, 간편결제, 가상계좌 중 한 개 표시
  *현재 DB에 없는 정보, 보고서에 기재되는 정보로 해당 항목 어떻게 저장할지 논의 필요
- 배송 유형일 경우 : 현재는 표시 x, 추후 배송사별 분류 등 다양한 케이스가 추가될 시 화면에 표시

[2-1c] 판매 채널명 : 그룹핑된 판매 채널명 표시

판매 채널이 지정되어 있지 않을 경우 미표시

[2-1d] 이슈 건수 : 그룹핑된 총 이슈 건수 표시

[2-2] 지표 카드

결제 유형이면서 카드 또는 간편결제인 그룹에 표시

그룹 내 이슈를 지표를 기준으로 다시 묶어 지표별 카드 생성

[2-2a] 지표명 : 그룹핑된 지표의 이름 표시

[2-2b] 발생 건수 : 그룹핑된 이슈 발생 건수 표시

동일 지표의 이슈가 2건 이상일 때만 표시.

[2-2c] 최신 지표값 : 그룹핑된 이슈 중 가장 최근 발생한 이슈의 지표값 표시

동일 지표의 이슈가 2건 이상일 때 "최신값 기준" 라벨 표시

[2-2d] 변화 추이 (이슈가 2건 이상일 때만 표시)

[2-2d-1] 방향 화살표 및 변화량 : "{방향 화살표} {변화량}" 형식으로 표시

방향 화살표 표시 정책 : 최초 이슈 값과 최신 이슈 값을 비교하여 표시
- 최신값 > 최초값 → "▲" 표시
- 최신값 < 최초값 → "▼" 표시
- 최신값 = 최초값 → "—" 표시

변화량 표시 정책 : "({부호}{차이값}{단위})" 형식으로 표시
- 수식: 차이값 = 최신값 − 최초값
- 부호: 차이값 > 0이면 "+", 차이값 < 0이면 "−", 0이면 미표시
- 소수점 1자리까지 표시

색상: 화살표 색상과 동일

[2-2d-2] 값 변화 : "{최초값}{단위} → {최신값}{단위}" 형식으로 표시

[2-2d-3] 최초/최근 발생 시간

그룹핑된 이슈의 최초 및 최근 발생 시간 표시

표시 형식 : "HH:MM"
```

## 부록: PRD 대비 차이점 작성법

PRD가 함께 제공된 경우, 디스크립션 마지막에 "부록: PRD 대비 차이점" 테이블을 작성한다. 이 테이블은 Phase 7 (PRD 동기화)의 입력 자료가 된다.

```markdown
부록: PRD 대비 차이점

| 항목 | PRD | 와이어프레임 | 비고 |
|------|-----|----------|------|
| 게스트 결제 | 입력 폼 정의 | 미구현 | 지원 범위 확인 필요 |
| 재주문 버튼 | 명시적 정의 없음 | 구현됨 | 역할 정의 필요 |
```

**작성 기준:**
- 프로토타입에만 있는 기능, PRD에만 있는 명세, 양쪽 내용이 다른 경우 모두 기록
- "비고" 컬럼에 논의 필요 사항이나 판단 방향을 간략히 기술
- 사소한 차이(문구 뉘앙스 수준)는 생략하고, 개발/기획 의사결정이 필요한 항목만 기록
