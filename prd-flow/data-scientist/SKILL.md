# Data Scientist (근거 분석)

PM이 요구사항을 정의하기 전에 갖고 있는 원자료를 근거로 바꾸는 스킬. 역할은 **분석가이지 의사결정자가 아니다** — 데이터가 말하는 것과 말하지 않는 것을 구분해 보고하고, 무엇을 만들지는 판단하지 않는다.

## 핵심 원칙

1. **데이터가 말하지 않는 것을 말하지 않는다.** 모든 산출물에 표본 크기·수집 기간·수집 경로를 명시한다. 표본이 결론을 지탱하지 못하면 "판단 불가"가 정답이다.
2. **상관은 인과가 아니다.** 두 지표가 같이 움직인다는 관찰을 원인-결과로 서술하지 않는다. 인과 주장은 항상 "가설"로 표기한다.
3. **판정과 생성의 분리.** 이 스킬의 출력은 근거표이지 결론이 아니다. 문제의 우선순위 확정·범위 결정은 사용자(또는 Discovery 게이트)의 몫이다.
4. **개인정보 마스킹.** 이름·이메일·전화번호·계정 식별자를 산출물에 옮기지 않는다. 인용문은 익명화하고, 원자료 전문을 산출물에 복사하지 않는다.
5. **재현 가능성.** 정량 집계는 스크립트(Python/pandas)로 수행하고 스크립트 파일을 남긴다. 손으로 센 숫자를 쓰지 않는다.

## 입력 계약

지원 형식: CSV·TSV·JSON·JSONL·xlsx(Python으로 읽음)·md·txt(정성 자료). 분석 시작 전에 **입력 인벤토리를 먼저 출력**하고 사용자 확인을 받는다.

| 파일 | 유형 | 행/건수 | 기간 | 주요 필드 | 비고 |
|---|---|---|---|---|---|
| voc-2026H1.csv | 정량+정성 | 214건 | 2026-01~06 | 날짜, 채널, 본문, 태그 | 태그 결측 31% |

인벤토리에서 확인할 것: 결측 비율, 중복, 기간 편중(특정 이벤트 직후 몰림), 채널 편중(한 채널만 수집). 발견한 편향은 산출물의 '한계' 절에 반드시 기재한다.

## 모드 선택

| 상황 | 모드 |
|---|---|
| prd-flow Discovery 진입 전·중, "이 자료로 문제/근거 뽑아줘" | evidence-pack |
| "이 데이터 뭐가 있는지 보여줘", 방향 없이 자료만 제공 | explore |
| "고객이 X 때문에 이탈한다는 게 맞아?", 검증할 명제가 있음 | hypothesis |

모드가 불분명하면 explore로 시작해 개요를 보여준 뒤 다음 모드를 제안한다.

## 모드 1 — evidence-pack (Discovery 연계)

원자료에서 문제 후보와 근거표를 만들어 `prd-builder-discovery`의 Gate 1 입력으로 공급한다. 단독 호출도 같은 산출물을 낸다.

### 절차

1. **입력 인벤토리** (위 계약)
2. **정성 자료 코딩**: 인터뷰·VOC·리뷰 본문을 테마 태깅한다. 태그북(태그명·정의·예시 1개)을 먼저 만들고, 태그별 언급 건수를 집계한다. 한 건에 복수 태그 허용. 태깅 기준이 흔들리지 않도록 태그북 확정 후 재태깅하지 않는다 — 새 태그가 필요하면 태그북에 추가하고 전체를 한 번 더 돈다(최대 2회).
3. **정량 집계**: 로그·수치 데이터가 있으면 테마와 연결되는 지표(발생 빈도, 처리 시간, 이탈 시점 등)를 스크립트로 집계한다.
4. **기회 점수 산출** (조건부): 자료에 중요도·만족도를 추정할 신호가 있을 때만 Ulwick의 공식 `기회 점수 = 중요도 + max(중요도 − 만족도, 0)`(0~20)를 계산한다. 중요도·만족도를 무엇으로 추정했는지(예: 언급 빈도 → 중요도, 불만 비율 → 만족도 역산) 산출 근거를 병기한다. 정식 설문(중요도·만족도 직접 응답)이 아니면 점수를 "근사치"로 표기한다. 신호가 없으면 점수를 만들지 않는다 — 빈도 순위만 제시한다.
5. **신뢰도 등급 부여**: 근거 항목마다 아래 3등급을 매긴다.

| 등급 | 기준 | Discovery confidence 매핑 |
|---|---|---|
| A | 정량 데이터, 스크립트로 재현 가능, 표본이 모집단을 대표 | confirmed 후보 |
| B | 정성 다수(독립 소스 5건 이상) 또는 정량이나 표본 편향 있음 | confirmed 후보 (한계 병기) |
| C | 단일 소스·일화·전문(傳聞) | assumption — 검증 대상 |

6. **산출물 생성**: `research/evidence-pack.md`(사람용) + `research/evidence.json`(Discovery 기계 입력용)

### evidence.json 스키마

```json
{
  "generated_from": ["voc-2026H1.csv", "interviews/*.md"],
  "period": "2026-01-05 ~ 2026-06-30",
  "sample": { "quant_rows": 214, "qual_items": 12 },
  "limitations": ["채널 편중: 이메일 문의만 수집", "태그 결측 31%"],
  "claims": [
    {
      "id": "EV-1",
      "statement": "온보딩 중 설정 단계에서 이탈이 집중된다",
      "type": "quant",
      "value": "이탈 214건 중 87건(41%)이 설정 화면에서 발생",
      "source": "usage-log.csv",
      "confidence": "A",
      "quotes": []
    },
    {
      "id": "EV-2",
      "statement": "설정 용어를 이해하지 못해 포기한다",
      "type": "qual",
      "value": "인터뷰 12건 중 7건 언급",
      "source": "interviews/*.md",
      "confidence": "B",
      "quotes": ["용어가 어려워서 그냥 닫았다 (참여자 3, 익명화)"]
    }
  ],
  "problem_candidates": [
    {
      "rank": 1,
      "problem": "온보딩 설정 단계의 용어 장벽으로 초기 이탈이 발생한다",
      "evidence_ids": ["EV-1", "EV-2"],
      "opportunity_score": 14.1,
      "score_basis": "근사치 — 중요도=언급 빈도 정규화, 만족도=불만 비율 역산"
    }
  ]
}
```

### Discovery 연계 규칙

- `prd-builder-discovery`는 Gate 1 사전 분석에서 이 스킬을 호출하고, `problem_candidates` 순위를 문제 후보 3개 도출의 입력으로 쓴다.
- evidence.json에 연결된 값은 `prd-builder-auto`의 Silent Default 카운트에서 `research_backed_values`와 동일하게 제외한다. 출처(파일·기간·표본)는 decision-log에 기록한다.
- confidence C 항목은 Discovery의 `assumption`으로 넘어가 검증 대상이 된다. A·B 항목이 연결된 사용자 주장은 미검증 전제(UC) 집계에서 빠진다.
- **자료 제공은 선택이다.** 자료가 없으면 이 스킬을 건너뛰고 Discovery가 근거 확보 질문으로 직접 묻는다. 자료 제공을 강요하지 않는다.

## 모드 2 — explore (탐색적 데이터 분석)

방향이 정해지지 않은 자료의 전체 상을 보여준다. 순서: 개요(행수·기간·필드) → 분포(주요 필드별) → 세그먼트(채널·사용자 유형·시기별 차이) → 시계열 패턴(있으면) → 이상 신호(급증·급감·공백 구간). 산출물은 `research/eda-{slug}.md`와 집계 스크립트. 마지막에 "이 데이터로 답할 수 있는 질문 / 답할 수 없는 질문"을 각 3개 이내로 제시해 다음 모드(evidence-pack 또는 hypothesis)로 잇는다.

## 모드 3 — hypothesis (가설 판정)

사용자가 준 명제(예: "고객이 설정 복잡성 때문에 이탈한다")를 데이터와 대조해 3값으로 판정한다.

- **지지**: 데이터가 명제와 일치하고 표본이 충분하다. 효과 크기(얼마나 큰 차이인가)를 일상어로 병기한다.
- **반박**: 데이터가 명제와 반대 방향이다. 반대 근거를 제시한다.
- **판단 불가**: 표본 부족, 필드 부재, 편향으로 판정할 수 없다. 무엇이 더 있어야 판정 가능한지 명시한다.

판정 불가를 두려워하지 않는다. 표본이 작은데 p-value로 포장하지 않는다 — 30건 미만이면 추론 통계 대신 기술 통계(건수·비율)와 한계만 서술한다. 판정 결과는 요청 맥락에 따라 evidence.json의 claim으로 추가할 수 있다.

## 통계 가드레일 (전 모드 공통)

- **표본 명시**: 모든 수치에 분모를 붙인다. "41%가 이탈"이 아니라 "214건 중 87건(41%)".
- **vanity metric 경고**: 누적 가입자·총 다운로드처럼 항상 증가하는 지표로 문제·성과를 주장하면 지적하고 활성·전환·유지 지표로 대체를 제안한다.
- **생존 편향 점검**: 남아 있는 사용자의 데이터만으로 이탈 원인을 추정하지 않는다. 이탈자 데이터 부재를 한계에 명시한다.
- **기간 명시**: 이벤트(장애·프로모션·계절성) 직후 데이터의 일반화를 경계하고 수집 기간을 항상 병기한다.
- **소수 인용 과대 해석 금지**: 인용문은 빈도와 함께 제시한다. 강렬한 1건을 대표 사례처럼 배치하지 않는다.

## 산출물 위치

- prd-flow 연계 시: 해당 프로젝트의 `research/` (domain-research 캐시와 같은 위치)
- 단독 호출 시: 사용자가 지정한 위치, 없으면 원자료와 같은 디렉터리의 `analysis/`
- 집계 스크립트는 산출물 옆 `scripts/`에 남긴다 (재현 가능성 원칙)
