# 리서치 캐시 템플릿

`prd-flow/{feature-slug}/research/domain-{topic-slug}.md` 파일의 표준 구조. 모든 섹션이 필수는 아니며, 토픽 성격에 맞는 섹션만 채운다. **전체 200줄 이내**로 압축한다.

```markdown
# 도메인 리서치: {토픽 이름}

> 조사 일시: {YYYY-MM-DD}
> 사용 쿼리: "{쿼리 1}", "{쿼리 2}"
> 출처 수: {N}개 도메인
> 상태: {신규 | 갱신({이전 일시}) | 사용자 제공 자료 병합}

## 1. 용어 정의

| 용어 | 정의 | 출처 |
|---|---|---|
| {용어} | {한 줄 정의} | [출처: {도메인}] |

## 2. 대표 제품·패턴

- **{제품/서비스명}**: {핵심 기능 구성·UX 패턴 요약 1~2줄} [출처: {도메인}]
- 공통 패턴: {카테고리 제품들이 공유하는 기능·플로우 관행}

## 3. 수치·벤치마크

| 항목 | 값 | 비고 | 출처 |
|---|---|---|---|
| {지표/임계치} | {값} | {단일 출처 여부, 측정 조건} | [출처: {도메인}] |

## 4. 정책·규제·엣지케이스

- {도메인 규제/플랫폼 정책/알려진 엣지케이스} [출처: {도메인}]
- ⚠️ 검증 필요: {단일 출처이거나 상충 정보가 있는 항목}

## 5. PRD 반영 포인트

- {이 리서치가 PRD의 어느 결정에 근거가 되는지 1줄씩}

## 출처 목록

1. {도메인} — {페이지 제목 or 요지}
2. ...
```

## 작성 규칙

- 검색 원문을 통째로 붙여넣지 않는다. 패턴·수치·용어만 추출.
- 모든 수치·주장에 출처 병기. 출처가 하나뿐이면 "단일 출처" 표시.
- 사용자 제공 지식과 충돌하는 항목은 사용자 지식을 본문에, 리서치 값을 비고에 남긴다.
- 섹션 5(PRD 반영 포인트)는 캐시를 적재한 Phase에서 계속 갱신해도 된다.
