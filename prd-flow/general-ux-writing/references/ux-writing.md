# Tone and Writing — 표준 UX Writing 룰북

서비스의 모든 UI 텍스트(라벨·버튼·알림·에러·헤더·캡션·placeholder)를 작성할 때 따라야 할 가이드. prd-flow 스킬 세트의 표준 UX writing 룰북이다.

> **활용 시점**: 버튼 라벨, 알림 문구, 에러 메시지, 폼 라벨/helper/placeholder, 빈 상태 메시지, 토스트/스낵바, 모달 제목/본문/CTA 작성 시.

---

## 1. 코어 밸류 — 4가지 지향 가치

모든 텍스트는 아래 4개 가치를 동시에 충족해야 한다.

| 가치 | 의미 | 화면 안에서의 모습 |
|---|---|---|
| **명확한** | 사용자가 즉시 이해 | "결제가 거절되었습니다" (○) / "오류 발생" (✗ 무엇이?) |
| **전문적인** | 도메인의 신뢰 | "API 응답 시간 5초 초과" (○) / "엄청 느려요" (✗) |
| **책임감 있는** | 책임 소재와 행동 책임 명시 | "다시 로그인이 필요합니다" (○) / "다시 해주시면 좋겠어요" (✗) |
| **일관적인** | 서비스 전반 용어·어조 통일 | 같은 개념은 같은 단어로. "취소"와 "철회" 혼용 금지 |

---

## 2. 메시지 3요소 — 알림·경고의 표준 구조

알림·경고·중요 메시지는 아래 3요소 중 **최소 2개**를 조합한다. 긴급도에 따라 조정.

| 요소 | 정의 | 시제·어조 |
|---|---|---|
| **A. 현재 상황 / 문제** | 시스템이 확인한 사실 (데이터·이벤트·수치) | 현재형 단정 (`~되었습니다`, `~확인되었습니다`) |
| **B. 영향 / 책임** | 방치 시 예상되는 잠재적 위험 | 미래형 (`~할 수 있습니다`, `~됩니다`) |
| **C. 필수 행동** | 사용자에게 요구되는 조치 | `~이 필요합니다` |

### 조합 패턴

| 긴급도 | 조합 | 예시 |
|---|---|---|
| 즉시 대응 필요 (긴급) | **A + C** | "결제가 거절되었습니다(A). 다른 카드로 재시도가 필요합니다(C)." |
| 사전 경고 | **A + B** | "구독 만료까지 3일 남았습니다(A). 갱신하지 않으면 서비스 접근이 중단됩니다(B)." |
| 정보 안내 | **A + C** (간결) | "신규 가입 요청 3건 대기 중(A). 검토 후 승인이 필요합니다(C)." |
| 완벽한 메시지 | **A + B + C** | "다른 기기에서 로그인 시도가 감지되었습니다(A). 본인이 아닐 경우 계정이 도용될 수 있습니다(B). 즉시 비밀번호 변경이 필요합니다(C)." |

### 안티 조합 (피해야 할 패턴)

- **A만**: "오류 발생" → 무엇을 해야 할지 모름
- **C만**: "확인이 필요합니다" → 무엇을 확인해야 할지 모름
- **B만**: "위험할 수 있습니다" → 추측·공포 조장만 됨

## 3. 어조 분리 규칙

메시지 성격에 따라 3가지 어조를 분리한다. **혼용하면 신뢰감이 깨진다.**

| 메시지 유형 | 어조 | 사용처 | 예시 |
|---|---|---|---|
| **시스템 기능** | 명사형 | 버튼·메뉴·페이지 타이틀·진행 상태 | `저장`, `삭제`, `대시보드`, `처리 중`, `계정 설정` |
| **상태 / 조치 요구** | `~이 필요합니다` | 알림·경고·시스템 진단 결과 | "결제 정보 업데이트가 필요합니다." |
| **사용자 조작 / 안내** | `~해주세요` | 폼 helper, placeholder, 가이드 메시지 | "올바른 이메일 형식으로 작성해주세요.", "검색어를 2자 이상 입력해주세요." |

### 어조 매핑 — 실제 화면 영역별

| 영역 | 어조 | 일반 SaaS 예시 |
|---|---|---|
| 사이드바 nav | 명사형 | `대시보드`, `프로젝트`, `통계`, `설정` |
| 페이지 타이틀 | 명사형 | `계정 설정`, `결제 관리`, `프로젝트 선택` |
| 액션 버튼 | 명사형 (동사 명사화) | `저장`, `등록`, `초대 전송`, `결제하기` |
| 폼 라벨 | 명사형 | `이메일`, `비밀번호`, `회사명`, `전화번호` |
| 폼 placeholder | `~해주세요` | "이메일 주소를 입력해 주세요.", "8자 이상 입력해 주세요." |
| 폼 helper | 명사형 또는 평서문 | "영문·숫자·특수문자 포함 8자 이상" |
| 에러 메시지 | `~해주세요` | "올바른 이메일 형식으로 작성해주세요." |
| 알림 배너 (긴급) | `~이 필요합니다` | "결제 정보 업데이트가 필요합니다." |
| 빈 상태 (Empty) | 명사형 + `~해주세요` | "프로젝트가 없습니다. 새 프로젝트를 생성해주세요." |
| 토스트 (정보) | 평서문 단정형 | "저장되었습니다.", "초대장이 전송되었습니다." |
| 토스트 (오류) | `~해주세요` | "네트워크 연결을 확인해주세요." |

## 4. 라이팅 실행 원칙 4가지

### 4-1. 사용자 중심 행동 유도

> 정보 제공보다 행동 유도에 초점. 사용자가 해야 할 일을 즉시 파악하고 행동하게 만든다.

**체크리스트**
- [ ] 버튼·최종 문구가 단순 `보기` 대신 구체적 행동(`결제하기`, `재시도`, `시작하기`, `초대 전송`, `업그레이드`)을 담고 있는가?
- [ ] 사용자 목적이 문장 시작에 위치하는가? (예: `프로젝트를 시작하려면, [버튼]을 누르세요`)
- [ ] 문구가 시스템 상태 설명이 아닌 사용자 행동을 명확히 포함하는가?
- [ ] 사용자가 할 수 없는 것 대신 할 수 있는 것을 강조했는가?

**Before / After**

| Before (시스템 관점) | After (사용자 행동 관점) |
|---|---|
| "데이터 조회" | "조회" 또는 "데이터 조회하기" |
| "초대 메일 발송 기능" | "초대 메일 전송" |
| "현재 비밀번호 변경 불가" | "임시 비밀번호로 로그인 후 변경해주세요" |
| "정보를 확인할 수 없습니다" | "다시 로그인해주세요" |
| "처리가 가능합니다" | "처리하기" |

### 4-2. 직관성 및 간결성 확보

> 핵심 메시지에 집중. 불필요한 정보 제거, 쉽고 통일된 언어 사용.

**체크리스트**
- [ ] 불필요한 설명·의미 없는 단어가 제거되었는가?
- [ ] 기술 전문 용어/약어 대신 사용자가 쉽게 이해하는 용어로 대체되었는가?
- [ ] 불가피한 전문 용어 사용 시, 툴팁·인포팁으로 의미·해설을 즉시 제공했는가?
- [ ] 서비스 전반에서 통일된 단어를 사용하고 있는가?

**전문 용어 처리 — 권장 패턴**

약어·기술 용어는 풀어서 본문에 박지 말고 (i) 아이콘 + 호버 Tooltip으로 처리.

예: "응답 시간 1.2s (i)" — 호버 시 Tooltip으로 "응답 시간(Response Time): 사용자가 요청을 보낸 후 서버로부터 첫 응답을 받기까지 걸린 시간"

**용어 통일 — 프로젝트별 관리 권고**

서비스마다 도메인이 다양하므로 본 스킬은 강제 용어 매트릭스를 제공하지 않는다. 대신 다음 원칙을 적용:

1. **첫 등장 시 결정**: 새 개념이 처음 UI에 등장할 때 단어 1개로 확정
2. **프로젝트 용어 사전 누적**: `docs/glossary.md` 등에 결정된 용어 누적
3. **서비스 전반 검색**: 새 화면 작성 전 기존 용어 검색 후 재사용 우선

**자주 혼동되는 일반 용어 예시**

| 같은 개념 | 통일 권고 | 혼용 금지 |
|---|---|---|
| 사용자가 자신을 식별 | "로그인" | "로그인 / 사인인 / 접속" 혼용 ✗ |
| 사용자가 시스템을 떠남 | "로그아웃" | "로그아웃 / 사인아웃 / 종료" 혼용 ✗ |
| 작업 종결 | "취소" | "취소 / 철회 / 중단" 혼용 ✗ |
| 일시적 비활성 | "비활성화" | "OFF / 꺼짐 / 해제" 혼용 ✗ |
| 완전 제거 | "삭제" | "삭제 / 제거 / 지움" 혼용 ✗ |

### 4-3. 진단 및 위험 고지

#### 4-3a. 단정적 사실 제시 (현재 상태)

> 추측·가정 없이 시스템이 확인한 사실만 현재 시제로 단정. 신뢰성 확보.

**규칙**
- ❌ 추측 표현: `~수 있습니다`, `~것 같습니다`, `~것으로 보입니다`, `~가능성이 있습니다`
- ✅ 단정 표현: `~되었습니다`, `~확인되었습니다`, `~감지되었습니다`
- ❌ 주관적 형용사: `꽤`, `심하게`, `약간`, `많이`
- ✅ 측정값: 수치(%, 시간, 임계치 대비) + 구체적 식별자

**좋은 예 — 일반 SaaS**

```
"API 응답 시간이 5.2초로 측정되었습니다. 평소 평균 200ms 대비 26배 증가."

→ 사실(응답 시간) + 수치(5.2초) + 비교 기준(평소 평균) 모두 단정.
   추측 없음, 주관적 형용사 없음.
```

```
"결제 거절 3회 연속 발생. 첫 거절 5분 전, 마지막 거절 30초 전."

→ 카운트 + 시간 상대 표현. 객관적 사실만.
```

#### 4-3b. 잠재적 영향 명시 (미래)

> 현재 상태가 사용자에게 미치는 미래 결과를 책임감 있게 경고.

**규칙**
- 경고 상황: 방치 시 예상되는 잠재적 위험을 `~할 수 있습니다` / `~됩니다` 시제로 경고
- 설정/미작동 상황: 사용자가 잃게 되는 핵심 가치를 명시하여 설정 유도

**현재형 vs 미래형 시제 구분 — 가장 헷갈리는 부분**

| 시점 | 시제 | 예시 |
|---|---|---|
| **현재 상태** | 단정 (`~되었습니다`) | "결제가 거절되었습니다." |
| **미래 영향** | `~할 수 있습니다` | "방치 시 구독이 중단될 수 있습니다." |
| **잘못된 혼용** | 현재 상태를 `~수 있습니다`로 표현 | ❌ "결제가 거절될 수 있습니다." (이미 거절됐는데?) |

핵심: **현재형에 추측을 쓰면 신뢰가 떨어지고, 미래형에 단정을 쓰면 책임 회피가 어려워진다.** 시제와 어조를 짝지어야 한다.

### 4-4. 불확실성 제어

> 사용자의 불안을 유발하는 요소를 제거. 시스템 사용 과정을 예측 가능하게.

**체크리스트**
- [ ] 버튼 누름·다음 단계 진행 시, 다음 화면에서 발생할 결과를 미리 알려 불안감을 제거했는가?
- [ ] 유머·은어·이모티콘·`놀라운`·`대박` 같은 감정적·과장된 표현이 정보의 신뢰도를 저해하지 않았는가?

**예측 가능성을 높이는 카피 패턴 — 일반 SaaS 예시**

| 패턴 | 좋은 예 |
|---|---|
| 결과 사전 안내 | "프로젝트를 삭제하면 연결된 모든 데이터가 함께 제거됩니다. 삭제하시겠습니까?" |
| 소요 시간 안내 | "데이터 백업에는 약 5분이 소요됩니다." |
| 영향 범위 명시 | "이 변경은 팀의 모든 멤버에게 적용됩니다." |
| 되돌리기 가능 여부 | "삭제된 데이터는 복구할 수 없습니다." |
| 다음 단계 안내 | "결제 완료 시 영수증이 이메일로 발송됩니다." |

## 5. 화면 유형별 카피 작성 가이드

### 5-1. 폼 페이지 / 등록 팝업

| 위치 | 어조 | 예시 |
|---|---|---|
| 페이지/팝업 타이틀 | 명사형 | "계정 정보 수정", "팀원 초대" |
| 섹션 헤더 | 명사형 | "기본 정보", "결제 정보", "알림 설정 (선택)" |
| 라벨 | 명사형 + 필수는 `*` | "이메일 *", "회사명", "전화번호" |
| Placeholder | `~해주세요` | "이메일 주소를 입력해 주세요." |
| Helper text | 명사형/평서문 | "영문·숫자·특수문자 포함 8자 이상" |
| Error message | `~해주세요` | "올바른 이메일 형식으로 작성해주세요." |
| 등록/저장 CTA | 명사형 | "등록", "저장", "초대 전송" |
| 취소 버튼 | 명사형 | "취소" |

### 5-2. 알림 배너 / 상황 요약

긴급도에 따라 3요소 조합 결정:

| 상황 | 권장 조합 | 카피 패턴 |
|---|---|---|
| 즉시 대응 (긴급) | A + C | "[항목] [사실] 확인(A). 즉시 [행동]이 필요합니다(C)." |
| 사전 경고 (주의) | A + B | "[항목] [수치]가 [임계치] 대비 [비율] 초과(A). 방치 시 [위험]이 발생할 수 있습니다(B)." |
| 분석 결과 / 패턴 | A 단정형 + 객관 수치 | "[항목]이 [수치] 수준에서 [시간]째 유지 중, 급변 없음." |

### 5-3. 빈 상태 (Empty State)

| 위치 | 카피 |
|---|---|
| 제목 | 명사형, 사실 단정. "프로젝트가 없습니다", "검색 결과가 없습니다" |
| 설명 | `~해주세요`. "새 프로젝트를 생성해주세요", "다른 검색어로 시도해주세요" |
| CTA (선택) | 명사형. "생성", "초대하기" |

### 5-4. 확인 모달

| 위치 | 카피 패턴 |
|---|---|
| 제목 | 행동 명사형. "프로젝트 삭제", "구독 취소" |
| 본문 | 결과 + 되돌리기 가능 여부 명시. "삭제된 프로젝트는 복구할 수 없습니다. 정말 삭제하시겠습니까?" |
| 확인 버튼 | 행동 명사형 + 심각도 컬러. "삭제" (danger), "취소" |
| 취소 버튼 | "취소" |

### 5-5. 토스트 / 스낵바

| 상황 | 패턴 |
|---|---|
| 성공 (positive) | 단정 평서문. "저장되었습니다", "초대장이 전송되었습니다" |
| 오류 (negative) | 원인 + 해결 가이드. "네트워크 연결을 확인해주세요" |
| 정보 (basic) | 단정 평서문. "3개의 새 알림이 있습니다" |
| 액션 필요 (snackbar) | 결과 + 되돌리기. "메시지가 삭제되었습니다. [실행 취소]" |

## 6. 텍스트 작성 자가 검증 5단계

화면 코드 작성 후 모든 텍스트에 대해 아래 5단계를 점검한다.

### Step 1. 어조 분리 점검
- [ ] 시스템 기능(버튼·메뉴)이 모두 명사형인가?
- [ ] 상태/조치 알림이 `~이 필요합니다` 어조인가?
- [ ] 사용자 안내가 `~해주세요` 어조인가?

### Step 2. 메시지 3요소 점검 (알림·경고)
- [ ] 알림 문구가 A/B/C 중 최소 2개를 포함하는가?
- [ ] A를 `~수 있습니다`로 추측 표현하지 않았는가? (현재형 단정만)
- [ ] B를 `~되었습니다`로 단정하지 않았는가? (미래형만)

### Step 3. 단정성 점검
- [ ] 현재 상태 표현에 추측 표현(`~것 같다`, `~수 있다`, `~보인다`)이 없는가?
- [ ] 주관적 형용사(`꽤`, `심하게`, `약간`, `많이`)가 없는가?
- [ ] 수치·임계치·구체적 식별자로 대체되었는가?

### Step 4. 행동 유도 점검
- [ ] 버튼이 `보기` 같은 추상어 대신 구체적 행동을 담고 있는가?
- [ ] 사용자가 할 수 있는 것을 강조했는가? (할 수 없는 것 강조 ✗)
- [ ] 결과 사전 안내가 있는가? (다음 단계, 소요 시간, 영향 범위, 되돌리기 가능 여부)

### Step 5. 신뢰감 점검
- [ ] 이모지·이모티콘이 없는가?
- [ ] 유머·은어·과장 표현(`놀라운`, `대박`, `최고의`, `혁신적인`)이 없는가?
- [ ] 오류 메시지에 해결 가이드가 함께 있는가?
- [ ] 같은 개념이 같은 단어로 통일되어 있는가?

## 7. 일반 SaaS에서 자주 쓰이는 정답 카피 패턴

일반 SaaS 화면에서 그대로 차용 가능한 카피 패턴.

### 수치 + 비교 표현
- "**$24.99** /월" (가격 + 주기 병기)
- "사용량 **82%** 초과" (임계 대비 비율)
- "**5.2%** ▲" (변화 수치 + 방향 화살표)
- "마지막 활동 **3시간 전**" (시간 상대 표현)
- "총 **1,124 건**" (수치 강조)

### 상태 + 시각 단서 조합
- "활성" + positive color dot
- "대기 중" + warning color
- "오류" + danger color
- "처리 중" + info color spinner

### 메타 정보 표기
- "팀원 **12명**" (카운트 강조)
- "프로젝트 · 멤버 12명" (구분자: 가운데 점)
- "최근 30일 · 03.01 ~ 03.30" (기간 표기)
- "2026-05-27" (날짜 ISO 형식 권장)

### CTA 패턴
- "프로젝트 시작" (행동 명사형)
- "새 프로젝트 생성" (수식어 + 행동)
- "팀 멤버 관리" (영역 + 행동)
- "초대장 전송" (대상 + 행동)
- "전체 보기 ▾" (행동 + 토글 아이콘)

### 알림 배너 압축 표현
- "**5월 1일** 결제 예정. 현재 등록된 카드의 **유효기간이 다음 달 만료**됩니다. 정상 결제를 위해 **카드 정보 업데이트가 필요합니다**."
  - 일정(굵게) + 사실(키워드 강조) + 행동 단정 조합
- "다른 기기에서 로그인 시도가 확인되었습니다. 본인이 아닐 경우 즉시 비밀번호 변경이 필요합니다."
  - 사실 단정 + 조건부 행동 단정
