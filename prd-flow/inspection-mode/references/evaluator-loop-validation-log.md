# inspection-mode Evaluator 검증 로그 (일반화 추적)

evaluator-loop.md 표준의 독립 Evaluator가 self-eval이 놓친 갭을 **도메인 불문** 잡는지를 회귀검증으로 측정·추적하는 누적 로그다. 새 케이스마다 아래 "케이스 결과"에 추가한다.

---

## 측정 방법

- **입력**: 고치기 전 desc — git 초기/중간 커밋을 prd-flow 클론본에서 checkout(원본 불변).
- **정답셋**: 그 이후 수정 커밋 메시지 = 사용자가 수동 발견한 갭. 단 제품·도메인 판단(정답 없는 발산형)은 "범위 밖"으로 분리.
- **평가**: 독립 Evaluator(Agent 도구), inspection-mode Phase 4·5·10·10-b 기준. **Phase 11 캘리브레이션은 측정 오염 방지로 차단**(검증 대상의 실제 갭이 예시에 들어 있어 컨닝이 되므로) → 하한(보수적) 측정.
- **지표**: recall(정답 갭 재현율) · precision(짚은 것 중 진짜 갭) · 신규 발견(정답셋 밖의 진짜 갭).

## 종합 평가 — 3건 회귀검증 (2026-06-30)

| 케이스 | 도메인 | 판정 | 계산식 lens | PRD 정합 lens | precision |
|---|---|---|---|---|---|
| A | 성과 리포트 자동 생성 | fail | ❌ L-3 미재현 | 중립 | 높음 |
| B | AI 분석 요약 | fail | ❌ L-3 미재현 | ✅ F-01·F-02 강력 | 높음 |
| C | 리소스 모니터링 | fail | ✅ L-3 정확 재현 | ✅ F-1·F-2·F-3 강력 | 높음 |

**결론**:
1. **3/3 모두 fail + 치명 갭 재현/발견** — 독립 Evaluator가 self-eval이 놓친 갭을 도메인 불문 잡는다. **inspection-mode 내 일반화 입증.**
2. **precision 일관되게 높음**(3건 모두 헛갰 미관찰, 단 사용자 검토 전 잠정) — 실무 적용 가능 수준.
3. **계산식 lens의 정밀한 처방**: "무조건 약함"이 아니라 **PRD 수식 구체성에 의존**. PRD에 수식이 구체적이면 PRD 정합 lens가 잡고(케이스 C), PRD가 추상적이고 desc 자체 충분성이 문제면 약하다(케이스 A·B).

**일반화 한계(정직)**: 3건 모두 동일 스킬(inspection-mode)·동일 평가자 모델·동일 작성자 산출물. inspection-mode 내 도메인 일반화는 입증됐으나, 타 스킬·타 작성자 일반화는 별도 검증 필요. precision은 사용자 검토로 확정 대기.

## 누적 교훈 (evaluator-loop.md / 스킬 로컬 반영 대기)

1. **캘리브레이션 오염 방지** — 캘리브레이션 예시는 검증 대상과 **다른 프로젝트** 사례로 둔다(같은 프로젝트면 컨닝).
2. **명세 충분성 lens에 계산식 검사 명시** — "계산식의 입력·수식·단위 미명시 = 치명"을 못박고, **PRD에 수식이 없어도 desc 자체의 충분성**을 검사한다(PRD 정합만으로는 추상적 PRD를 통과시킴 — 케이스 A·B L-3 미재현의 원인).
3. **PRD 정합 lens 강력 — 앵커 대조 필수화** — FN-·F-·D- 앵커를 PRD와 1:1 대조하면 사람이 커밋으로 안 남긴 충돌·통짜 누락까지 잡힌다(케이스 B F-01·F-02, 케이스 C F-1~F-3).

- **표시 정보 세분 넘버링 누락**: 케이스 A 갭5 / 케이스 B EventRow·2-2·3-1 → Phase 10 #15 맹점 **확정**.
