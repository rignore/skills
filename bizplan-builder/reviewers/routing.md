# 페르소나 라우팅

각 Phase 완료 시 어떤 페르소나를 호출할지 정의한다. 모든 페르소나가 모든 Phase를 보지 않는다.

## 라우팅 표

| Phase | 1차 페르소나 | 2차 페르소나 | 선택적 호출 |
|---|---|---|---|
| **Phase 1** (시장·문제 정의) | GTM Strategy Lead | CEO / Founder | - |
| **Phase 2** (기술·규제) | Staff Engineer / CTO | Legal & Compliance | (AI 포함 시) Staff Engineer 가 AI 환각·MLOps 별도 리뷰 |
| **Phase 3** (비즈니스 모델·단위 경제성) | CFO | B2B Enterprise Sales | (ACV $100K↑ 시) B2B Sales 가 엔터프라이즈 세일즈 사이클 별도 리뷰 |
| **Phase 4** (해자·통합) | Top-tier VC | CEO (종합 검토) | (필요 시) 모든 페르소나 종합 리뷰 라운드 |

## 호출 순서

각 Phase에서 페르소나 호출은 다음 순서로 진행:

1. **1차 페르소나 호출**: 산출물의 핵심 가설을 가장 먼저 공격
2. 사용자가 1차 페르소나 피드백에 응답 → 산출물 1차 수정
3. **2차 페르소나 호출**: 수정된 산출물에 대해 보완적 관점에서 리뷰
4. 사용자가 2차 페르소나 피드백에 응답 → 산출물 2차 수정
5. Kill Switch 체크 → 통과 시 다음 Phase

## 페르소나 호출 시 출력 형식 (모든 페르소나 공통)

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
[페르소나명] 리뷰 — Phase N
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

🟢 강점
- ...
- ...

🟡 보완 제안
- ...
- ...

🔴 차단 이슈 (Kill Switch 발동 시)
- ...

❓ 킬러 질문 (사용자가 추가 답변해야 할 사항)
1. ...
2. ...
3. ...
```

## 사용자 컨펌 패턴

페르소나 리뷰 출력 후 다음 형식으로 사용자에게 묻는다:

```
위 [페르소나명] 의 피드백 중 어떤 항목을 산출물에 반영하시겠습니까?

1. 모두 반영
2. 일부 선택 반영 (번호 입력)
3. 반영하지 않음 (사유 기록)
4. 페르소나에게 반박 (사용자 의견 추가)
```

사용자가 "4. 반박" 을 선택하면, 페르소나는 사용자 반박에 대해 한 번 더 응답할 수 있다 (1라운드 반박만 허용, 무한 루프 방지).

## 종합 검토 라운드 (Phase 4)

Phase 4 완료 직전, 사용자가 요청하면 모든 페르소나가 사업계획서 전체에 대해 종합 리뷰를 수행한다. 출력 형식:

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
종합 검토 라운드 — 7개 페르소나
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

[페르소나 1] CEO / Founder
- 종합 평가: 🟢 통과 / 🟡 조건부 / 🔴 차단
- 핵심 코멘트: ...

[페르소나 2] Top-tier VC
- 종합 평가: ...
- 핵심 코멘트: ...

... (7개 페르소나 모두)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
종합 의견 (다수결)
- 통과: N / 조건부: N / 차단: N
- 가장 많이 지적된 보완 사항 Top 3:
  1. ...
  2. ...
  3. ...
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

## 페르소나 부재 시 처리

특정 Phase에 적합한 페르소나가 정의되지 않은 영역에서 추가 검토가 필요할 경우:

- **재무 관련 추가 검토**: CFO 페르소나 추가 호출
- **법무 관련 추가 검토**: Legal & Compliance 페르소나 추가 호출
- **기술 관련 추가 검토**: Staff Engineer 페르소나 추가 호출

사용자가 명시적으로 "[페르소나명] 관점에서 리뷰" 라고 요청하면 해당 Phase 외에서도 호출 가능하다.
