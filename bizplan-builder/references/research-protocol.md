# 외부 리서치 프로토콜

사업계획서의 시장·경쟁·벤치마크 수치는 Claude의 내부 지식만으로 채우지 않는다. 이 문서는 웹 검색을 언제·얼마나·어떻게 수행하고, 결과를 어떻게 산출물과 decision-log에 반영하는지 정의한다. 목적은 두 가지다: ① 모든 핵심 수치에 출처를 강제해 투자자 검토 방어력을 확보하고, ② 리서치 폭주로 인한 컨텍스트·시간 낭비를 상한으로 차단한다.

---

## 1. Phase별 적용 지점

| Phase | 적용 지점 | 강도 | 검색 상한 |
|---|---|---|---|
| 1 | 문제 실재성 · 경쟁/대안 솔루션 현황 | **필수** | 1~2회 |
| 1 | TAM/SAM 교차 검증 (하향식 시장 수치 대조) | **필수** | 1~2회 |
| 2 | 규제 최신성 (EU AI Act 시행 단계, 국내 도메인 규제·인증 요건) | **필수** (AI 에이전트·규제 산업 해당 시) | 1회 |
| 3 | 이탈률·CAC·가격 업계 벤치마크 | **필수** | 1~2회 |
| 3 | `unit-economics-benchmarks.md` 정적 기준의 최신성 확인 | 권장 | 1회 |
| 4 | 경쟁사 최신 동향 (포지셔닝 매트릭스 근거) | **필수** | 1~2회 |

- "필수" 지점은 스킵하지 않는다. 해당 Phase 산출물 작성 **전**에 수행한다.
- 사용자가 이미 충분한 1차 데이터(자체 조사·고객 인터뷰·계약 데이터)를 제공한 지점은 리서치를 생략할 수 있다. 생략 사실과 근거를 decision-log에 1줄 기록한다.

## 2. 공통 규칙

1. **검색량 상한**: 적용 지점당 표의 상한을 지킨다. 쿼리는 핵심 1~2개로 압축한다. 상한 내에서 답이 안 나오면 "확인 불가"로 처리하고 해당 값을 SD로 기록한다 — 상한을 넘겨 검색하지 않는다.
2. **결과 활용**: 수치·패턴·업계 관행만 추출한다. 검색 원문 전체를 산출물이나 캐시에 적재하지 않는다.
3. **사용자 제공 지식 최우선**: 사용자가 직접 제공한 데이터·도메인 지식이 리서치와 충돌하면 사용자 지식을 따른다. 충돌 사실만 decision-log에 1줄 남긴다.
4. **출처·조회일 병기**: 인용한 수치·주장은 `[출처: 도메인, 조회일]` 형태로 산출물에 기록한다. BP는 IR 자료로 전환될 수 있으므로 조회일이 필수다.
5. **SD 회계 연계**: 리서치로 채운 값은 출처가 decision-log에 기록된 경우에 한해 Silent Default 카운트에서 제외한다 (`references/silent-defaults.md` §1).
6. **집계 가시화**: Phase 통과 시점에 해당 Phase의 리서치 수행 건수·출처 목록을 사용자에게 제시한다. Phase 4 통합 시 전체 리서치 집계를 decision-log 하단에 정리한다.
7. **단정 금지**: 리서치 값은 참고 근거이지 확정 사실이 아니다. 특히 시장 규모는 출처마다 편차가 크므로, 복수 출처가 있으면 단일 값이 아니라 **범위**로 제시한다 (예: "국내 산업 안전 SW 시장 800억~1,200억원 [출처 2건]").

## 3. BP 특화 규칙

- **하향식 → 상향식 교차 강제**: 리서치로 확보한 하향식 시장 수치(시장조사 보고서류)는 그 자체로 TAM/SAM 근거가 되지 못한다. 반드시 상향식 산정(대상 기업 수 × 단가)과 교차하고, 두 값의 괴리가 2배 이상이면 괴리 원인을 명시한다. `references/cognitive-biases.md`의 하향식 의존 반려 규칙과 연동된다.
- **정적 벤치마크 vs 최신 값**: `unit-economics-benchmarks.md`의 기준값과 리서치로 확인한 최신 업계 값이 다르면 **최신 값을 우선**하고, 차이와 출처를 decision-log에 기록한다. 벤치마크 파일 자체는 수정하지 않는다.
- **경쟁사 수치 출처 위계**: 공식 출처(IR·공시·공식 블로그·프라이싱 페이지) > 업계 리포트 > 언론 보도 > 커뮤니티. 하위 출처 단독 인용 시 "단일 출처·미검증" 표시를 남긴다.
- **IR 목적 강화 규칙**: context.json의 목적이 IR이면 One-Page Summary에 들어가는 시장·경쟁 수치는 출처 2개 이상 확보 또는 범위 표기를 요구한다. 미충족 시 해당 수치에 `⚠️ 단일 출처` 표시를 유지한 채 진행한다.

## 4. 리서치 캐시

재사용 가치가 있는 결과(시장 수치·벤치마크·규제 요건·경쟁 패턴)는 작업 디렉토리의 `research/{topic}.md`에 저장하고, 이후 Phase·페르소나 리뷰가 참조한다.

### 캐시 파일 템플릿

```markdown
# {토픽}

- 조사일: YYYY-MM-DD
- 사용 쿼리: "..."
- 출처 수: N

## 수치
- {수치} [출처: 도메인, 조회일] (⚠️ 단일 출처 — 해당 시)

## 패턴·관행
- ...

## 규제·요건 (해당 시)
- ...
```

### 캐시 운영 규칙

- 같은 토픽 캐시가 이미 있으면 재검색하지 않고 재사용한다.
- 조사일이 6개월 이상 지났거나 빠르게 변하는 항목(요금·규제)이면 갱신을 제안한다.
- 캐시 파일 하나는 200줄 이내로 압축한다. 동시 참조는 현재 Phase와 관련된 캐시로 한정한다.

## 5. 페르소나 리뷰 연계

페르소나 리뷰 호출 시 참조 가능한 캐시 목록을 프롬프트에 명시한다.

```
[CFO 호출]
참조 가능한 리서치 캐시:
- research/saas-churn-benchmark.md
- research/kr-industrial-safety-market.md

위 근거와 산출물 간 충돌·누락을 함께 검토해 주세요.
```
