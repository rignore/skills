# 인지 편향 및 논리적 비약 탐지 프레임워크

McKinsey, BCG 등 글로벌 전략 컨설팅 펌의 의사결정 프로세스에서 차용한 편향 차단 알고리즘. 모든 Phase에서 자동 적용된다.

## 1. MECE (Mutually Exclusive, Collectively Exhaustive) 테스트

### 원칙

문제 분해 시 각 범주가 **상호 배타적** 이면서도 **전체를 포괄** 해야 한다.

### 적용 영역

- 시장 세분화 (Phase 1 — TAM/SAM/SOM)
- 타겟 고객 분류 (Phase 1 — ICP)
- 수익 모델 구분 (Phase 3 — 비즈니스 모델)
- 경쟁사 분류 (Phase 4 — 경쟁 포지셔닝)

### 위배 패턴 (자동 감지)

**Mutually Exclusive 위배 (교집합 발생)**:
```
❌ 타겟 시장: ① 화학 산업 ② 대기업 ③ 한국 시장
   (대기업이면서 한국 화학사인 경우 3개 범주에 모두 속함)
```

**Collectively Exhaustive 위배 (누락 발생)**:
```
❌ 수익 모델: 구독 / 라이선스
   (Usage-based, Freemium, 마켓플레이스 수익 등 누락)
```

### 위배 시 결과

- 마케팅 예산 중복 산정
- 시장 규모 과대 계상 또는 누락 (Texas Sharpshooter Fallacy)
- 경쟁 분석의 사각지대 발생

### 자동 수정 요구

위배 감지 시 다음을 사용자에게 요구:
1. 분류 기준을 단일 차원으로 통일 (예: "산업" / "규모" / "지역" 중 하나)
2. 누락된 카테고리 보강
3. "기타" 카테고리 사용 시 그 안의 비중·구성 명시

## 2. 가설 연역적 문제 해결 (Hypothesis-led Problem Solving)

### 원칙

McKinsey 7단계 문제 해결 프로세스 및 Minto Pyramid 원칙에 따라:

```
Answer (결론) ← 가장 먼저
  ↓
Why (근거 1, 근거 2, 근거 3)
  ↓
Why (각 근거의 데이터·사실)
```

### 위배 패턴 (자동 감지)

**장황한 배경 설명만 나열** (결론 부재):
```
❌ "최근 산업 안전에 대한 관심이 증가하고 있고, AI 기술도 발달하고 있으며,
    정부 규제도 강화되고 있어서, 우리는 이 기회를 잡고자 한다..."
```

**검증 불가능한 서술**:
```
❌ "AI 도입으로 효율이 증대된다"
❌ "혁신적인 솔루션으로 시장을 선도한다"
❌ "고객들이 큰 가치를 얻을 것이다"
```

### 자동 수정 요구

- 결론 우선 (Answer First) 으로 재배치 강제
- 모든 주장을 **반증 가능한 가설** 형태로 수정 요구

수정 예시:
```
❌ "AI 도입으로 효율이 증대된다"
✅ "고객사의 안전 사고 보고서 작성 프로세스를 평균 2시간 → 10분으로 단축하여
    50인 사업장당 연간 5,000만원 인건비를 절감한다"
```

가설 검증 형식:
- **만약** [조건] 이라면, **그 결과** [측정 가능한 결과] 가 발생할 것이다
- **반증 조건**: [어떤 데이터를 보면 이 가설이 틀렸다고 판단할 것인가]

## 3. 자동화 편향 (Automation Bias) 차단

### 원칙

의사결정자가 AI 의 산출물·외부 보고서·시장조사 데이터를 맹신하는 오류를 방지해야 한다.

### 위배 패턴 (자동 감지)

- "Gartner 보고서에 따르면..." (출처 검증 없이 단순 인용)
- "ChatGPT 가 분석한 결과..." (AI 산출물 무비판 수용)
- "시장조사 업체 X 의 추정에 따르면..." (방법론 검증 없이 인용)

### 자동 수정 요구

외부 출처 인용 시 다음을 강제:
1. **출처 명시** (보고서명, 발행일, 저자/기관)
2. **방법론 검증** (표본 크기, 조사 방법, 한계점)
3. **교차 검증** (최소 2개 이상 독립 출처)
4. **자체 검증 데이터 보강** (1차 데이터 우선)

## 4. 확증 편향 (Confirmation Bias) 차단

### 원칙

자신의 가설을 지지하는 데이터만 선택적으로 취합 (Cherry-picking) 하는 오류를 방지해야 한다.

### 위배 패턴 (자동 감지)

- 통계적 유의성 결여된 소수 사례 (3-5개 인터뷰) 의 일반화
- 성공한 경쟁사 사례만 인용, 실패한 사례 무시
- 자사에 유리한 시나리오만 작성, 보수·낙관 시나리오 부재
- "100% 만족", "모든 고객이..." 같은 절대화 표현

### 자동 수정 요구

1. **표본 크기 명시**: "5명 인터뷰" → 표본 한계 명시 + 추가 검증 계획
2. **반대 사례 강제 포함**: 실패한 경쟁사·실패한 가설의 분석
3. **3개 시나리오 강제** (보수·기본·낙관)
4. **반박 가능성 인정**: "이 가설이 틀릴 수 있는 경우는..." 명시

## 5. 레드팀 (Red Teaming) 강제

### 원칙

자신의 비즈니스를 공격하는 입장에서 가장 가혹한 시나리오를 가정한다.

### 강제 시나리오 (Phase 4 필수)

**시나리오 1 — 경쟁사 파괴적 혁신**:
- AWS, Microsoft, 구글 같은 Big Tech 가 동일 기능을 무료 또는 1/10 가격으로 출시
- 우리의 18개월 내 대응 전략은?

**시나리오 2 — 주요 고객 이탈**:
- ARR 30% 이상 비중인 Top-3 고객 중 1개 이탈
- 12개월 내 ARR 회복 가능한가? 어떻게?

**시나리오 3 — 외부 충격**:
- 규제 강화 (예: EU AI Act 강화, 추가 인증 요구)
- 거시 경제 침체 (고객사 IT 예산 30% 삭감)
- Foundation Model 가격 5배 인상
- 핵심 데이터 라이선스 갱신 거부

### 통과 조건

각 시나리오에 대해:
1. 영향 정량화 (ARR 손실, Burn 증가, 런웨이 단축)
2. 대응 전략 (구체적 액션 + 책임자 + 기한)
3. 회복 KPI (언제 어느 수준으로 회복되는가)

## 6. 텍사스 명사수 오류 (Texas Sharpshooter Fallacy)

### 원칙

데이터를 먼저 모은 뒤 의미 있는 패턴을 사후적으로 그려내는 오류 방지.

### 위배 패턴

- "우리 PoC 5개사 중 3개가 화학 산업이었으니 화학이 우리 시장이다" (사후적 패턴화)
- "Top 10 SaaS 의 공통점은 X 다, 그러므로 우리도 X 를 해야 한다" (생존자 편향)

### 자동 수정 요구

- 가설을 **먼저** 세우고, 그 가설을 검증할 데이터를 **나중에** 수집
- 사후 패턴 발견 시 별도 가설로 재정립 후 신규 데이터로 검증

## 7. 인지 편향 종합 체크리스트 (Phase 별 자동 적용)

| Phase | MECE | Answer First | 자동화 편향 | 확증 편향 | 레드팀 | 사후 패턴화 |
|---|---|---|---|---|---|---|
| Phase 1 | ✅ 시장·고객 분류 | ✅ ICP 결론 우선 | ✅ TAM 출처 검증 | ✅ 인터뷰 표본 검증 | - | ✅ 가설 → 데이터 순서 |
| Phase 2 | ✅ 규제 분류 | ✅ 아키텍처 결론 | ✅ 벤치마크 검증 | ✅ 보안 가정 검증 | - | - |
| Phase 3 | ✅ 수익 모델 | ✅ 단위 경제성 결론 | - | ✅ 3개 시나리오 강제 | ✅ 보수 스트레스 테스트 | ✅ 이탈률 가정 검증 |
| Phase 4 | ✅ 경쟁사 분류 | ✅ 5기둥 압축 | - | ✅ 해자 반박 검증 | ✅ 3개 시나리오 강제 | - |
