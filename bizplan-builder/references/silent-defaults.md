# Silent Default 추적

사업계획서의 수치·가정 중 사용자가 명시하지 않았고 리서치 출처도 없는 상태로 Claude가 채워 넣은 값을 **Silent Default(SD)**로 정의하고 추적한다. BP에서 SD는 치명적이다 — TAM 파라미터, 이탈률, 전환율 같은 암묵 가정 하나가 재무 프로젝션 전체를 오염시키고, 투자자 검토에서 가장 먼저 공격받는 지점이 된다.

---

## 1. 값 출처 3분류

산출물에 들어가는 모든 수치·가정은 아래 셋 중 하나로 분류한다.

| 분류 | 정의 | 처리 |
|---|---|---|
| **사용자 명시 값** | 사용자가 대화에서 직접 제공 | 그대로 사용. SoT |
| **리서치 기반 값** | 외부 리서치로 확보, `[출처: 도메인, 조회일]` 병기 | SD 카운트 제외. decision-log에 출처 기록 (`references/research-protocol.md`) |
| **Silent Default** | 위 둘 다 아님 — Claude의 추정 | 아래 기록·확인 절차 적용 |

출처 병기 없이 채운 값은 리서치를 참고했더라도 SD로 집계한다. 출처 기록이 리서치 기반 값의 성립 조건이다.

## 2. Phase별 고위험 SD 카탈로그

아래 항목은 SD 발생 빈도와 파급이 특히 큰 지점이다. 이 항목에서 추정이 발생하면 반드시 기록한다.

| Phase | 고위험 SD 항목 |
|---|---|
| 1 | TAM/SAM 산정 파라미터(대상 기업 수·평균 단가), SOM 점유율 가정, 문제로 인한 재무 손실 수치, 다크 퍼널 기여 비율 |
| 2 | 인프라 비용 단가, 인증 획득 기간·예산, 최대 고객 규모 부하 가정 |
| 3 | 월 이탈률, ARPA, Freemium 전환율, CAC 구성 항목 단가(인건비·커미션·도구), Tier별 가격, 성장률, 세일즈 쿼터 |
| 4 | 경쟁사 전환 비용(Switching Cost) 수치, 해자 형성 소요 기간, 경쟁사 대응 속도 가정 |

## 3. 기록 형식 (decision-log.md)

SD 발생 즉시 작업 디렉토리의 `decision-log.md`에 아래 형식으로 기록한다.

```markdown
### SD-{n} · {값 요약, 예: 월 이탈률 2%}
- Phase / 위치: Phase 3 / 단위 경제성 표 · LTV 산정
- 값: 월 이탈률 2%
- 추정 근거: 중소기업 대상 SaaS 업계 통상 범위(1~3%) 중간값
- 검토된 대안: 1% / 2% / 3%
- 영향 범위: LTV, LTV:CAC, 3개년 프로젝션의 누적 고객 수 전체
- 상태: 미확인
```

상태 값: `미확인` / `사용자 확정` / `수정됨` / `가정 유지 (사용자 승인)`

## 4. 임계값·처리 규칙

| 규칙 | 내용 |
|---|---|
| **누적 임계 (기본 3)** | 한 Phase 작성 중 미확인 SD가 3개 누적되면 **작성을 중단**하고 즉시 일괄 확인을 요청한다. 흔들리는 가정 위에 가정을 더 쌓지 않는다. 임계값은 context.json `silent_default_threshold`로 조정 가능 |
| **핵심 전제 즉시 확인** | LTV·CAC·TAM 산정에 직결되는 SD는 누적 개수와 무관하게 발생 즉시 확인을 요청한다 |
| **Kill Switch 선행 조건** | 미확인 SD가 1개라도 남아 있으면 Kill Switch 검증 루프(`references/evaluator-loop.md`)에 진입하지 않는다 |
| **Phase 4 통합 노출** | 상태가 `가정 유지 (사용자 승인)`인 SD는 One-Page Summary의 리스크 섹션에 "검증되지 않은 핵심 가정"으로 노출한다. IR 목적일 때 특히 — 투자자가 발견하기 전에 스스로 명시하는 편이 방어력이 높다 |

## 5. 일괄 확인 프롬프트 형식

```markdown
⚠️ 확인 필요한 가정 {n}건

| ID | 값 | 추정 근거 | 이 값이 틀리면 |
|---|---|---|---|
| SD-1 | 월 이탈률 2% | 업계 통상 범위 중간값 | LTV·프로젝션 전체 재산정 |
| SD-2 | ... | ... | ... |

각 항목에 대해: ① 그대로 확정 ② 값 수정 (수정값 제시) ③ 가정 유지하되 리스크로 기록
```

사용자가 "일단 가정대로 진행"을 선택하면 차단하지 않는다. 상태를 `가정 유지 (사용자 승인)`으로 기록하고 진행하되, 규칙 4의 Phase 4 노출 대상이 된다.

## 6. 페르소나 리뷰 연계

페르소나 리뷰 호출 시 해당 Phase의 SD 목록(상태 포함)을 프롬프트에 명시한다. 특히 CFO·Top-tier VC 페르소나는 `가정 유지` 상태의 SD를 킬러 질문의 우선 대상으로 삼는다.
