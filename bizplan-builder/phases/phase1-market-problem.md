# Phase 1 - 시장 적합성 및 문제 정의 (Market & Problem Discovery)

## 목적

해결할 가치가 있는 문제인지, 시장 규모가 충분한지, 타겟 고객이 명확한지 검증한다. 이 단계의 가설 오류는 이후 모든 Phase를 오염시키므로 가장 엄격하게 검증한다.

## 관여 페르소나

- **CEO / Founder** (`reviewers/ceo-founder.md`)
- **GTM Strategy Lead** (`reviewers/gtm-lead.md`)

## 핵심 질문 (사용자에게 단계적으로 제시)

### 1) 문제 정의

- 해결하려는 문제는 정확히 무엇인가?
- 그 문제는 누구에게 발생하는가? (역할·산업·규모)
- 문제 발생 빈도 (일/주/월 단위)와 강도 (사소한 불편 / 업무 중단 / 매출 손실 / 규제 위반)는?
- 현재 그 문제로 인한 재무적 손실 (시간·비용·기회비용) 은 얼마인가?
- 현재 고객은 이 문제를 어떻게 해결하고 있는가? (기존 솔루션, 수기 처리, 무대응)

❌ 반려: "기존 시스템이 비효율적이다", "고객들이 불편을 겪고 있다"
✅ 통과: "월 50건 이상의 안전 사고 보고서 작성에 건당 평균 2시간 소요, A 공장 기준 연간 1,200시간 (약 5,000만원) 인건비 손실"

### 2) 시장 규모 (TAM / SAM / SOM)

- TAM (Total Addressable Market): 전체 시장 규모
- SAM (Serviceable Addressable Market): 사업 모델·지역으로 도달 가능한 시장
- SOM (Serviceable Obtainable Market): 3~5년 내 실제 확보 가능 시장

**필수**: 상향식(Bottom-up) 산정 근거를 요구한다.

❌ 반려: "글로벌 산업 안전 시장 100조원 (시장조사 보고서)"
✅ 통과: "한국 50인 이상 화학·중공업 사업장 1,200개 × 평균 연 라이선스 6,000만원 = SAM 720억원, 3년 내 5% 점유 시 SOM 36억원"

### 3) 이상적 고객 프로필 (ICP)

배제 테스트 (Exclusion Test) 를 적용한다. 다음 항목을 모두 정의:

- 산업 (NAICS / KSIC 코드 단위)
- 기업 규모 (직원 수, 매출액 범위)
- 지역
- 기술 성숙도 (디지털 전환 단계)
- 구매 결정 구조 (단일 결정자 / 다중 이해관계자)
- ARR 기여 가능 범위 ($K 단위)
- **배제 조건**: 어떤 고객은 절대 타겟이 아닌가? (예: 직원 50인 미만, 클라우드 미도입, 보안 인증 없는 산업)

❌ 반려: "제조업 전반"
✅ 통과: "한국 화학·정유·조선 산업, 연 매출 1,000억원~1조원, 직원 200~2,000명, ISO 45001 보유, OT 시스템(SCADA/DCS) 운용 중. 배제: 식품·섬유·연 매출 500억 미만"

### 4) 다중 페르소나 가치 제안

B2B는 사용자 ≠ 구매자. 최소 3개 페르소나의 상충하는 니즈를 모두 충족하는 가치 제안을 정리:

| 페르소나 | 핵심 관심사 | 우리의 가치 제안 (정량) |
|---|---|---|
| 임원 (의사결정자) | ROI, 리스크 감소 | 예: "안전 사고 30% 감소로 연 PL 2억원 절감" |
| 관리자 (운영자) | 통제력, 가시성 | 예: "실시간 대시보드로 50개 현장 통합 모니터링" |
| 실무자 (사용자) | 사용성, 업무 부담 | 예: "보고서 작성 시간 2시간 → 10분" |

❌ 반려: "AI 기반 분석으로 빠르고 편리한 안전 관리"
✅ 통과: 각 페르소나별 KPI 직결 성과 명시

### 5) 다크 퍼널 정량화

기존 어트리뷰션 도구로 추적 불가능한 다크 퍼널 (커뮤니티, 입소문, Slack 그룹, 컨퍼런스 발표) 을 어떻게 파이프라인에 편입시킬 것인가?

- 어떤 다크 퍼널 채널을 활용할 것인가?
- 정량 측정 방법 (예: 첫 미팅 시 "어디서 우리를 알게 되셨나요?" 표준 질문, 자체 호스팅 콘텐츠 다운로드 추적)
- 다크 퍼널 기여 비율 가정 (예: 신규 파이프라인의 30%)

## 외부 리서치 (필수)

산출물 작성 **전**에 `references/research-protocol.md`에 따라 다음 두 지점을 수행한다. 스킵하지 않는다.

1. **문제 실재성·경쟁 검증** (검색 1~2회): 정의한 문제가 실제로 업계에서 보고되는지, 경쟁·대안 솔루션이 이 문제를 어떻게 다루는지 확인. "경쟁 부재" 주장이 나오면 이 리서치로 반드시 교차한다 — 경쟁 부재는 시장 부재의 증거일 수 있다.
2. **TAM/SAM 교차 검증** (검색 1~2회): 하향식 시장 수치(시장조사 보고서류)를 확보해 상향식 산정과 대조. 괴리가 2배 이상이면 원인을 명시. 복수 출처가 있으면 범위로 제시.

공통 규칙: 모든 인용 수치에 `[출처: 도메인, 조회일]` 병기, 재사용 가치 있는 결과는 `research/` 캐시 저장, 사용자가 제공한 1차 데이터(자체 조사·고객 인터뷰)가 있으면 그것이 최우선이며 해당 지점 리서치는 생략 가능 (생략 사실을 decision-log에 1줄 기록).

리서치로도 확인 불가한 수치(다크 퍼널 기여 비율, SOM 점유율 가정 등)를 추정으로 채우면 `references/silent-defaults.md`에 따라 SD로 즉시 기록한다. TAM/SAM 산정 파라미터의 SD는 핵심 전제이므로 발생 즉시 사용자 확인을 요청한다.

## 산출물

다음 4개 산출물을 로컬 `phase1/` 파일로 작성한다 (01-problem.md / 02-market-sizing.md / 03-icp.md / 04-value-matrix.md).

1. **문제 정의서**
   - 문제 진술 (1단락)
   - 빈도 / 강도 / 재무 손실 수치
   - 현재 해결 방식과 한계
   - 우리가 다르게 푸는 방식 (1단락)

2. **TAM/SAM/SOM 산정표**
   - 각 수치 + 상향식 산정 공식
   - 출처 (1차 데이터 우선, 2차 시장조사는 보조)
   - 3년 / 5년 SOM 시나리오

3. **ICP 카드**
   - 위 6개 항목 + 배제 조건
   - 타겟 ICP 기업 예시 3-5개 (실명 또는 가명)

4. **다중 페르소나 가치 제안 매트릭스**
   - 위 표 형식으로 작성

## 페르소나 리뷰 호출

산출물 4개 작성 완료 후, 다음 순서로 페르소나 리뷰 자동 실행:

1. **GTM Strategy Lead** 리뷰 → ICP 정밀도, 다크 퍼널 정량화, 가치 제안 5기둥 점검
2. **CEO / Founder** 리뷰 → 시장 생존성, 피벗 가능성, 장기 비전 점검

각 페르소나는 다음 형식으로 출력:

```
[페르소나명]
🟢 강점: ...
🟡 보완 제안: ...
🔴 차단 이슈: ... (있을 때만)
❓ 킬러 질문: ... (사용자가 추가 답변해야 할 사항)
```

사용자가 채택한 피드백만 Notion에 반영, 채택 여부와 함께 변경 이력 자동 기록.

## Kill Switch (다음 Phase 진입 차단 조건)

**판정 절차**: 미확인 SD 0개 확인(선행 조건) → `references/evaluator-loop.md`의 검증 루프로 아래 전 항목을 산출물과 1:1 대조한 목록을 출력한 뒤에만 판정한다. 페르소나 리뷰의 🔴 차단 이슈는 임시 항목으로 승격해 함께 대조한다.

다음 중 **하나라도** 해당하면 Phase 2 진입 차단, Phase 1 재기획 요구:

- [ ] 타겟 고객층이 불분명하거나 너무 광범위 (ICP 배제 테스트 실패)
- [ ] 고객 페인포인트가 감정적 서술뿐, 비즈니스 손실 수치 부재
- [ ] TAM 산정이 하향식(Top-down)에만 의존, 상향식 근거 누락
- [ ] 시장 세분화가 MECE 원칙 위배 (교집합 또는 누락)
- [ ] 다중 페르소나 중 1개 이상의 가치 제안이 정량 KPI와 연결되지 않음
- [ ] 현재 고객의 대안 솔루션 분석 부재 (경쟁 부재 주장은 시장 부재의 증거)

Kill Switch 발동 시 재기획 가이드 (어느 항목을 보강해야 하는지) 를 명시하고, notion_upload가 true면 Notion 페이지 상태를 "Kill Switch 발동"으로 변경.
