# Phase 0 - 시작 전 확인 및 작업 환경 생성

## 목적

사업계획서 작성에 들어가기 전, 사업의 본질과 검증 강도를 결정하는 6가지 항목을 확인하고 작업 디렉토리와 context.json을 생성한다. Notion 뼈대 페이지는 업로드 옵션을 사용할 때만 생성한다.

## 6가지 확인 항목

다음을 한 번에 묻지 말고, **번호 매긴 목록으로 한 메시지에 제시하여 사용자가 한 번에 답할 수 있게 한다**.

1. **사업/제품명**: 정식 명칭 또는 가칭
2. **사업 유형**: 다음 중 하나 또는 하이브리드
   - B2B SaaS (순수 소프트웨어 구독)
   - AI 에이전트 (LLM·자율 판단 기반)
   - IIoT (산업용 IoT, 하드웨어 + 소프트웨어)
   - 하이브리드 (두 가지 이상 결합)
3. **사업 단계**: 가드레일 가중치 차등 적용
   - Pre-seed (가설 단계, 매출 부재) → 정성 검증 비중 ↑
   - Seed (PMF 검증, 초기 매출) → 단위 경제성 추정 검증
   - Series A 이후 (스케일업) → 정량 가드레일 엄격 적용, Rule of 40 필수
4. **Notion 업로드 사용 여부** (기본값: 미사용): 미사용이면 전 과정 로컬 파일로만 진행. 사용 선택 시에만 추가로 **Notion 부모 페이지**(페이지 URL 또는 페이지명)를 묻는다
5. **목적**: 산출물 톤·구조 결정
   - 내부 검토용 (경영진·이사회)
   - 투자자 IR용 (VC, AC)
   - 파트너십 제안용 (전략 파트너)
6. **이해관계자**: 누가 검토할지 (역할 명시: CEO, CFO, 사외이사, 리드 투자자 등)

## 답변 검증 로직

- **사업 유형이 IIoT 포함**: Phase 2에서 하드웨어 CapEx, IT/OT 통합, Servitization 항목이 필수로 추가됨을 사전 고지
- **사업 유형이 AI 에이전트 포함**: Phase 2에서 EU AI Act, 환각 통제, IP 귀속 항목이 필수로 추가됨을 사전 고지
- **단계가 Pre-seed인데 목적이 IR용**: 정량 가드레일은 추정치 기반으로만 검증됨을 고지하고, 정성적 가설(문제·해자)에 더 비중 두기

## 작업 디렉토리 및 context.json 생성 (필수)

6가지 답변을 모두 받은 직후, Notion 사용 여부와 무관하게 수행한다.

1. 사업/제품명에서 `business-slug`를 도출한다 (영문 소문자·하이픈, 예: "SiteGuard AI" → `siteguard-ai`). 도출한 슬러그를 사용자에게 1줄로 고지한다.
2. `./bizplan/{business-slug}/` 디렉토리를 생성한다 (하위: `research/`, `phase1/`~`phase4/`).
3. `context.json`을 SKILL.md의 스키마대로 작성한다. 6가지 답변이 그대로 필드에 매핑된다 (`business_type`, `stage`, `purpose`, `stakeholders`, `notion_upload`).
4. `decision-log.md`·`review-log.md`를 빈 골격으로 생성한다.

이후 모든 Phase는 context.json을 사업 유형·단계·옵션 판단의 단일 출처로 참조한다.

## Notion 뼈대 페이지 생성 (notion_upload가 true일 때만)

context.json 작성 후, `notion_upload: true`인 경우에만 Notion MCP를 사용하여 다음 구조로 빈 뼈대 페이지를 생성하고, 생성된 페이지 URL을 context.json `notion_page_url`에 기록한다. `false`이면 이 섹션 전체를 생략한다.

### 페이지 제목

```
[사업명] 사업계획서 — [사업 유형] / [단계]
```

예: `SiteGuard AI 사업계획서 — AI 에이전트 / Series A`

### 페이지 프로퍼티

| 프로퍼티 | 타입 | 값 |
|---|---|---|
| 사업명 | Title | 입력값 |
| 사업 유형 | Select | B2B SaaS / AI 에이전트 / IIoT / 하이브리드 |
| 단계 | Select | Pre-seed / Seed / Series A↑ |
| 목적 | Select | 내부 검토 / IR / 파트너십 |
| 작성자 | Person | 사용자 |
| 상태 | Status | Phase 0 완료 |
| 마지막 수정일 | Date | 자동 |

### 페이지 본문 구조

```
📌 메타 정보
- 사업 개요 (1-2줄)
- 이해관계자: ...
- 작성 시작일: ...

📋 One-Page Summary  [작성 전]
(Phase 1·3·4 완료 시 자동 채워짐)

▼ Phase 1: 시장 적합성 및 문제 정의  [작성 전]
  - 문제 정의
  - TAM / SAM / SOM
  - ICP 카드
  - 다중 페르소나 가치 제안
  - 페르소나 리뷰: CEO, GTM Lead

▼ Phase 2: 기술 아키텍처 및 법무 리스크  [작성 전]
  - 시스템 아키텍처
  - 규제 대응 매트릭스
  - 데이터 거버넌스
  - 인프라 비용 추산
  - 페르소나 리뷰: Staff Engineer, Legal

▼ Phase 3: 비즈니스 모델 및 단위 경제성  [작성 전]
  - 비즈니스 모델 캔버스
  - 단위 경제성 표
  - 3개년 재무 프로젝션
  - 가격 정책
  - 세일즈 모델
  - 페르소나 리뷰: B2B Sales, CFO

▼ Phase 4: 해자 구축 및 통합 스토리텔링  [작성 전]
  - 차별적 해자 정의
  - 경쟁 포지셔닝 매트릭스
  - 통합 내러티브 (5기둥)
  - 레드팀 스트레스 테스트
  - 페르소나 리뷰: Top-tier VC, CEO

📊 정량 가드레일 검증 결과  [작성 전]
(Phase 3 완료 시 자동 계산)

🔍 페르소나 리뷰 로그
(각 Phase 진행 시 자동 추가)

🛡️ 레드팀 스트레스 테스트 결과
(Phase 4 진행 시 자동 추가)

📜 변경 이력
(모든 수정 자동 기록)
```

## Phase 0 완료 후

작업 환경 생성이 완료되면:

1. 작업 디렉토리 경로를 사용자에게 제공 (notion_upload가 true면 뼈대 페이지 URL도 함께)
2. 4-Phase 워크플로우 개요를 다시 한번 짧게 제시 (각 Phase 페르소나·소요 예상 라운드)
3. **Phase 1 진입 의사 확인**: "Phase 1 (시장·문제 정의) 진입할까요? 아니면 특정 Phase부터 시작하고 싶으신가요?"
4. 사용자가 "Phase 1 시작" 컨펌하면 `phases/phase1-market-problem.md` 읽고 진입

## 예외 처리

- **사용자가 "그냥 한 번에 다 써줘"**: 단계별 검증의 목적을 짧게 설명하고 거부. "초기 가설 오류가 재무·GTM 모델 전체를 오염시키는 것을 방지하기 위함"이라고 명시.
- **사용자가 "Notion에도 올려줘" (중도 전환)**: context.json `notion_upload`를 true로 변경하고 부모 페이지를 확인. 뼈대 페이지를 그 시점에 생성하되, **이미 통과한 Phase의 확정 산출물만** 반영한다. 진행 중 산출물은 통과 후 반영 원칙을 유지.
- **사용자가 "Notion 빼줘" (중도 해제)**: `notion_upload`를 false로 변경. 기존 Notion 페이지는 삭제하지 않고 방치 사실만 고지.
- **사용자가 "특정 Phase만 작성"**: 가능. 단, 의존성 경고 (예: Phase 3 단위 경제성은 Phase 1의 ICP·가격 가설에 의존).
