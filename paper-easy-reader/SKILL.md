# Paper Easy Reader

학술 논문을 처음 접하는 독자도 이해할 수 있도록 읽기 쉬운 한국어로 변환하는 스킬.

**핵심 가치:** 학술적 정확성은 유지하면서, 문장 구조와 표현만 바꿔 누구나 읽을 수 있게 만든다.

---

## Phase 0 — 입력 확인

스킬 실행 전 아래 항목을 확인한다.

| 항목 | 수집 방법 | 부재 시 처리 |
|------|----------|------------|
| 논문 원문 | PDF 업로드 / 텍스트 붙여넣기 / 대화 내 문서 | **없으면 진행 불가** — 파일 요청 |
| 번역 범위 | 사용자 지정 | 기본값: 처음부터 끝까지 전체 |
| 보존할 도메인 용어 | 사용자 지정 또는 Phase 1에서 자동 추출 | Phase 1에서 자동 처리 |
| 출력 형식 | 사용자 지정 | 기본값: .md 파일 생성 후 다운로드 |

파일이 업로드된 경우 `/mnt/skills/public/file-reading/SKILL.md`를 참조하여 올바른 방식으로 읽는다.

---

## Phase 1 — 도메인 및 보존 용어 식별

논문을 읽기 전에 아래 두 가지를 파악한다.

### 1-1. 도메인 파악

논문의 연구 분야를 확인한다. 도메인마다 보존해야 할 용어 집합이 다르다.

| 도메인 예시 | 보존 용어 예시 |
|-----------|-------------|
| AI / ML / RAG | 노드, 엣지, 커뮤니티, 임베딩, 벡터, 청크, 코퍼스, 파이프라인, 프롬프트, 토큰, 인덱싱 |
| 온톨로지 / 지식 그래프 | 클래스, 인스턴스, 속성, 공리, 트리플, OWL, RDF, SPARQL |
| 네트워크 / 그래프 이론 | 노드, 엣지, 리프, 루트, 서브그래프, 모듈성, 차수 |
| 자연어 처리 | 토큰, 임베딩, 어텐션, 파인튜닝, 컨텍스트 윈도우 |
| 데이터베이스 / 시스템 | 쿼리, 인덱스, 클러스터, 스키마 |

### 1-2. 보존 용어 결정 원칙

다음 기준으로 어떤 용어를 원문 그대로 유지할지 결정한다.

**반드시 보존:**
- 해당 도메인에서 보편적으로 통용되는 영어·한국어 혼용 전문 용어
- 논문에서 핵심 개념으로 정의된 고유 용어 (예: GraphRAG, Leiden, ROUGE-L)
- 알고리즘·모델·도구 이름 (예: GPT-4, Claimify, HotPotQA)
- 수식·변수명·코드

**번역 가능:**
- 일반 동사·형용사 (retrieve → 검색하다, generate → 생성하다)
- 설명적 명사구 (knowledge graph → 지식 그래프 또는 그대로 유지, 맥락에 따라)
- 방법론 명칭 중 직역이 자연스러운 것 (query-focused summarization → 질의 중심 요약)

⚠️ **판단 불확실 시 원문 유지를 기본값으로 한다.** 용어를 잘못 번역하는 것이 원문 유지보다 훨씬 해롭다.

## Phase 2 — 쉬운 한국어 변환 원칙

### 2-1. 문장 단순화 패턴

아래 변환 패턴을 일관되게 적용한다.

| 원칙 | 원문 패턴 | 변환 패턴 |
|------|---------|---------|
| **짧은 문장** | A이며, B이고, C이다. | A이다. B이다. C이다. |
| **능동태** | ~가 수행된다 / ~에 의해 생성된다 | LLM이 수행한다 / LLM이 생성한다 |
| **직접적 서술** | ~라고 할 수 있다 / ~인 것으로 보인다 | ~이다 / ~이다 |
| **연결어 추가** | (관계 불명확) | 왜냐하면 / 즉 / 다시 말해 / 이 덕분에 / 반대로 |
| **예시 활용** | 추상적 설명만 있는 경우 | "예를 들어 ~" 추가 (원문에 예시가 있을 때) |
| **개념 도입 시** | 처음 등장하는 전문 개념 | 한 줄 설명 추가 ("이를 ~라고 부른다") |

### 2-2. 학술 표현 → 일상 표현 변환 예시

| 학술 표현 | 일상 표현 |
|---------|---------|
| "이는 ~을 의미한다" | "즉 ~이다" |
| "본 연구에서는 ~을 제안한다" | "논문은 ~을 제안한다" |
| "~에 기반하여 접근법을 설계하였다" | "~을 기반으로 설계했다" |
| "실험 결과, ~임을 확인하였다" | "실험 결과, ~임을 확인했다" |
| "이와 같은 방식을 통해" | "이 방식으로" |
| "~의 관점에서 살펴보면" | "~입장에서 보면" |
| "추가적으로 고려해야 할 사항은" | "또한" |

### 2-3. 유지할 것

아래 내용은 변환하지 않고 원문 그대로 유지한다.

- 모든 수치, 통계, p-값, 승률
- 표와 그림 (설명 텍스트만 변환)
- 알고리즘 의사코드 및 수식
- 참고문헌 목록
- 프롬프트 원문 (해설 텍스트만 변환)
- 인용 형식 (저자, 연도)

## Phase 3 — 섹션별 처리 규칙

논문의 각 섹션은 성격이 다르므로 처리 방식도 다르게 적용한다.

### 초록 (Abstract)

- "이 논문이 무엇을 왜 하는지, 어떤 결과가 나왔는지"를 중심으로 재구성
- 배경·방법·결과·의의 흐름으로 단락 분리
- 분량: 원문과 비슷하거나 약간 짧게

### 서론 (Introduction)

- 기존 문제 → 해결 접근 → 이 논문의 기여 순서로 흐름 명확히
- 처음 등장하는 핵심 개념마다 한 줄 설명 추가
- 참고문헌 인용은 "(저자, 연도)" 형식으로 그대로 유지

### 배경 / 관련 연구 (Background / Related Work)

- 각 선행 연구를 "이 연구는 ~을 했다. 한계는 ~이었다" 형식으로 단순화
- 비교 구조가 있으면 표로 정리

### 방법론 (Methods / Approach)

- 단계가 있으면 번호 목록이나 단계별 소제목으로 명확히 분리
- 각 단계의 "왜 이렇게 했는가"를 원문에서 찾아 한 줄 추가
- 알고리즘 설명은 의사코드 앞에 "이 알고리즘이 하는 일:" 한 줄 추가

### 실험 설정 (Experiments / Setup)

- 데이터셋, 비교 조건, 평가 지표를 각각 짧게 설명
- 표는 그대로 유지하고 표 앞에 "이 표가 보여주는 것:" 한 줄 추가

### 결과 (Results)

- 수치는 그대로 유지
- "이 수치가 의미하는 것:" 형식으로 해석 한 줄 추가
- 주목할 발견은 굵게 표시

### 논의 / 결론 (Discussion / Conclusion)

- "이 연구가 밝힌 것"과 "남은 한계"를 명확히 분리
- 향후 연구 방향은 간결하게

### 부록 (Appendix)

- 프롬프트, 코드 원문은 그대로 유지
- 앞에 "이 프롬프트가 하는 일:" 한 줄 추가
- 통계 분석 표는 그대로 유지하고 주요 결론 한 줄 추가

## Phase 4 — 출력

### 4-1. 파일 생성

결과물을 `.md` 파일로 생성한다.

```
파일명: [논문제목_축약]_쉬운버전.md
저장 위치: /mnt/user-data/outputs/
```

파일 상단에 아래 메타 블록을 추가한다.

```markdown
> **이 문서는 [원제목] 논문을 쉽게 읽을 수 있도록 재작성한 버전이다.**
> 원문: [저자, 연도, arXiv/DOI 등]
> 도메인 전문 용어([예: 노드, 엣지, 커뮤니티 등])는 원문 그대로 유지했다.
```

### 4-2. 완료 보고

파일 생성 후 `present_files`로 전달하며 아래 내용을 간단히 보고한다.

```
✅ 번역 완료
- 처리 섹션: N개
- 보존한 도메인 용어: [주요 용어 목록]
- 파일: [파일명]
```

## 품질 체크리스트

파일 생성 전 아래 항목을 내부적으로 점검한다. 사용자에게 서술하지 않는다.

| 항목 | 확인 기준 |
|------|---------|
| 도메인 용어 보존 | 결정한 전문 용어가 번역되지 않았는가? |
| 사실 정확성 | 수치, 통계, 결과가 원문과 동일한가? |
| 문장 길이 | 대부분의 문장이 2줄 이내인가? |
| 능동태 | 수동태 문장이 최소화됐는가? |
| 연결어 | 문단 간 흐름이 자연스러운가? |
| 개념 도입 | 처음 등장하는 핵심 개념에 설명이 추가됐는가? |
| 원문 요소 보존 | 표, 수식, 프롬프트, 참고문헌이 그대로인가? |
| 메타 블록 | 파일 상단에 출처 정보가 있는가? |

## 가드레일

- **사실 창작 금지:** 원문에 없는 내용을 추가하지 않는다. 해석·연결어는 허용, 새로운 주장은 금지.
- **번역 투 교정:** "~되어진다", "~임에 따라" 같은 번역 투 표현은 자연스러운 한국어로 바꾼다.
- **과도한 축약 금지:** "쉽게"는 "짧게"가 아니다. 중요한 내용은 빠뜨리지 않는다.
- **범위 초과 금지:** 사용자가 특정 섹션만 요청한 경우 그 섹션만 처리한다.
- **저작권 준수:** 논문 원문을 그대로 재현하지 않는다. 내용은 충분히 재구성한 표현으로 전달한다.
