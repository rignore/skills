# 평가 차원 세부 기준

Phase 2 평가 카드 작성 시 이 파일을 참조한다.

---

## 1. 트리거 정확도

**정상**: 사용자 메시지에 스킬 description의 트리거 키워드가 포함되고, 스킬이 발동됨.

**미발동 (False Negative)**: 트리거 조건이 충족됐는데 발동하지 않음.
- 판단 기준: description에 명시된 키워드 또는 의도가 사용자 메시지에 있었는데 일반 대화로 처리된 경우
- 심각도: 🔴 높음 (사용자 경험 저하, 스킬 기능 누락)

**오발동 (False Positive)**: 트리거 조건이 충족되지 않았는데 발동됨.
- 판단 기준: 사용자가 스킬 영역 외 작업을 요청했는데 스킬이 개입한 경우
- 심각도: 🟡 중간 (사용자 흐름 방해 가능성)

**지연 발동**: 트리거 조건이 충족됐지만 여러 턴 후 발동됨.
- 심각도: 🟢 낮음 (결과는 맞으나 UX 개선 여지)

---

## 2. 출력 품질

**할루시네이션**: 스킬 references에 없는 정보를 사실처럼 출력.
- 판단 기준: 사용자가 정정 요청 / 출력이 references와 불일치
- 심각도: 🔴 높음

**범위 초과**: 스킬 영역 밖의 작업을 수행 (예: prd-builder가 와이어프레임까지 생성).
- 심각도: 🟡 중간

**불완전 출력**: Phase 산출물이 해당 phase 파일의 스펙을 충족하지 못함.
- 심각도: 🟡 중간

**출력 형식 불일치**: SKILL.md에 정의된 출력 형식(표, 토글, 페르소나 헤더 등)을 따르지 않음.
- 심각도: 🟢 낮음

---

## 3. 페이즈 흐름

**컨펌 없이 진행**: Phase 완료 후 사용자 승인 없이 다음 Phase로 이동.
- 심각도: 🔴 높음 (핵심 원칙 위반)

**Phase 건너뜀**: 필수 Phase를 사용자 요청 없이 생략.
- 심각도: 🟡 중간

**Phase 역순 진행**: Phase 번호 역순으로 진행하는 비정상 패턴.
- 심각도: 🟡 중간

**Phase 0 생략**: 시작 확인 없이 바로 본문 작성 진입.
- 심각도: 🔴 높음

---

## 4. 레퍼런스 적재

**필수 파일 누락**: SKILL.md에 "반드시 읽을 파일"로 명시된 파일을 읽지 않음.
- 심각도: 🔴 높음

**선택 파일 누락**: 조건부 파일(예: region-context-loader)을 조건이 충족됐는데 읽지 않음.
- 심각도: 🟡 중간

**불필요한 파일 적재**: 작업 유형과 무관한 references 파일을 읽어 컨텍스트 낭비.
- 심각도: 🟢 낮음

---

## 5. 페르소나 정확도

**영역 침범**: 페르소나 A가 페르소나 B의 전문 영역을 다룸.
- 판단 기준: reviewers/routing.md의 Phase별 페르소나 배정 기준 참조
- 심각도: 🟡 중간

**톤 불일치**: 해당 페르소나의 reference 파일에 정의된 말투·관점과 다른 응답.
- 심각도: 🟢 낮음

**선택적 호출 무시**: 조건부 페르소나(예: Mobile Engineer)를 조건 없이 항상 호출.
- 심각도: 🟡 중간

---

## 6. 스킬 간 연계

**체인 누락**: SKILL.md에 정의된 "다른 스킬과의 연계" 체인을 따르지 않음.
- 예: prd-builder Phase 7 완료 후 prd-to-tickets 제안을 하지 않음
- 심각도: 🟢 낮음

**중복 수행**: 이미 다른 스킬이 처리한 작업을 재수행.
- 심각도: 🟡 중간

---

## 7. 가드레일 준수

스킬별 금지 패턴 위반 여부. 예시:

**prd-builder 가드레일**:
- 화살표(→) 사용
- 변수명/코드 표기 (`user_id` 형식)
- 디자인 심미성 기술
- 개발 구현 디테일 포함

**design-token-sync 가드레일**:
- raw hex 색상 사용
- px 단위 font-size
- 이모지 UI 사용
- 다크 사이드바

심각도: 위반 내용에 따라 개별 판단 (보통 🟡 중간 ~ 🔴 높음).

---

## 심각도 기준 요약

| 심각도 | 기준 | 권장 조치 |
|---|---|---|
| 🔴 높음 | 스킬 핵심 기능 실패 또는 사용자 신뢰 훼손 | Phase 3에서 반드시 수정안 작성 |
| 🟡 중간 | 출력 품질 저하 또는 흐름 방해 | Phase 3에서 수정안 작성 (우선순위 2) |
| 🟢 낮음 | UX 개선 여지 또는 세부 불일치 | 수정 제안만, 필수 아님 |
