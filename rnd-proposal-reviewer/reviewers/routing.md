# 페르소나 라우팅

각 Phase 및 도메인별로 어떤 페르소나를 호출할지 정의. 모든 페르소나가 모든 Phase를 보지 않는다.

## Phase × 페르소나 라우팅

| Phase | 권장 페르소나 | 선택 페르소나 |
|---|---|---|
| 1. 자격 검증 | 안전/보안 규제 | - |
| 2. 기술 타당성 | 도메인별 1~2차 (AI/SW/IoT/에너지) | 스마트 제조 |
| 3. 사업화 경제성 | DX/비즈니스 | 스마트 제조(제조 도메인), 안전/보안(안전 도메인) |
| 4. 예산 편성 | 안전/보안 규제, DX/비즈니스 | - |
| 5. 통합 리뷰 | 전원 (한 줄 코멘트) | - |

## 도메인 × 페르소나 우선순위

| 도메인 | 1차 | 2차 | 3차 |
|---|---|---|---|
| 신재생 에너지 | 에너지 계통 | IoT/에지 | SW 아키텍처 |
| 스마트 팩토리 | 스마트 제조 | IoT/에지 | AI 알고리즘 |
| AI 에이전트 | AI 알고리즘 | SW 아키텍처 | DX/비즈니스 |
| B2B SaaS | SW 아키텍처 | DX/비즈니스 | AI 알고리즘 |
| AIoT 안전 | 안전/보안 규제 | IoT/에지 | AI 알고리즘 |
| **전력설비 화재·진단** | **전력설비 전기공학** | IoT/에지, 안전/보안 규제 | AI 알고리즘, 에너지 계통 |

## 호출 절차

1. Phase 완료 후 사용자에게 묻기:

```
Phase {N}이 검토되었습니다. 페르소나 리뷰를 진행할까요?

이 Phase에 권장되는 페르소나 ({도메인}):
- {페르소나 1}: {관점 한 줄}
- {페르소나 2}: {관점 한 줄}

선택 페르소나:
- {선택 페르소나}: {관점 한 줄}

호출할 페르소나를 선택해 주세요. (전체/개별 선택/건너뛰기)
```

2. 사용자가 선택한 페르소나만 `reviewers/<persona>.md` 읽고 해당 관점으로 리뷰 작성

3. 페르소나별 리뷰 결과를 다음 형식으로 출력:

```
[페르소나명]

🟢 강점:
- {강점 1}

🟡 보완 제안:
- {제안 1}

🔴 차단 이슈: (있을 때만)
- {이슈 1}

❓ 킬러 질문: (평가위원이 물을 법한 질문)
- {질문 1}
- {질문 2}

📌 권장 답변 프레임: (있을 때만)
- {답변 구조}
```

4. 사용자에게 채택 여부 묻기:

```
{페르소나}의 피드백입니다.

각 항목에 대해 채택 여부를 알려주세요:
- 보완 제안 1: 채택 / 거부
- 보완 제안 2: 채택 / 거부
- 차단 이슈 1: 채택 (거부 시 사유 필요)

킬러 질문에 대한 대응 전략도 함께 알려주세요.
```

5. 채택된 피드백만 Phase 산출물에 반영
6. 변경 이력 테이블에 기록 (반영된 페르소나 명시)
7. 페르소나 리뷰 로그 토글에 전체 리뷰 누적

## 멀티 페르소나 호출

여러 페르소나 동시 호출 시 각각 독립적으로 리뷰 작성. 상충 의견은 사용자에게 명시:

```
페르소나 간 상충 의견:
- AI 알고리즘: 모델 파라미터를 10배 키워 SOTA 달성 강조
- SW 아키텍처: 인프라 비용이 사업성을 무너뜨림 — 경량화 필요

어떻게 결정하시겠어요?
```
