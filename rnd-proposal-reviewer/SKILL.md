# R&D Proposal Reviewer

정부 R&D 지원사업 제안서(사업계획서)를 7인 전문가 페르소나 관점에서 단계별로 검토하는 스킬. IRIS 전자평가시스템의 실제 평가 프로세스를 모사하여 Fail-Safe 4단계로 결함을 탐지하고 고득점 전략을 제시한다.

## 핵심 원칙

1. **Fail-Safe 단계별 진행**: 4단계(자격 → 기술 → 사업 → 예산) 중 이전 단계를 통과하지 못하면 다음 단계로 진행하지 않는다. Auto-fail 조건을 최우선 차단.
2. **킬러 질문 중심 리뷰**: 각 페르소나는 실제 평가위원회에서 나올 법한 "킬러 질문"을 던지고, 제안서가 답변하고 있는지 검증한다.
3. **도메인 페르소나 선택적 호출**: 과제 성격(AI/IoT/에너지/제조/SaaS 등)에 따라 해당 도메인 페르소나만 선택 호출. 전원 호출하지 않는다.
4. **정책 정합성 검증**: "왜 지금 대한민국 정부 예산으로 개발되어야 하는가"에 대한 명확한 답이 제안서에 녹아있는지 검토.
5. **두 가지 모드 지원**: ① Review 모드(기존 제안서 검토) ② Build 모드(제로베이스 기획부터 가이드).

## 작성/검토 가드레일 (모든 Phase 공통)

- **개조식 우선**: 줄글보다 번호 계층 + 짧은 서술형 (평가위원 가독성 확보)
- **정량 근거 우선**: 모든 KPI·목표치는 산출 근거(베이스라인·비교군·측정 방법)와 함께 제시. "생산성 20% 향상"처럼 근거 없는 수치 경고
- **공인 인증 레퍼런스**: 기술 주장의 객관성 확보를 위해 TTA V&V, GS인증, CSAP, KC 등 공인 인증 경로 명시 여부 점검
- **부처별 관성 반영**: IITP(기술 혁신성/SOTA 비교), NIPA(사업화·수출), 중기부(고용·매출), 산업부(공정/에너지 KPI) 등 발주 기관 평가 관성에 맞춰 강조점 조정
- **Auto-fail 우선 차단**: 재무(부채비율 500%↑/유동비율 50%↓/자본잠식), 참여 제한, 세금 체납, 청년 고용 의무 등은 반드시 Phase 1에서 확인

## 워크플로우

### 0단계 — 시작 전 확인

사용자가 R&D 제안서 검토/작성 요청 시 다음 7가지를 먼저 확인한다.

1. **모드**: Review(기존 제안서 검토) / Build(제로베이스 기획)
2. **과제명 및 발주 기관**: 어느 부처·전문기관 과제인가 (IITP/NIPA/중기부/산업부/지자체 등)
3. **사업 공고명 및 공고 URL**: 가능하면 IRIS 공고 페이지 링크
4. **도메인**: 신재생 에너지 / 스마트 팩토리 / AI 에이전트 / B2B SaaS / AIoT 안전 / 기타
5. **Notion 부모 페이지**: 검토 리포트를 어디에 만들지
6. **제안서 자료**: PDF/Notion 페이지/텍스트 붙여넣기 (Review 모드 시)
7. **마감일 및 남은 시간**: 긴급도에 따라 검토 깊이 조정

확인 후 `phases/phase0-setup.md`를 읽고 Notion 검토 리포트 뼈대 페이지를 생성한다.

### Phase 진행

각 Phase 진입 시 해당 `phases/phaseN-*.md` 파일을 읽고 그 안의 체크리스트와 페르소나 호출 절차를 따른다.

| Phase | 파일 | 검토 초점 | 주요 페르소나 |
|---|---|---|---|
| 0 | `phases/phase0-setup.md` | 세팅·뼈대 페이지 | - |
| 1 | `phases/phase1-qualification.md` | 행정·재무 Auto-fail 차단 | 안전/보안 규제 |
| 2 | `phases/phase2-technical.md` | 기술 타당성·혁신성·KPI | AI, SW 아키텍처, IoT, 에너지 (도메인별 선택) |
| 3 | `phases/phase3-business.md` | 사업화·수익 모델·수요처 | DX/비즈니스, 스마트 제조 |
| 4 | `phases/phase4-budget.md` | 예산 편성·인건비·간접비·매칭 | 안전/보안 규제 (체크리스트) |
| 5 | `phases/phase5-final.md` | 통합 리뷰·가점 전략·체크리스트 | 전원 종합 |

각 Phase 완료 시:

1. 결함 탐지 결과를 Traffic Light(🟢/🟡/🔴)로 사용자에게 제시
2. 🔴 차단 이슈가 있으면 다음 Phase 진입 전 보완안 합의
3. `reviewers/routing.md`를 참조하여 해당 Phase에 적합한 페르소나 리뷰 호출 여부 질의
4. 리뷰 진행 시 `reviewers/<persona>.md` 읽고 페르소나 관점·킬러 질문 생성
5. 사용자가 채택한 피드백만 Notion 리포트에 반영
6. 다음 Phase 진행 의사 확인

## 7인 전문가 페르소나 시스템

### 페르소나 라인업

| 페르소나 | 핵심 영역 | 주요 평가 지표 |
|---|---|---|
| AI 알고리즘 | 모델 혁신성·데이터 품질 | 정확도, F1, 추론 속도, 강건성 |
| SW 아키텍처 | 시스템 안정성·클라우드 보안 | CSAP 준수, MSA, 확장성 |
| IoT/에지 | 데이터 수집 신뢰성·내구성 | 센서 정밀도, 통신 성공률, 국산화율 |
| 스마트 제조 | 현장 KPI 달성도 | OEE, 생산성 향상률, 불량 감소율 |
| 에너지 계통 | 에너지 효율·그리드 안정성 | 발전 예측 오차율, 계통 안정도 |
| DX/비즈니스 | 사업화·시장 경쟁력 | CLTV/CAC, TAM/SAM/SOM, ROI |
| 안전/보안 규제 | 법적 준수·보안 증거력 | 중대재해법 부합성, 데이터 무결성 |
| 전력설비 전기공학 (도메인 특화) | PD·아크·절연열화·Retrofit 전기 안전 | IEC 60270 준수, 아크 트립 시간(ms), 오동작률 |

### 페르소나 출력 형식 (공통)

```
[페르소나명]

🟢 강점:
- {제안서에서 잘 된 부분}

🟡 보완 제안:
- {점수 끌어올릴 수 있는 구체적 보완안}

🔴 차단 이슈: (있을 때만 — Auto-fail 또는 감점 집중 영역)
- {즉시 수정 필요한 항목}

❓ 킬러 질문: (평가위원이 물을 법한 질문)
- {질문 1}
- {질문 2}

📌 권장 답변 프레임: (있을 때만)
- {질문에 대한 답변을 어떻게 준비할지}
```

페르소나 정의 파일:
- `reviewers/ai-algorithm.md` — AI 모델·데이터·할루시네이션·강건성
- `reviewers/sw-architecture.md` — MSA·CSAP·멀티테넌시·무중단 배포
- `reviewers/iot-edge.md` — 센서 노이즈·EMC·통신 프로토콜·국산화
- `reviewers/smart-manufacturing.md` — OEE·레거시(ERP/MES) 연동·현장 교육
- `reviewers/energy-grid.md` — 발전 예측·계통 안정성·ESS·VPP
- `reviewers/dx-business.md` — TAM/SAM/SOM·CLTV/CAC·구독 모델·글로벌
- `reviewers/safety-security.md` — 중대재해법·CSAP·영상 비식별화·로그 무결성
- `reviewers/power-equipment.md` — 부분방전(PD)·아크 감지·보호계전기 연계·ESS 열폭주·Retrofit 전기 안전 (전력설비 화재 예방·절연열화 진단 과제 전용)

## Notion 작업

Notion MCP를 사용한다. 페이지 구조 표준은 `references/notion-template.md` 참조.

핵심 페이지 구성:
- 상단: 메타 정보 (과제명, 발주 기관, 공고 URL, 마감일, 모드)
- 상단 토글: **Executive Summary** (Traffic Light 한눈 대시보드)
- 본문 토글들: 각 Phase별 검토 결과
- 하단: 페르소나 리뷰 로그, 가점 전략 체크리스트, Auto-fail 체크리스트

## 다른 스킬과의 연계

- **Build 모드에서 PRD가 필요할 때**: `prd-builder`로 제품/기능 PRD 먼저 작성 후 제안서로 확장
- **투자 유치용 사업계획서**: `bizplan-builder` (VC 관점 7인 페르소나, 단위 경제성 검증)
- **과제 선정 후 실행 단계**: `prd-to-tickets`로 Epic/Story/Task 분해

## 실행 시 첫 응답 패턴

제안서 검토/작성 요청을 받으면 절대 바로 검토에 들어가지 않는다. 항상 다음 순서:

1. Phase 0 시작 알림
2. 7가지 확인 항목 질문 (모드, 과제명/발주기관, 공고 URL, 도메인, Notion 위치, 제안서 자료, 마감일)
3. 모든 답변 받은 후 `phases/phase0-setup.md` 읽고 뼈대 페이지 생성
4. 생성된 뼈대 페이지 링크 제공 후 Phase 1(행정/재무 자격 검증) 진입 의사 확인

> ⚠️ **주의**: Phase 1은 건너뛸 수 없다. Auto-fail 조건 하나가 기술·사업 점수 전부를 무효화한다.
