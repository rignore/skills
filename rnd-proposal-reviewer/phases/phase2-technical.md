# Phase 2 — 기술 타당성 및 혁신성 리뷰 (Technical Workflow)

기술 전문가 4인(AI, SW 아키텍처, IoT, 에너지)이 주도하여 기술 개발의 구체성과 실현 가능성을 평가한다. 도메인에 따라 호출 페르소나를 선택적으로 구성.

## 목표

- 기술 개발 목표의 구체성·측정 가능성 확인
- Global SOTA 대비 혁신성 검증
- 마일스톤 정합성·위험 관리 대책 점검
- 도메인 페르소나의 킬러 질문에 대한 제안서 답변 평가

## 주도 페르소나 (도메인별 선택)

Phase 0에서 선택한 도메인에 따라 자동 호출:

| 도메인 | 1차 페르소나 | 2차 페르소나 |
|---|---|---|
| 신재생 에너지 | 에너지 계통 | IoT/에지, SW 아키텍처 |
| 스마트 팩토리 | 스마트 제조 | IoT/에지, AI 알고리즘 |
| AI 에이전트 | AI 알고리즘 | SW 아키텍처 |
| B2B SaaS | SW 아키텍처 | AI 알고리즘 |
| AIoT 안전 | IoT/에지, 안전/보안 | AI 알고리즘 |

## 검토 프레임워크

### 1. 기술 개발 목표 구체성

- [ ] 개발 목표가 정량 KPI(수치 + 측정 단위)로 표현되었는가
- [ ] 측정 방법과 측정 주체(공인 시험기관 여부)가 명시되었는가
- [ ] 베이스라인(현재 값)과 목표치(개발 후 값)가 모두 제시되었는가
- [ ] "향상/개선" 같은 모호한 표현 대신 구체 수치인가

**탐지 예시**
- 🔴 "AI 모델의 정확도를 향상시킨다" → 베이스라인·목표치 없음
- 🟡 "F1-Score 0.85 달성" → 베이스라인 없음, SOTA 대비 혁신성 불명
- 🟢 "F1-Score 0.72(자체 기준) → 0.88, TTA V&V 인증 (Global SOTA 0.91)"

### 2. Global SOTA 대비 혁신성

- [ ] 해당 기술의 Global SOTA 벤치마크가 표로 제시되었는가
- [ ] 제안 기술의 차별 포인트(방법론·데이터·성능·비용)가 명확한가
- [ ] 단순 따라잡기(catch-up)인지, 독자적 접근(novel)인지 구분 가능한가

### 3. 마일스톤 정합성

- [ ] 연도별/단계별 마일스톤이 논리적 순서인가
- [ ] 하드웨어·소프트웨어 연동 시점이 현실적인가 (HW 먼저, SW 통합 후)
- [ ] 각 마일스톤마다 검증 가능한 산출물(프로토타입·논문·특허·인증)이 있는가
- [ ] 전체 기간의 20~30%가 최종 실증/검증에 할당되었는가

### 4. 핵심 성능 지표(KPI) 검증

- [ ] KPI가 공인 시험기관(TTA, KTL, KTR 등)의 인증 가능한 성격인가
- [ ] KPI 측정 시나리오(환경·조건·샘플 수)가 명시되었는가
- [ ] 부정적 KPI(오탐률, 지연 시간 등)가 포함되어 균형을 갖추었는가

### 5. 위험 관리 (Risk Management)

- [ ] 기술 리스크 식별 및 확률·영향도 평가 테이블
- [ ] 각 리스크별 대안(Plan B) 명시
- [ ] 외부 의존성(부품 수급, 규제 변화, 파트너 이탈) 대비책

## 도메인별 핵심 킬러 질문

각 페르소나 파일에 전체 질문 목록이 있음. 대표 질문만 발췌:

**AI 알고리즘**
- 비정형 데이터 노이즈 20% 이상 환경에서 모델 강건성을 보장하는 데이터 증강/필터링 기법은?
- 학습 데이터의 편향성을 어떻게 검증·보정하는가?
- 할루시네이션 제어를 위한 Guardrail 또는 후처리 로직은?

**SW 아키텍처**
- CSAP 31개 통제 항목 중 '가상화 보안'과 '접근 통제'의 기술적 구현 방식은?
- 멀티테넌시 환경에서 타 테넌트와의 데이터 격리 방식은?
- 무중단 배포 및 장애 복구 RTO/RPO 목표는?

**IoT/에지**
- 고압 전력선의 EMI가 센서 데이터 전송 손실을 유발할 경우, 에지 단계 에러 정정 알고리즘은?
- 하드웨어 국산화율 목표와 핵심 부품 수급 리스크는?
- LoRa/Zigbee/5G 중 선정 근거와 커버리지 실측 계획은?

**스마트 제조**
- 목표 '불량률 15% 감소'가 현재 설비 Capa와 원재료 변동성을 고려할 때 달성 가능한가?
- 레거시 ERP/MES와의 데이터 연동 방식 및 기존 프로세스 충돌 방지책은?
- 작업자 숙련도 향상 교육 계획과 현장 수용성 확보 방안은?

**에너지 계통**
- 기상 이변으로 인한 간헐성을 제어하지 못해 계통 과부하 시 ESS 즉각 우회 보호 협조 체계는?
- 한전 계통 연계 기준(배전선로 용량·전압 안정도) 만족 실증 계획은?
- 탄소 배출 저감 효과 산출의 방법론(LCA 기반 여부)은?

## 진행 절차

1. Phase 0에서 확정된 도메인 페르소나 1~2명을 사용자 동의 후 호출
2. 각 페르소나가 위 체크리스트 + 자신의 킬러 질문으로 제안서 검토
3. 결함 발견 시 `reviewers/<persona>.md` 출력 형식으로 리포트
4. 사용자가 보완안 채택 여부 결정
5. Notion 리포트 업데이트

## 🔴 차단 이슈 기준

다음 중 하나라도 해당하면 Phase 3 진입 전 보완 필수:
- KPI가 정량화되지 않음
- Global SOTA 대비 혁신성 근거 전무
- 핵심 리스크에 대한 Plan B 없음
- 마일스톤이 실현 불가능한 일정 (예: 1년차에 상용화 완료)
