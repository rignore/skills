# 리서치 루프 — 학술 자료로 개선 근거 보강

FAIL 원인 분석이 하네스 내부 정보(코드·lessons.md)만으로 풀리지 않을 때, 외부 학술·기술 자료를 조사해 다음 라운드의 개선 계획에 반영하는 서브루프. 라운드 절차의 "귀속 분석" 단계와 "개선 고정" 단계 사이에 끼워 실행한다.

## 1. 발동 조건 (하나 이상 해당 시)

1. **정체**: 같은 계열 개선을 2라운드 연속 시도했는데 순효과가 유의 기준 미만 (`stalled_rounds >= 2`).
2. **도메인 지식 요구**: FAIL 원인 가설이 하네스 밖의 지식을 요구한다. 예 — 센서 노이즈 분포가 가우시안 가정과 다른 이유, LLM 추출 누락의 알려진 원인과 대응 기법, 특정 통계 검정의 적용 조건.
3. **판정 기준 타당성 의심**: 기준 수치 자체가 근거 없이 정해졌다는 의심. 예 — "잔차 왜도 < 0.5"가 해당 센서 유형에 적정한가.

단순 구현 버그(스택 트레이스로 원인이 보이는 것)에는 발동하지 않는다 — 그냥 고친다.

## 2. 절차

1. **질의 설계**: 관찰한 현상을 학술 용어로 변환한다. 예 — "센서 잔차가 두꺼운 꼬리" 현상이면 "sensor noise heavy-tailed distribution", "이상 주입 데이터의 현실성" 문제면 "synthetic anomaly injection realism time series". 질의 2~4개를 만들어 서로 다른 각도(원인 이론 / 대응 기법 / 판정 방법론)를 커버한다.
2. **조사 실행**: 규모에 따라 선택한다.
   - 가벼운 확인(용어·공식·적용 조건): WebSearch로 직접 조사.
   - 깊은 조사(원인 이론과 대응 기법을 다각도로, 출처 검증 포함): deep-research 스킬에 질의를 넘긴다.
3. **기록**: `research-notes.md`에 append — 발동 사유, 질의, 출처(URL·논문 제목), 요지 3~5줄, 하네스 적용 후보. 출처 없는 요지는 기록하지 않는다.
4. **개선 계획 반영**: 적용 후보를 `lessons.md`의 "잔여 원인 구조(다음 개선 후보)" 목록에 근거 링크와 함께 추가한다. 다음 라운드의 "개선 고정" 단계가 이 목록에서 개선안을 고른다 — 리서치가 곧 개선 실행은 아니다. 개선안 채택·기각 판단은 개선 고정 단계에서 한다.

## 3. 가드레일

- **리서치 결과는 solver 개선 근거로만**: 리서치를 근거로 판정 기준·통계 설계를 바꾸고 싶으면 기준 조정 트랙(가드레일 1) 또는 Planner 재계획 게이트(가드레일 2)를 경유한다. "논문에서 기준이 다르다더라"는 라운드 중 기준 완화의 면죄부가 아니다.
- **출처 등급 구분**: 동료 검증 논문·표준 문서 > 벤더 기술 문서 > 블로그. 판정 기준 조정의 근거로는 앞의 두 등급만 인정한다.
- **적용 전 소규모 검증**: 리서치에서 얻은 기법은 전체 라운드에 넣기 전에 변형(variation) 실행으로 소규모 검증할 수 있으면 먼저 한다 — 근거가 좋아도 이 시스템에서 통한다는 보장은 없다.
- **리서치도 비용이다**: 라운드당 리서치는 1회로 제한한다. 리서치가 반복 발동되는 것은 지표·범위 설정이 잘못됐다는 신호 — Planner 재계획을 검토한다.
