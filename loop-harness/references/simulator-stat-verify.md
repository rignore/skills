# preset: 시뮬레이터 물리 모델 통계 검증

- **대상 프로젝트**: 물리 기반 시뮬레이터 코드베이스(git repo). 예 — 다구역 확산 시뮬레이터가 합성 센서 시계열을 생성한다.
- **정답표의 원천(시나리오 문서)**: `docs/시뮬데이터-통계검증-시나리오.md` — 판정 기준 26항목의 SoT(Source of Truth). 라운드 시작 전 반드시 원문을 읽어라.
- **목적**: 시뮬레이터가 생성한 합성 데이터가 ① 물리 이론값 정합 ② 설계 명세 정합 ③ 실측 데이터의 일반 통계 성질, 3축 기준을 충족하는지 26항목으로 판정한다. 실제 현장 실측과의 대조는 (가상 환경 가정 하) 범위 밖이다.
- **Phase P 상태**: 이 preset이 Planner 진단을 이미 반영했다(실측 기반). `harness-plan.md`는 이 preset을 원안으로 작성하고 사용자 컨펌만 받으면 된다.

이 preset은 **결정론 재검증**형이다 — 정답표(물리 이론식·설계 명세)가 이미 확립돼 있어 Phase P 리서치를 생략할 수 있다(생략 사유를 `harness-plan.md`에 1줄 남긴다). 정체 시 리서치 루프는 여전히 발동한다.

## 0. 통계 설계 (Phase P 진단 결과)

- **mode: deterministic** — main_loop는 seed 기본값 0 고정이라 같은 조건 재실행이 결정론적이다. 판정은 N=1.
- **seed 민감도**: 종료 전 1회, 다른 seed 2~3개(코드의 seed 인자 직접 지정)로 재실행해 판정이 뒤집히는 항목을 확인한다. 뒤집히는 항목은 "seed 민감"으로 표시하고 기준의 노이즈 여유를 기준 조정 트랙에서 재검토한다.
- **라운드 간 비교**: paired 원칙 — 26항목 단위 1:1 대조(회복/퇴행/불변). 유의 기준: 순효과(회복 − 퇴행) ≥ +2항목.
- **변형(variation) 축 후보**: 노이즈 파라미터(σ 설계식), 운영 주기 계수, 유출률 파라미터, 이상 주입 시나리오 종류. 한 번에 한 변수.
- **리서치 질의 예시** (정체 시): "sensor noise distribution characteristics", "multi-zone box model dispersion validation", "synthetic sensor data statistical realism validation".

## 1. 하네스 매핑

| 축 | 구성 요소 |
|---|---|
| 고정축(evaluator) | ① 시나리오 문서의 판정 기준 26항목 — `verification/loop/`의 checks로 고정 ② `verification/loop/`의 기계 검증 스크립트(checks_s1.py ~ checks_s6.py + tally) ③ 설계 명세 — `config.json` 설계값, 센서 datasheet 수치, 물리 이론식(정상상태값 v_ss 검산식·온도-발생률 보정식·파생 채널 혼합식) |
| 탐색축(solver) | 시뮬레이터 구현 — `physics.py`, `observation.py`, `environment.py`, `config.json` |

고정축 유의사항: 시나리오 문서가 "판정 기준 수치는 초안"이라 명시하므로 기준 조정이 실제로 발생할 수 있다. 조정하더라도 라운드 중 소급 적용은 금지 — §6(FAIL 3분류)의 기준 조정 트랙을 따른다.

## 2. 판정 항목 26개 (정답표 요약)

시나리오 그룹 6개, 총 26항목. 판정 기준 수치는 시나리오 문서 §3 원문 그대로다. 수치가 원문과 다르면 이 preset이 아니라 시나리오 문서가 정답이다. (아래 값은 구조를 보이기 위한 예시 수치다.)

용어: **상태값 v** = 각 구역의 스칼라 물리량(시뮬레이터가 모델링하는 대상). **발생률 Q_gen** = 상태값을 올리는 소스 항. **유출률** = 상태값을 낮추는 배출 항(단위 시간당 교환 횟수). **v_ss** = 소스·유출이 평형을 이룬 정상상태값.

### S1. 기술통계 검증 (3항목) — 평균·편차가 이론값과 맞는가

| ID | 검증 내용 | 판정 기준 |
|---|---|---|
| S1-1 | 구역·공정단계·조건별 정상 구간의 상태값 v 평균을 v_ss 검산식(physics.py `v_ss` × f(부하) × 보정계수 × 운영 주기 계수)과 대조 | 이론값 대비 오차 ±15% 이내 (1차 지연·인접 교환류 감안) |
| S1-2 | 정상 라벨 구간에서 경고 임계 매트릭스 초과 비율 산출 (예: 특정 구역 정상 구간의 임계값 초과 비율) | 구역·단계별 초과 비율 ≤ 1% (오탐 유발 방지) |
| S1-3 | 관측값에서 이동 중앙값(60초 창)을 뺀 잔차 분포를 Q-Q plot·왜도·첨도로 확인 — 가우시안 노이즈(`rng.gauss`)이므로 정규 근사여야 함 | 잔차 왜도 \|skew\| < 0.5, 초과첨도 \|kurt\| < 1.0 |

S1-1 계산 예시 — Z04(체적 270, 유출률 25) 단일 조건, 최소 부하 시 v_ss ≈ 10.2. 최대 부하(f(부하)=3.0) 시 ≈ 30.7로 경고 임계 50 미만이어야 설계 의도와 부합.

### S2. 관측(센서) 모델 검증 (5항목) — datasheet 명세 재현

| ID | 검증 내용 | 판정 기준 |
|---|---|---|
| S2-1 | RUN-B 잔차 표준편차를 값 구간별(bin)로 산출해 설계식 σ = max(2.5%×값, 0.5)와 대조 | 저값(<20) 구간 σ = 0.5±0.15, 고값 구간 σ/값 = 2.5±0.5% |
| S2-2 | 드리프트 단위 검증: `Sensor.observe`에 t_s=30일을 넣고 드리프트 성분만 추출 (48시간 런에서는 노이즈에 묻혀 검출 불가) | 30일 시점 편향 = 측정값의 2.0±0.2% |
| S2-3 | 응답 지연 T90: 급성 이벤트 주입 시 진값(v)과 관측값의 교차상관 시차 측정. 구역 유출 동역학과 분리해 센서 지연만 본다 | 시차 ≈ τ=13초 (±4초), 스텝 기준 T90 ≈ 30초 |
| S2-4 | 교차 민감도(cross-sensitivity): 간섭원 상시 구역과 무간섭 구역의 표시값/진값 비율 비교. 간섭계수 0.9 반영 확인 | 두 집단의 비율 차이가 설계 간섭계수 방향·크기와 일치 |
| S2-5 | 보정계수(CF) 정합: 표시값 = Σ(성분별 실제값 ÷ CF) 관계를 성분별로 재계산 대조. 특정 성분은 CF가 커서 크게 과소 표시되는 것이 정상 | 재계산값 대비 오차 < 노이즈 2σ |

### S3. 시계열 패턴 검증 (4항목) — 시간 구조가 실제답게 나타나는가

| ID | 검증 내용 | 판정 기준 |
|---|---|---|
| S3-1 | 운영 주기·피크 패턴: RUN-B 상태값을 시간대별 집계. 주기 계수 설계값 주간(06~18시) 1.0, 야간초반(18~22시) 0.7, 심야 0.3, 오전 피크(08~11시) ×1.4, 오후 피크(14~16시) ×1.3 | 시간대별 평균 비율이 설계 계수 대비 ±20% 이내 (예: 심야/주간 비율 ≈ 0.3) |
| S3-2 | 외기 일주기: 온도 06시 최저·15시 최고 사인 곡선, 습도는 온도와 역상관, 기압 1005~1021hPa 범위 약 3주 주기 | 온도 최고·최저 시각 ±1.5h, 온도-습도 상관계수 < −0.8, 기압 범위 위반 0건 |
| S3-3 | 자기상관 구조: 원시 계열은 ODE 적분 결과이므로 강한 양의 상관, 이동 중앙값 제거 후 잔차는 백색잡음 근사 | 원시 계열 lag-1 ACF > 0.95, 잔차 lag-1 ACF < 0.3 |
| S3-4 | 변화율 물리 한계: 정상 구간 초당 변화율 dv/dt 분포. 상승 상한 = 최대 Q_gen 환산치, 하강 상한 = 유출 붕괴율 (유출률/3600)×v. 노이즈 2σ 여유 포함 | 스파이크 미주입 정상 구간에서 한계 초과 0건 |

### S4. 물리 정합성 검증 (6항목) — 구역 간·변수 간 관계

| ID | 검증 내용 | 판정 기준 |
|---|---|---|
| S4-1 | 구역별 프로파일 차등: 6개 구역 정상 구간 상태값의 평균·분산을 Kruskal-Wallis 검정으로 비교. Z04(체적 270·유출률 25)와 Z05(체적 400·유출률 6)는 뚜렷이 달라야 함 | 구역 간 차이 유의(p < 0.01), 구역별 평균 순위가 v_ss 이론 순위와 일치 |
| S4-2 | 유출-상태값 역관계: 구역별 평균 상태값과 1/(체적×유출률)의 회귀로 v_ss 비례 관계 확인 | 결정계수 R² > 0.8 |
| S4-3 | 인접 구역 확산: Z01에 급성 이벤트 주입. 개구부 연결 구역 Z02(4.0m²)·Z04(2.5m²)는 시차를 두고 상승, 개구부 없는 Z06은 무반응 | Z02·Z04 상승폭 > 사전 평균 +3σ, Z06 변동 ±1σ 이내, 상승 시차 > 0 |
| S4-4 | 계절(온도-발생률) 보정: 1월·8월 런의 평균 상태값 비율을 온도-발생률 이론 배수와 대조. 설계 보정치: 여름 +29%, 겨울 −42% | 계절별 배율이 이론 배수 대비 ±10%p |
| S4-5 | 유출 정체(stagnation): 정체 주입(기압<960hPa AND 습도>75%) 시 유출효율 0.5 적용으로 유효 유출률 절반, 평형값 2배 수렴 | 주입 후반 평균값 = 사전 대비 1.8~2.2배 |
| S4-6 | 파생 채널 정합 단위 검증: 파생 비율 채널을 성분별 값에서 혼합식으로 재계산해 채널값과 대조 | 재계산 오차 < 1% |

### S5. 이상 주입 시그니처 검증 (5항목) — 이상 데이터도 물리적으로 타당한가

| ID | 검증 내용 | 판정 기준 |
|---|---|---|
| S5-1 | 급성 이벤트(acute): 급격 상승 후 새 평형 수렴, 센서 지연 반영 | 상승 시작이 주입 시점 +T90 이내, 복구 후 사전 수준 ±2σ 복귀 |
| S5-2 | 점진 이벤트(gradual): 완만한 단조 상승 기울기 | 주입 구간 선형회귀 기울기 > 0 유의, 급성 대비 기울기 뚜렷이 작음 |
| S5-3 | 유출 이상(fan_stop·filter_clog): 상태값 상승과 동시에 배출풍속 하락·필터차압 상승 동반 | 1차 채널과 동반 채널이 모두 기대 방향, fan_stop 후 값이 새 v_ss(유출률 비율 역산)로 수렴 |

## 3. RUN 매트릭스 (시나리오 문서 §2)

1 tick = 1초. 시나리오들이 데이터셋을 공유하도록 실행(RUN)을 5개로 묶는다.

| RUN | 생성 방법 | 조건 | 사용 시나리오 | 소요 시간 |
|---|---|---|---|---|
| RUN-A | 기존 산출물 재사용 | docs/stream-export.csv + stream-labels.csv + stream-ground-truth.jsonl | S6 전체, S1 예비 실행 | 즉시 (생성 불필요) |
| RUN-B | 정상 장기 런 | `main_loop.py --ticks 172800`(48시간), 이상 주입 없음, seed 고정 | S1, S2-1, S3 전체, S4-1, S4-2 | 약 3분 (2,000 ticks 실측에서 외삽) |
| RUN-C | 계절 대비 런 | `--start`로 t0을 1월·8월로 지정해 각 24시간(86,400 ticks) 2회 | S4-4 | 합계 약 3분 (동일 실측 외삽) |
| RUN-D | 이상 주입 런 | `scenario_engine.py`(단일 구역 12종) + 인접 확산용은 main_loop 스트림 중 `inject.py`로 Z01 급성 이벤트 주입 | S2-3, S2-4, S4-3, S4-5, S5 전체 | scenario_engine은 in-memory라 수 초. inject 스트림 런은 주입·복구 구간 길이로 결정 — Round 0에서 러너 작성 시 실측 기입 |
| RUN-E | 단위 검증 (데이터 런 불필요) | 함수 직접 호출·수치 재계산 | S2-2, S4-6, S1-1 검산식 대조 | 즉시 |

- 공통 전처리: labels.csv의 (category·subtype) 라벨로 정상/이상 구간을 분리하고, 통계는 구역 × 공정단계(phase) 단위로 집계한다.
- 실행 순서: ① 즉시 — S6(RUN-A), S1 예비, RUN-E 단위 검증 ② RUN-B 생성 후 — S1~S3, S4-1·S4-2 ③ RUN-C·RUN-D 생성 후 — S4-3~S4-5, S5.
- RUN 생성은 병목이 아니다(전체 10분 이내). 라운드 회전 비용은 checks 스크립트 작성(Round 0)에 집중된다.

## 4. 운영 주의사항 (실측 확인된 사실)

1. **산출물 경로 하드코딩·덮어쓰기**: `main_loop.py`는 산출물 경로를 하드코딩하고 실행할 때마다 덮어쓴다 — `docs/stream-export.csv`, `docs/stream-labels.csv`, `docs/stream-ground-truth.jsonl`, `docs/stream-payload.jsonl`. 새 RUN 생성 직후 산출물을 `verification/runs/RUN-X/`로 즉시 이동 보관하라. RUN-A 원본은 git 추적 파일이므로 다음 명령으로 복원한다.
   ```bash
   git checkout -- docs/stream-export.csv docs/stream-labels.csv docs/stream-ground-truth.jsonl
   ```
2. **seed**: CLI에 노출되지 않고 코드 기본값 0으로 고정 — 동일 조건 재실행은 결정론적이다. loop-harness 가드레일의 "재실행 변동 분리"는 생략 가능하되, seed 1개로 판정한 항목은 종료 전 1회 seed 민감도(다른 seed 2~3개로 판정 뒤집힘 여부)를 확인한다.
3. **계절 런 t0 지정**: `--start` 옵션으로 지정한다. 예: `--start 2026-01-15T00:00`(겨울), `--start 2026-08-15T00:00`(여름).

## 5. 검증 스크립트 설계 원칙

- 구성: `verification/loop/checks_s1.py` ~ `checks_s6.py`(시나리오 그룹별 판정) + tally(집계).
- **이론값 독립 재계산**: 판정에 쓰는 이론값은 설계 문서의 수식에서 checks 스크립트가 독립 재계산한다. `physics.py` 함수를 그대로 불러 검산하면 solver가 자기 자신을 채점하는 것이다. 예외 1건 — S1-1은 폐형식 해(`v_ss`) 대 ODE 적분 결과의 비교라 같은 모듈의 서로 다른 계산 경로를 대조하는 검증이므로 `v_ss` 호출을 허용한다(예외 사유를 checks 주석에 명시).
- **판정 출력 형식 고정**: 각 checks의 출력은 `ID | 측정값 | 판정 기준 | 판정(pass/fail) | 비고` 형식을 강제한다. verdict는 소문자, 셀 내 `|` 사용 금지. tally가 이 형식을 정규식으로 파싱해 수치를 확정한다.

## 6. FAIL 3분류 처리

| 분류 | 처리 |
|---|---|
| ① 물리 모델 결함 (수식·파라미터) | solver 수정 후 영향받는 RUN만 재생성 — RUN 매트릭스(§3)에서 해당 항목이 쓰는 RUN을 역산한다 |
| ② 판정 기준 부적정 | 기준 조정 트랙으로 분리. 라운드 중 조정 금지, 사유를 기록하고 다음 라운드부터 적용 |
| ③ 구현 버그 | ①과 동일 — solver 수정 후 영향 RUN만 재생성 |

시나리오 문서가 "판정 기준 수치는 초안"이라 명시하므로 ②가 실제로 발생할 수 있다. 그래도 라운드 내 소급 적용은 금지다 — 떨어진 항목을 아는 상태에서의 기준 변경은 사후 완화이기 때문이다.

## 7. 무결성 필수 PASS (협상 불가)

다음 항목의 FAIL은 기준 조정(②) 대상이 아니다. 반드시 solver 수정으로만 해소한다.

- S6 전체 3항목: 타임스탬프(S6-1)·결측(S6-2)·값 범위(S6-3)
- S5-5(라벨 정합 100%)

## 8. 상태 파일 위치와 스키마

위치: `<프로젝트>/verification/loop/` 아래 `state.json`·`lessons.md`·`run-log.md` (git 커밋).

```json
{
  "metric": "sim-stat",
  "round": 0,
  "max_rounds": 3,
  "target": { "pass_min": 26, "integrity_fail_max": 0 },
  "stat_design": { "mode": "deterministic", "n_reps": 1, "judge_stat": "paired_recovery_minus_regression", "seed_sensitivity_seeds": 3 },
  "history": [],
  "converged": false,
  "stalled_rounds": 0
}
```

- `pass_min: 26` — 26항목 전 PASS가 목표. 기준 조정을 거친 항목의 PASS도 사유 기록이 있으면 인정한다.
- `integrity_fail_max: 0` — 무결성 필수 항목(§7)의 FAIL 허용치 0.
- `run-log.md` — RUN별 생성 조건·소요 시간·보관 경로를 기록한다.

## 9. 종료 조건과 리포트

- **종료 조건**: 26항목 전 PASS(기준 조정 항목은 사유 기록 포함) 또는 `max_rounds` 도달. 도달 시 최고 PASS 라운드의 결과로 확정하고 종료한다.
- **라운드 보고서**: `verification/loop/reports/round-N.md` (매 라운드, 작업 노트). round-procedure.md §5-1 형식.
- **최종 보고서 파일**: `docs/시뮬데이터-통계검증-결과-YYYYMMDD.md`. round-procedure.md §5-2 프로세스를 따른다 — editorial-reviewer 검토 게이트 필수, 판정 코드에 의미 병기(예: "S1-1(구간 평균이 이론값과 일치)"), 각 판정에 구체 사례 1건.
- **최종 판정표 형식**: `ID | 측정값 | 판정 기준 | 판정(PASS/FAIL/조정) | 비고`. FAIL 항목은 §6의 3분류로 원인을 기록한다.
