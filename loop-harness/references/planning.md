# Phase P — 계획 (Planner 에이전트)

테스트 대상에 맞는 하네스를 설계하는 단계. 산출물은 `harness-plan.md` 1본이며, 사용자 컨펌 게이트를 거쳐 고정한다. 이후 라운드에서 이 문서는 고정축이다 — 통계 설계·종료 조건을 라운드 중에 바꾸지 않는다.

## 실행 방식

Planner는 별도 서브에이전트로 실행하라. 프롬프트에 넣을 것: 대상 시스템 설명(또는 코드·문서 경로), 사용자가 개선하려는 지표, 이 문서의 진단 항목과 설계서 템플릿. Planner가 대상 코드·문서를 직접 읽고 진단하게 한다.

## 0. 범위 모드와 리서치 선행 (진단 전 결정)

### 0-1. 범위 모드 선택 (집중 / 광범위)

하네스가 무엇을 측정할지의 범위를 먼저 정한다. 이 선택이 지표·판정 항목·gold set 규모를 결정한다.

| 모드 | 집중(Focused) | 광범위(Broad) |
|---|---|---|
| 지표 | 문제 축 **하나**(예: 정책 준수율·복원율) | 여러 품질 축 동시 |
| 판정 항목 | 그 축 항목만 | 전체 항목, **축별 분리 집계**(단일 총점으로 뭉개지 않는다) |
| gold set | 그 축을 트리거하는 최소 케이스 | 대표 케이스 다양 |
| 쓸 때 | 원인 규명·개선 귀속을 명확히 하고 한 축을 수렴시킬 때 | 전반 품질 스냅샷·회귀 감시 |
| 리스크 | 그 축에 과적합 — 다른 축 품질은 미측정 | 원인 규명이 흐려짐, 비용 큼 |

- **권고**: 개선이 목적이면 **집중 모드로 시작**해 한 축을 수렴시킨 뒤, 다음 축으로 한 번에 하나씩 넘어간다. 광범위 모드는 전반 회귀 감시가 목적일 때.
- 두 모드 모두 판정은 **항목별 분리 집계**다(analytic rubric — 항목별 신뢰도가 단일 총점보다 높다). 여러 축을 하나의 종합 점수로 합치지 않는다. 무엇이 나아졌는지 흐려진다.

### 0-2. 리서치 선행 — 설계 전 기본 단계 (바로 설계 금지)

Phase P는 **배경만 듣고 바로 harness-plan을 쓰지 않는다.** 순서는 **배경 청취 → 리서치 → 진단·설계**다. 설계를 감이 아니라 근거로 세우기 위해, 두 갈래를 조사한다.

- **(A) 문제·도메인 리서치 (무엇을·왜 개선하나)**: 개선하려는 문제의 배경·원인·선행 사례. 이 문제가 실제로 존재하는지, 어떻게 측정된 전례가 있는지, 도메인 지식이 판정 기준을 어떻게 규정하는지. 지표·범위를 근거로 잡기 위함.
- **(B) 평가 방법론 리서치 (어떻게 판정하나)**: ① 지표 설계·정의(이진 vs 척도, 등급) ② 정답 데이터 구축(규칙/명세 대체 가능분 vs gold set) ③ 정답 데이터가 어려우면 LLM-as-a-judge 등 대안(reference-free·self-consistency·rubric) ④ judge bias 완화·gold 규모·κ 밴드.
- **방식**: `research.md`의 리서치 루프(WebSearch 또는 deep-research 스킬)를 Phase P **첫 단계로 발동**한다. 결과는 `research-notes.md`에 출처와 함께 기록하고, 설계서의 근거로 인용한다.
- **생략은 예외**: 정답표가 이미 확립됐고 배경이 자명한 **결정론 재검증**(예: 기존 시뮬레이터 물리값 재측정)만 리서치를 건너뛸 수 있고, 그 경우도 생략 사유를 `harness-plan.md`에 1줄 남긴다. **LLM 심판이 포함되면 리서치는 무조건 필수.**
- **경계**: 정답표를 만들 수 없는 발산형·일회성 테스트는 여전히 미트리거. 리서치는 판정 설계의 근거이지 solver 개선 근거가 아니다(판정 기준 변경은 가드레일 1 경유).

## 1. 대상 시스템 진단 (설계서 §1에 기록)

| 진단 항목 | 확인 방법 | 설계에 미치는 영향 |
|---|---|---|
| 결정론 여부 | 같은 입력·같은 seed로 2회 실행해 산출물 동일한지 확인 | `stat_design.mode` 결정 — 확률적이면 N회 반복 필수 |
| 측정 1회 비용 | 소규모 실측(예: 전체의 1~5% 분량)으로 시간·토큰·요금 외삽 | N(반복 수)·max_rounds의 상한을 결정 |
| 정답표 존재 여부 | 기대값·기대 시그니처가 문서로 있는가, 만들 수 있는가 | 없고 만들 수도 없으면 **이 하네스 적용 불가** — 단, 규칙/명세로 대체 가능한 결정 신호이거나, gold를 못 만드는 항목이라도 rubric-criteria 기반 reference-free 판정을 human review 트리거로 살릴 수 있으면 그 항목만 진행한다. 발산형·novel 산출물은 중단하고 보고 |
| 판정 자동화 가능성 | 판정이 수치 계산인가, LLM 판단이 필요한가 | 수치면 스크립트 단독 심판, LLM 판단이면 심판 3인 병렬 표결(그 이상은 실효 표본이 안 늘어 무의미 — SKILL §1 5요소 ⑤) |
| 판정 티어 배정 | 각 판정 항목이 결정(규칙 grep/파싱)·의미(LLM 심판)·렌더(시각 회귀) 중 무엇인가 | 결정 신호(hex·px·토큰명·존재 여부)=규칙, 의미 신호(적절성·문맥·리듬)=LLM, computed style·캐스케이드·동적 값=렌더. **한 항목을 두 티어가 중복 판정 금지**, 정규식으로 의미 억지 매칭 금지(FP 폭발) |
| 산출물 덮어쓰기·부작용 | 실행이 기존 파일·외부 상태를 덮어쓰는가 | RUN 산출물 보관 규약, 복원 절차를 운영 주의에 기록 |
| 해법(solver)의 수정 단위 | 무엇을 바꿀 수 있는가 — 프롬프트 문구, 파라미터, 코드 구조 | 개선 탐색 순서(작은 단위부터)와 정체 시 전환 목표 결정 |

## 2. 통계 설계 (설계서 §3에 기록 — 상세 근거는 statistics.md)

Phase P에서 아래를 수치로 고정한다. 실측 결과를 본 뒤의 변경은 금지다.

1. **반복 수 N**: 확률적 시스템의 판정용. 측정 비용과 판정 안정성의 절충으로 결정하되 최소 5회. 결정론 시스템은 N=1 + 종료 전 seed 민감도(seed 2~3개). N은 target 역산 게이트(statistics.md §2)를 먼저 통과해야 한다 — 전부 통과 가정에서도 target 미달인 N은 반려.
2. **판정 통계**: 항목별 pass/fail이면 N회 중 통과 비율과 Wilson 신뢰구간. 연속 지표면 중앙값과 부트스트랩 구간. 라운드 간 비교는 paired(항목 단위 1:1).
3. **유의 기준**: "개선"으로 인정하는 최소 순효과(예: paired 회복 −퇴행 ≥ +3건, 또는 신뢰구간 비겹침).
4. **변형(variation) 축**: 원인 분해가 필요할 때 바꿀 조건 후보(한 번에 한 변수). 예: 입력 길이, 온도 파라미터, 데이터 구간.
5. **지표 정의(분자/분모까지)**: 이진 pass/fail 비율로 확정한다 — 1-5 척도 금지(LLM 절대 점수는 seed마다 흔들리고 상단에 몰려 절대 helpfulness 일치도가 0.45-0.60에 그침). 분모=판정 항목×gold 케이스, 분자=pass 건수. 등급을 쓰면 심각도 게이트로 **기계 계산**한다: BLOCKER(무결성 필수) 1건이라도 있으면 즉시 최저 등급(준수율 평균 무시), 나머지는 MAJOR/MINOR 누적. 등급은 모델이 부여하지 말고 카운트에서 계산한다.
6. **편향 통제(LLM 심판 시)**: judge≠solver 계열, 심판 3인 상한, pairwise면 A/B 스왑 2회(뒤집히면 판정 보류), 길이 중립(길이는 규칙 카운트로 분리해 판정 근거에서 배제), self-consistency(동일 입력 N회 판정의 분산을 신뢰 신호로, 저일치 케이스만 human 에스컬레이션). 판정 출력은 결함 지적이 아니라 **원인(why)+수정 지침(how-to-fix)** 필수. 근거는 `research-notes.md`.
7. **판정자 수 M**: LLM 심판이면 기본 3인, M=1은 캘리브레이션+감시 서브샘플 조건에서만(statistics.md §2-1). M과 일치도 측정 계획을 설계서에 기록한다.
8. **변별력 사전 점검**: 예상 통과율 구간을 파일럿 실측 또는 근거와 함께 명시한다. 천장(95% 이상)·바닥(5% 이하)이 예상되면 난이도 조정 또는 지표 재설계 후 진행(statistics.md §5-1).

- 유의 기준: <"개선" 인정 최소 순효과>

## 4. Planner 원칙

- **범위는 야심차게, 구현은 열어둔다**: 설계서는 무엇을 어떤 기준으로 판정하는지를 고정하되, solver가 어떻게 고칠지는 명시하지 않는다. 상류(계획)의 과잉 지정은 하류 오류를 만든다.
- **비용으로 검증한다**: max_rounds × 라운드당 측정 비용(N 반복 포함)을 합산해 총비용을 설계서에 적는다. 감당 불가면 N이나 정답표 크기를 줄이는 것이 아니라 지표 범위를 좁힌다.
- **컨펌 게이트**: 설계서 draft를 사용자에게 제시하고, 특히 N·M(판정자 수)·max_rounds·target·무결성 필수 항목은 명시적 동의를 받는다. 컨펌 후 `상태: confirmed`로 바꾸고 commit한다.
- **재계획 게이트**: 정체(stalled_rounds ≥ 2)로 통계 설계나 지표 범위를 바꿔야 하면, Planner를 다시 띄워 설계서를 개정한다. 개정판은 버전을 남기고(§ 하단에 개정 이력 1줄) 다음 라운드부터 적용한다 — 진행 중 라운드에 소급하지 않는다.
