# loop-harness — 반복 개선 사이클 하네스

정답표와 기계 판정이 있는 지표를 라운드 단위로 개선하는 방법론. 어떤 지표를 64.8%에서 83.1%로 끌어올린 실증 절차를 일반화했다. 대상은 묻지 않는다 — LLM 프롬프트, 시뮬레이터 물리 모델, 검색 품질, 성능 튜닝 등 "측정 가능한 지표 + 수정 가능한 해법"이 있는 모든 시스템에 적용한다.

## 실행 절차 (진입 시 이 순서대로 라우팅하라)

1. **preset 확인**: 작업 대상이 §7의 preset 표에 있으면 해당 reference를 먼저 읽고, 그 규약(상태 파일 위치·판정 항목·운영 주의)을 본 문서보다 우선 적용하라.
2. **작업 디렉토리 확인**: `<프로젝트>/verification/loop/`(preset이 다르게 지정하면 그 위치)에서 상태 파일을 확인하라.
   - `harness-plan.md` 없음 — **Phase P(계획)** 부터. `references/planning.md`를 읽고 수행하라.
   - `harness-plan.md` 있음, `state.json` 없음 — **Round 0(하네스 구축)**. `references/round-procedure.md`를 읽고 수행하라.
   - 둘 다 있음 — **Round N**. `state.json`이 `converged=true`이거나 `round >= max_rounds`면 새 라운드를 돌리지 말고 종료 상태만 보고하라. 아니면 `references/round-procedure.md`의 Round N 절차를 수행하라.
3. **단계별 상세 문서**: 통계 설계·판정 방법은 `references/statistics.md`, 리서치 루프는 `references/research.md`를 해당 단계에서 읽어라.

## 1. 3역할 구조 — 평가는 고정, 해법만 탐색

| 역할 | 하는 일 | 시점 | 원칙 |
|---|---|---|---|
| **Planner** | 대상 시스템 진단, 하네스 설계서(`harness-plan.md`) 산출 | 시작 전 1회 + 정체 시 재계획 | 지표·통계 설계·종료 조건을 실측 전에 고정. 야심찬 범위를 유지하되 세부 구현은 Solver에 맡긴다 |
| **Solver** | 개선 대상물(프롬프트·코드·파라미터) 수정, 산출물 생성 | 라운드마다 | 정답표·판정 기준 열람 금지 (측정 오염 차단) |
| **Evaluator** | 판정·집계 | 라운드마다, 내용은 라운드 중 수정 금지 | 회의적으로 튜닝하라 — 생성자를 자기비판적으로 만드는 것보다 평가자를 분리·회의화하는 쪽이 효과적이다. 수치 계산이면 스크립트가 유일 심판. LLM 심판이 필요하면 **생성 모델과 다른 계열**로 고정한다(self-preference 편향 차단 — 같은 계열은 자기 출력에 최대 +25% 후한 판정) |

- **분리 이유**: 평가를 함께 바꾸면 점수 상승이 개선 효과인지 채점 완화인지 구분할 수 없다. 에이전트는 자기 산출물을 관대하게 평가하는 경향이 있어 자기 채점을 구조적으로 차단해야 한다.
- **Evaluator(고정축) 5요소**: ① 정답표 ② 판정 프로토콜(기준·허용 오차, 사전 고정) ③ 소스 원문/설계 명세 ④ 기계 집계 스크립트 ⑤ **편향 통제**(LLM 심판을 쓸 때만): judge≠solver 계열 · 심판 앙상블 3인 상한(그 이상은 실효 표본이 안 늘어 무의미) · 이진 pass/fail(1-5 척도 금지) · 정답표를 심판 프롬프트에 reference로 동봉. ①~④ 중 하나라도 없으면 loop를 돌리지 말라 — Round 0에서 채운다. 정답표 없이 "좋아질 때까지"는 하네스가 아니라 감(感)이다.
- **역할별 모델 배정**: 계획(Planner)·귀속 분석·판정(Evaluator)은 상위 모델(예: opus)에, 실행·산출 생성(Solver)은 하위 모델(예: sonnet)에 배정한다. 사고 품질이 중요한 계획·판정에 상위 모델을, 양이 많은 생성에 하위 모델을 써 비용을 아낀다. 이 배정은 ⑤ 편향 통제(judge≠solver)와 정합한다 — 판정(상위 계열)이 생성(하위 계열)과 다르기 때문이다. Workflow의 agent별 `model` 파라미터로 역할마다 지정한다.

## 2. 단계 흐름

1. **Phase P — 계획**: Planner가 대상을 진단하고 `harness-plan.md`(지표 정의·5요소 진단·통계 설계·RUN 계획·max_rounds·종료 조건)를 산출한다. **바로 설계하지 않는다 — 순서는 배경 청취 → 리서치 선행 → 진단·설계다.** 범위 모드(집중/광범위)를 정하고(planning.md §0-1), 설계를 리서치로 근거화한다 — (A) 문제·도메인 리서치(무엇을·왜 개선하나)와 (B) 평가 방법론 리서치(어떻게 판정하나)를 Phase P 첫 단계로 발동한다(planning.md §0-2). 정답표가 확립된 결정론 재검증만 리서치를 생략할 수 있고, LLM 심판이 포함되면 무조건 필수다. 그런 다음 **사용자 컨펌 게이트를 거쳐 고정**한다. 상세: `references/planning.md`
2. **Round 0 — 하네스 구축**: 5요소 중 빈 것을 채우고 기준선(baseline)을 실측한다. LLM 심판을 쓰면 baseline 전에 **캘리브레이션 게이트**(심판 vs 정답표 일치도 κ≥0.6)를 통과해야 한다 — 미달이면 그 항목을 규칙 판정으로 이관하거나 루브릭을 재작성한다. solver 개선은 하지 않는다. 상세: `references/round-procedure.md`
3. **Round 1..N — 개선 사이클**: 개선 고정, solver 수정, 블라인드 산출, 판정, 기계 집계, 귀속 분석의 6단계. 라운드 종료 시 라운드 보고서(`reports/round-N.md`)를 작성한다. FAIL 원인 분석이 정체되면 리서치 루프로 분기한다. 상세: `references/round-procedure.md`
4. **종료**: target 달성(`converged=true`) 또는 max_rounds 도달(최고 수치 라운드로 확정). 종료 선언은 기계 집계 수치만이 한다. 종료 시 **최종 보고서**를 작성한다 — editorial-reviewer 검토 게이트를 거쳐 확정한다(round-procedure.md §5-2).

## 3. 통계적 유의성 (요약 — 상세는 references/statistics.md)

- **확률적 시스템**(LLM 산출, seed 비고정 시뮬레이션)은 단일 실행으로 판정하지 말라. 같은 조건 **N회 반복** 실행의 집계(통과율·신뢰구간)로 판정한다. N·판정 통계·유의 기준은 Phase P에서 고정하고 사후 변경을 금지한다 — 결과를 본 뒤의 N 변경은 p-hacking과 같은 구조다. N은 target에서 역산해 하한을 먼저 검증한다 — **전부 통과해도 target 신뢰 하한에 못 미치는 N은 시작 전에 실패가 확정된 설계이므로 반려한다**(조견표: statistics.md §2). LLM 심판은 기본 3인, 1인은 캘리브레이션 통과+감시 서브샘플 조건에서만(statistics.md §2-1).
- **결정론 시스템**(seed 고정)은 N=1로 판정하되, 종료 전 seed 민감도(다른 seed 2~3개로 판정 뒤집힘 여부)를 1회 확인한다.
- **조건 변형(variation) 실행**: 조건을 조금씩 바꿔(한 번에 한 변수) 결과 차이로 원인을 분해한다. 반복(replication)과 목적이 다르다 — 반복은 판정 신뢰성, 변형은 원인 규명.
- **라운드 간 비교는 paired**: 전체 평균이 아니라 항목 단위 1:1 대조(회복/퇴행/불변)로 개선 효과를 귀속한다.

## 4. 리서치 루프 (요약 — 상세는 references/research.md)

- **발동 조건**: ① 같은 계열 개선 2라운드 연속 순효과 미미(정체) ② FAIL 원인 가설이 도메인 지식을 요구 ③ 판정 기준 자체의 타당성 의심.
- **절차**: 현상을 학술 용어로 변환한 검색 질의 설계, 자료 조사(WebSearch 또는 deep-research 스킬), `research-notes.md`에 출처와 함께 기록, 개선 후보를 `lessons.md`의 잔여 원인 목록에 근거 링크와 함께 추가. 다음 라운드의 "개선 고정" 단계가 이를 입력으로 쓴다.
- **가드레일**: 리서치 결과는 solver 개선 근거로만 쓴다. 판정 기준 변경 근거로 쓰려면 기준 조정 트랙(가드레일 1)을 경유한다.

## 5. 가드레일 (위반 시 해당 라운드 무효)

1. **판정 기준 동결**: 라운드 간 프로토콜·정답표 변경 금지. 떨어진 항목을 아는 상태에서 그 항목을 구제하는 기준 변경은 형식을 갖춰도 사후 완화다. 기준 보강은 별도 트랙으로(사유 기록, 다음 라운드부터 적용).
2. **통계 설계 동결**: N(반복 수)·유의 기준·판정 통계의 사후 변경 금지. 변경이 필요하면 Planner 재계획 게이트를 거쳐 다음 라운드부터 적용한다.
3. **self-report 금지**: "개선됐다"는 자기 보고가 아니라 기계 집계 수치만이 판정한다. 종료 선언도 수치가 한다.
4. **재실행 변동 분리**: 확률적 시스템의 회복분은 개선 항목별로 귀속하고, 귀속 불가분은 "재실행 변동"으로 분리해 보수적 순효과를 따로 보고한다.
5. **정체 감지·전환**: 같은 계열 개선을 2라운드 연속 시도해 순효과가 미미하면 리서치 루프를 발동하거나 더 큰 단위(구조·아키텍처)로 전환한다.
6. **상한**: 라운드 수 상한을 시작 전에 정한다. 도달 시 최고 수치 라운드로 확정하고 종료한다. "한 번만 더"는 금지.
7. **이전 라운드 산출물 수정 금지**. 커밋은 작게 자주.
8. **Goodhart 방어**: 지표를 유일 north star로 쓰지 말라. 게이밍하면 깨지는 반대지표(guardrail metric)를 쌍으로 걸고(예: "정책 준수율"에 산출물 유용성·과제 완수), 정답표를 동결해 별도 holdout으로 정답표 과적합(teaching-to-test)을 감시한다. 형식만 맞추고 내용이 비는 게이밍(예: 문장 파편화로 규칙 통과)을 반대지표가 잡게 한다.

## 6. 상태 파일 — 파일 기반 핸드오프

세션·머신·컨텍스트가 바뀌어도 아래 파일만 읽으면 사이클을 이어갈 수 있어야 한다(git 커밋). 컨텍스트 리셋 시 대화 기억에 의존하지 말고 이 파일들로 재개하라.

| 파일 | 역할 | 작성 주체 |
|---|---|---|
| `harness-plan.md` | 하네스 설계서 — 지표·통계 설계·RUN 계획·종료 조건 | Planner (Phase P, 이후 동결) |
| `state.json` | 기계가 읽는 진행 상태 — 자동화 시 진입 가드 | 라운드 종료 시 갱신 |
| `lessons.md` | 다음 라운드가 읽는 교훈 — 시도·실패·잔여 원인·하지 말 것 | 라운드마다 append |
| `research-notes.md` | 리서치 결과 — 출처·요지·적용 후보 | 리서치 루프 발동 시 append |

```json
{
  "metric": "<지표명>",
  "round": 2,
  "max_rounds": 4,
  "target": { "<지표 필드>": "<목표값>" },
  "stat_design": { "mode": "stochastic", "n_reps": 10, "judge_stat": "pass_rate_wilson95" },
  "history": [
    { "round": 1, "value": 0.648, "date": "YYYY-MM-DD", "attributed_gain": null },
    { "round": 2, "value": 0.831, "date": "YYYY-MM-DD", "attributed_gain": "+9 (개선 귀속) / +6 (재실행 변동)" }
  ],
  "converged": false,
  "stalled_rounds": 0
}
```

`stat_design.mode`는 `deterministic`, `stochastic`, 또는 `hybrid`(트랙별로 결정론·확률 판정을 병행 — 예: 정적 코드 분석은 deterministic, LLM 심판은 stochastic). `history`의 수치 필드 정의는 Phase P에서 고정한다.

## 8. 하네스 단순화 재검토

하네스의 각 장치는 "모델이 스스로 못 하는 것"에 대한 가정을 인코딩한 것이다. 모델이 개선되면 가정을 재검토하고 과도한 스캐폴딩을 제거하라 — 가능한 가장 간단한 구성이 정답이다. 예: 판정이 결정론적 스크립트로 충분하면 심판 3인 표결을 두지 않는다.
